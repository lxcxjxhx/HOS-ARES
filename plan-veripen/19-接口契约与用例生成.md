# 19 · 接口契约与用例生成（OpenAPI / GraphQL）

> 为什么必须有这一章：车云有几百个接口，手工写用例不现实。
> 这一章把"给它一份 swagger，它自己生成用例并跑完"变成可交付的模块，而不是 PPT 里的一句话。

## 1. 模块定位

```
openapi.yaml / graphql schema
      │
      ▼
┌─────────────────────┐
│ veripen_contract    │  解析 → 归一化 → 用例模板 → 打分 → 去重
│  parser / planner   │  （纯函数，无网络）
└─────────┬───────────┘
          ▼
   cases.yaml（与 11 的用例格式一致，可人工审阅、可 diff）
          ▼
   oracle 消费（idor_cross_account / bola_functional / mass_assignment / 参数类）
```

**关键判断**：生成器只产**用例**，不产判定。判定仍在 oracle 里。这样生成器的错不会污染可信度。

## 2. 解析（OpenAPI 3.0/3.1）

| 输入 | 提取 | 输出字段 |
|---|---|---|
| `paths.*.*` | method, path, operationId, tags | `op_id` |
| `parameters` | name, in(query/path/header/cookie), schema.type, required | `params[]` |
| `requestBody` | content-type, schema 属性树（含 `readOnly`/`writeOnly`） | `body_schema` |
| `security` | 全局与 operation 级；securitySchemes 类型 | `auth_requirement` |
| `responses` | 2xx 的 schema（用于"正常响应"判定） | `success_shape` |
| `x-*` 扩展 | 自定义风险标注（可选） | `risk_hint` |

**归一化**：路径参数统一成 `{id}`；同名参数合并；`servers[0].url` 作为 base_url 候选（但**必须**在 profile scope 内才用）。

**拒绝条件**（启动即失败）：
- 解析出的 `base_url` 不在 `scope.assets` 内
- 操作数 > `max_operations`（默认 500，防撑爆）
- 存在 `$ref` 循环（记录并跳过该分支，不整体失败）

## 3. 用例模板（5 类，各有判定归属）

| 模板 | 生成什么 | 交给谁 | 触发条件 |
|---|---|---|---|
| T1 对象级越权 | 同路径、不同 id，A/B 账号交叉访问 | `idor_cross_account` | 路径含 `{id}` 类参数 且 有双账号 |
| T2 功能级越权 | 管理类路径（`/admin`、`/internal`、`/manage`）低权访问 | `bola_functional` | tags/路径命中管理关键词 |
| T3 批量赋值 | 对 `readOnly: true` 字段注入特权值 | `mass_assignment` | body schema 含 readOnly 字段 且 该 oracle 已授权 |
| T4 参数边界 | 类型边界（0/-1/超大/空/超长/特殊字符） | 各 oracle 的变体池 | 所有带参数的操作 |
| T5 认证缺失 | 去掉 Authorization/Cookie 直接访问 | `auth_absent`（判定并入 bola/idor 的 control） | operation 声明了 security |

**不生成的**：写操作的真实业务流（改价、下单）——那需要业务建模，进二期池。

## 4. 打分与排序（不是全跑，按风险排序）

```
score = 3×has_id_param + 2×is_admin_path + 2×has_readonly_field
      + 1×has_upload + 1×is_login_like + 0.5×param_count
      - 2×is_health_check - 3×is_public_static
```

| 规则 | 说明 |
|---|---|
| 只跑 Top-N | `policy.max_cases`（默认 200），其余写入 `cases.yaml` 但不执行 |
| 同类去重 | 同 `(op_id, oracle, param)` 只保留最高分一条 |
| 稳定排序 | 同分按 `op_id` 字典序，保证可复现（不依赖字典插入序） |
| 覆盖均衡 | 每个 tag 至少取 1 条，避免全挤在一个业务域 |

## 5. 产出格式（与 11 的 cases.yaml 完全一致）

```yaml
- case_id: GEN-001
  source: openapi:tsp-lab@2026-11-01
  op_id: getVehicleById
  asset: tsp-lab
  oracle: idor_cross_account
  template: T1
  params: { path: {vin: "LSVAA1234<nonce>"}, query: {} }
  expect_verdict: VERIFIED
  score: 8.5
  notes: "路径参数 vin；双账号；高价值"
```

**人工可审**：`make cases-diff` 显示与上次生成的差异；客户可以先审用例再跑。

## 6. GraphQL 变体

| 步骤 | 做法 |
|---|---|
| 端点 | profile 声明或 OpenAPI 里 `content-type: application/graphql` |
| 获取结构 | introspection（被禁用则跳过，记 `INCONCLUSIVE`） |
| 用例 | 对 query 的每个 `{id}` 参数做 T1；对 mutation 做 T2（低权调用） |
| 限制 | 单次查询深度 ≤3，防被当 DoS |

## 7. 与 mTLS / 双账号的配合

| 场景 | 处理 |
|---|---|
| 每个 operation 需要不同角色 | `security` 声明 → 生成用例时标注所需角色，缺角色则 `BLOCKED` 而非 `INCONCLUSIVE` |
| mTLS 必需 | 生成的用例带 `mtls: client_cert_ref`，由 vault 提供；缺证书 → `BLOCKED` |
| token 有效期短 | 用例执行前刷新一次，任务内缓存（避免触发风控） |

## 8. 实现约束（给 agent 的硬边界）

| 约束 | 值 |
|---|---|
| 纯函数 | 解析与生成不联网；只读文件 |
| 依赖 | `pyyaml` + `jsonschema`（不引入 openapi 全套 SDK，避免依赖爆炸） |
| 行数 | parser ≤400 行、planner ≤300 行 |
| 测试 | 3 份真实 swagger 样本（含 `$ref`、含 3.1、含 GraphQL）各 ≥10 条断言 |
| 幂等 | 同输入两次生成，`cases.yaml` 字节一致（排序稳定） |

## 9. 验收（A7 断言）

1. 给 `tsp-lab/openapi.yaml`（40 个 operation）→ 生成 200 条用例，**同输入两次字节一致**。
2. 生成的用例里，至少 5 条被 oracle 判 VERIFIED（真漏洞），0 条误报。
3. 把 `base_url` 改成 scope 外的域 → 启动即拒绝。
4. `make cases-diff` 能看出"新增 12 条 / 删除 3 条"。
