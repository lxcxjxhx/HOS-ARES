## 1. S2 · Cursor 工具集（A 级，10 个）

来源：`cursor-agent-1.0.3/package/dist/index.d.ts`（111 行，原文）

| # | 工具 | 关键参数 | 我们缺什么 |
|---|---|---|---|
| 1 | `codebase_search` | `query`, `target_directories?` | **语义检索**（不是 grep） |
| 2 | `read_file` | `relative_workspace_path`, `should_read_entire_file`, `start_line_one_indexed`, `end_line_one_indexed_inclusive` | **带行号区间的读** |
| 3 | `run_terminal_cmd` | `command`, `is_background`, **`require_user_approval`** | 后台执行 + **逐命令审批开关** |
| 4 | `list_dir` | `relative_workspace_path` | 列目录 |
| 5 | `grep_search` | `query`, `case_sensitive?`, `exclude_pattern?`, `include_pattern?` | 正则 + 包含/排除过滤 |
| 6 | `edit_file` | `target_file`, `instructions`, **`code_edit`**, `blocking` | **指令 + 编辑块分离** |
| 7 | `file_search` | `query` | 文件名模糊搜 |
| 8 | `delete_file` | `target_file` | 删文件（我们该禁） |
| 9 | `reapply` | `target_file` | 编辑失败后重放 |
| 10 | `parallel_apply` | `edit_plan`, `edit_regions[{path,start_line,end_line}]` | **多文件并行编辑** |

**三个结构上的启发**：

| 启发 | Cursor 怎么做 | 为什么重要 |
|---|---|---|
| **① 路径全部是"相对工作区"** | `relative_workspace_path` | 天然沙箱化，不涉及绝对路径泄露 |
| **② 编辑 = 指令 + 代码块分离** | `edit_file{instructions, code_edit}` | 模型说"改什么"和"改成什么"分开，可审计 |
| **③ 执行 = 可声明审批** | `run_terminal_cmd{require_user_approval}` | 由**模型**声明这条命令是否需要人批（而不是全有或全无） |

**第 ③ 条最值得抄**：我们现在是"按 action_class 一刀切"（`05 §1` 三类门）。
Cursor 是**让模型自己声明风险**，再叠加策略校验——这比一刀切更细，且能减少无谓审批。

## 3. S1 · Codex 机制面（B 级，二进制提取）

### 3.1 内建工具（从 `apply_patch` 的 tree-sitter 语法块确证）

二进制里有一段 **tree-sitter 语法查询**，用于识别 `apply_patch` heredoc：

```
(program . (redirected_statement body: (command name: (command_name (word) @apply_name) .)
  (#any-of? @apply_name "apply_patch" "applypatch")
  redirect: (heredoc_redirect . (heredoc_start) . (heredoc_body) @heredoc . (heredoc_end) .)) .)
```

**这证明三件事**：
1. Codex 的 `apply_patch` 是**自由文本格式**（heredoc）而不是 JSON——模型写 patch，框架解析
2. 它用 **tree-sitter 做语法级识别**，不是正则
3. 支持 `apply_patch` 与 `applypatch` 两种拼写（容错）

### 3.2 特性开关（`codex features list`，只读命令，确认存在的机制）

| 开关 | 状态 | 对应我们的缺口 |
|---|---|---|
| `multi_agent` / `multi_agent_mode` / `multi_agent_v2` / `multi_agent_v2_dynamic_tools` | stable/under dev | 我们有 `B12.5`，但**无动态工具** |
| `async_compaction` / `compaction_image_budget` / `context_management` | 混合 | 我们只有裁剪，`B12.4` 补压缩 |
| **`browser_use` / `browser_use_external` / `browser_use_full_cdp_access`** | **stable** | **我们完全没有** |
| **`computer_use`** | **stable** | **我们完全没有** |
| `code_mode` / `code_mode_host` / `code_mode_interrupt` / `code_mode_tool_search` | 混合 | **代码模式**（模型直接写代码而非调工具） |
| `guardian_*` 系列（多 agent 历史、父级 compaction 复用、root handoff） | under dev | 多 agent 上下文共享 |
| `external_agent_memory_import` | under dev | 外部记忆导入 |
| `incremental_tools` | stable | 增量工具注册 |
| `deferred_tool_world_state` | stable | 工具延迟加载 |
| `mcp_tool_list_changed` | stable | MCP 工具变更通知 |
| `experimental_windows_sandbox` / `elevated_windows_sandbox` | 混合 | **Windows 沙箱**（我们在容器里，可忽略） |

### 3.3 沙箱与审批（`--help` 确证）

```
-s, --sandbox <SANDBOX_MODE>
     Select the sandbox policy to use when executing model-generated shell commands
-a, --ask-for-approval <APPROVAL_POLICY>
     Configure when the model requires human approval before executing a command
```

**两个正交维度**：`sandbox_mode`（能做什么）× `approval_policy`（谁批）。
我们现在只有 `action_class` 一维（`05 §1`），**缺 sandbox 维度**。

### 3.4 插件市场（`codex plugin --help` 确证）

```
add          Install a plugin from a configured or remote marketplace
list         List plugins available from configured and remote marketplaces
marketplace  Add, list, upgrade, or remove configured plugin marketplaces
remove       Uninstall a plugin and remove its local cache
```

**这正好对应我们 `36` 的三层**：`marketplace` = 发现层，`list` = 注册层，`add/remove` = 装配层。
**我们的设计方向是对的，且多了"增量刷新 / 冷却 / 复用响应"三件它没有的**。

| 项 | 内容 |
|---|---|

## 9. 一句话结论

> **三家在"手"上完全同构**（读/写/编辑/搜/执行/计划），差别只在细节；
> **我们在"手"上完全是空的**，只有一张嘴（选 oracle）和一只拳头（发请求）。
>
> 所以不是"再加几个安全动作"的问题，是**先长出两只手**——
> 而这与"地址不入库 / 判定可 replay"**不冲突**，因为手产出的是 `Lead`，不是 `verdict`。
