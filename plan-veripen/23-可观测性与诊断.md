# 23 · 可观测性与诊断

> 目标：任何时候都能回答三问——**现在在干什么、为什么慢、为什么贵**。
> 不是搭一套监控平台，而是让 `make stats` 与 `make doctor` 说人话。

## 1. 三类可观测数据

| 数据 | 位置 | 用途 | 保留 |
|---|---|---|---|
| 业务事件 | `task_events`（库） / `out/<task>/step.jsonl` | 每一步做了什么、耗时、token | 90 天（导出 parquet 后清表） |
| 请求留痕 | capsule + `out/capsules/bodies/` | 审计、replay | 永久（WORM 语义） |
| 运行日志 | stdout JSON（docker logs） | 故障定位、支持 | 本地 7 天滚动 |

**三者通过 `trace_id` 与 `task_id` 互相跳转**，这是唯一的关联键。

## 2. `make stats TASK=<id>` 输出（三张表）

```
① 步耗时 Top5         seq=17 oracle=idor 842ms | seq=22 http 1.2s | ...
② token 分布          plan 38% / tool_out 21% / retry 12% / judge 0% / other 29%
③ 重试与降级          retry=2 (timeout×1, 5xx×1) | degrade=none | throttle_wait=3.4s
```

| 表 | 看什么 | 异常信号 |
|---|---|---|
| 步耗时 | 哪个 oracle 慢 | 单步 >10s → 查目标响应或网络 |
| token 分布 | 哪类消耗大 | `retry >20%` → 模型输出不稳定 |
| 重试降级 | 稳不稳 | `degrade≠none` → 模型/网关问题 |

## 3. `make stats ENG=<engagement>` 聚合（对交付有用）

| 指标 | 用途 |
|---|---|
| 每资产请求数 / QPS 峰值 | 证明没打挂客户 |
| 发现数 / 已验证率 / 平均置信度 | 质量画像 |
| 平均首发现步数 | 效率 |
| 总 token / 总成本 / 每发现成本 | 报价依据 |
| 死信率 / 越界次数 | 稳定性与安全性（越界必须 0） |

## 4. 日志规范

```json
{"ts":"...","level":"info","svc":"worker","trace_id":"t-01J...","task_id":"01J...",
 "kind":"http","asset":"web-01","oracle":"idor_cross_account","elapsed_ms":41,
 "status":200,"ok":true,"error_class":null,"tool":"http"}
```

| 规则 | 说明 |
|---|---|
| 敏感字段在 logger 层 redact | `authorization|cookie|set-cookie|x-api-key|password` → `<redacted>` |
| `level` 约定 | error=需人处理；warn=自动恢复但需关注；info=正常；debug=http 明细（默认关） |
| 不打印 body | body 只进 capsule，日志只记 `body_sha256` 与前 200 字符 |
| `error_class` 必填（失败时） | 对齐 04 的三分类，便于统计 |

## 5. `doctor` 的 15 项（见 12 §3，这里补充"说人话"要求）

| 失败时的输出必须包含 | 例 |
|---|---|
| 已查到的现象 | "端口 8000 被 pid 4242 (python) 占用" |
| 一条能直接复制的修复命令 | "kill 4242 或改 .env 的 API_PORT=8010" |
| 跑完之后该做什么 | "改完执行 make up" |

**禁止**：`Error: connection refused`、`Traceback...` 这类无行动信息的输出。

## 6. 三个"必须能在 1 分钟内定位"的场景

| 场景 | 定位命令 | 期望输出 |
|---|---|---|
| 任务卡住 | `make stats TASK=x` 看最后一步 | 指出卡在 preflight（等令牌）/ 等审批 / http 超时 |
| 报告缺一条发现 | `make replay ID=n` | 四态之一 + 原因码 |
| 客户现场跑不起来 | `make doctor --deep` | 红项 + 修复命令 |

## 7. 指标埋点（不做 Prometheus，先做文件）

| 埋点 | 位置 | 频次 |
|---|---|---|
| `step_latency_ms` | task_events | 每步 |
| `tokens_total` | task_events.budget_json | 每步 |
| `throttle_wait_ms` | task_events(kind=throttle) | 每次排队 |
| `scope_denied` | task_events(kind=scope ok=0) | 每次 |
| `replay_status` | capsules | 每次 replay |

`make stats` 直接读这些，不引入时序库。**P2**：真需要趋势图再接 Prometheus。

## 8. 交付时的"可观测性承诺"（写给客户看）

| 承诺 | 证明方式 |
|---|---|
| 我们的每个请求都可追溯 | 任意发现 → capsule → 请求/响应/时间/IP |
| 我们的速率受控 | `stats ENG` 输出 QPS 峰值曲线，不超合同 |
| 越界为零 | `/bounds` 页为空，`doctor --deep` 第 5 条查询为 0 |
| 出问题能复盘 | 日志 + 事件 + 证据三件套，按 task_id 串起来 |
