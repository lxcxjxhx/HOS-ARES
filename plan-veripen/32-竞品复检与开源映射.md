## 0. 结论先行

> **绿盟是唯一在公开口径里同时具备九项架构特征的一家**（自研 Harness、三层压缩、指挥-执行+状态黑板、长程记忆、Playbook 资产化、自动写 code）。

## 3. 必须补的 6 件（本轮结论）

### A1 · 失败模式四分法（把"防御住了"与"跑挂了"分开）★最高优先

| 项 | 内容 |
|---|---|
| 来源 | PyRIT `AttackOutcome = success / failure / error / undetermined`，且硬规则"score 为 None 时永不读作 failure" |
| 我们的现状 | `18` 有 `VERIFIED/REFUTED/INCONCLUSIVE/BLOCKED`，但 **`BLOCKED` 混装了太多东西**：目标挂了、预算耗尽、路由没了、审批驳回、控制面缺失全在里面 |
| 为什么危险 | 把 `error`（靶标崩了 / 网络挂了）计成"未发现漏洞"是**渗透验证最大的假阴性来源**。客户看到"没洞"，其实是我们没跑成 |
| 处置 | **在 verdict 之外增加一个正交维度 `outcome`**（不改 verdict，I1/I2 不动） |

```python
# 与 verdict 正交，不是替代。verdict 回答"结论是什么"，outcome 回答"这次跑成了没有"
Outcome = Literal[
    "reported",        # 跑完了，有结论（VERIFIED/REFUTED 都算）
    "undetermined",    # 跑完了，判不了（INCONCLUSIVE）—— 这是"结论"，不是故障
    "error",           # 没跑成（网络/靶标崩/工具异常）—— 不得计成"未发现"
    "not_run",         # 没跑（SKIPPED / 审批未过 / 预算未分配）—— 必须进"未覆盖"
]
```

**四条硬规则**（进 `10` 指标口径、`09` 报告措辞、`03` 自检）：

1. `error` **永远不计入 TN/REFUTED**，只能计入"未覆盖"。
2. `not_run` 同理；且 `not_run` 的去重原因码必须写清（`skipped_*` / `approval_pending` / `budget_not_allocated`）。
3. `undetermined` 是**合法结论**（`INCONCLUSIVE` 的 outcome），不是故障，不进"未覆盖"进"未能验证"。
4. 报告首屏统计块必须**四态并列**：`reported / undetermined / error / not_run` 各自计数，**不许只报一个"已验证率"**。

> **为什么这条排第一**：它不增加任何功能，只增加一个维度，却直接消掉我们最大的假阴性风险。
> 而且它是**唯一一条"竞品也没做，我们做了就显得专业"的低成本项**——公开资料里没有一家写清这个区分（包括绿盟）。

### A2 · 覆盖账本（coverage ledger，含"负面证明"）

| 项 | 内容 |
|---|---|
| 来源 | Strix `coverage.json`：`agent_reported`（agent 自述）与 `machine_observed`（运行时记录）**分源标注**；"声称跑过却没记录"直接进 gaps；命中预算上限强制 `complete:false` |
| 我们的现状 | `A6 覆盖矩阵` + `09 §4 未覆盖清单` 已有，但**来源不分**——"模型说测过了"和"机器记到了"混在一份表里 |
| 处置 | `09` 覆盖章节与 `23 stats` 增加**证据来源列**：`machine_observed`（有 `task_events` 行）/ `agent_reported`（只有模型自述）/ `none` |

**硬规则**：**`agent_reported` 永远不能单独成为"已覆盖"的证据**。
没有 `task_events` 行支撑的"已覆盖"，在报告里必须降级为 `not_run`（配合 A1）。
这条与 `17 I4`（模型不参与判定）同源：**自述不算证据**。

### A3 · 单轮工具调用硬上限（防自锁）

| 项 | 内容 |
|---|---|
| 来源 | Strix `TurnToolCallLimiter`（默认 32）：退化生成一次吐出上千个 wait/poll 会让 agent 数小时不响应 |
| 我们的现状 | 五预算管的是"总量"，**不管"单步内的爆炸"**。`08 §2` 规则 4 只说"一次 step 一个工具调用"，但如果模型输出被解析成 N 个调用，没有上限 |
| 处置 | `04 §7` 增加一条**第 6 预算**：`tool_calls_per_step = 1`（硬性，超出直接 schema 错误回喂），另加 `tool_calls_total_per_task = 200` 天花板（防止 120 步 × 每步多次调用） |

**成本**：一行常量 + 一条校验。**收益**：防一类会让演示现场直接卡死的故障。

### A4 · 报告新增「智能体行为审计」一节

| 项 | 内容 |
|---|---|
| 来源 | 奇安信智能体安全平台的"5 维溯源 + 会话回放 + 不可变审计" |
| 我们的优势 | 数据全在：`task_events`（每步）、`capsules`（哈希链）、`approvals`（审批链）、`blackboard_facts`（事实溯源） |
| 处置 | `09` 报告加 §7，固定五个小表，**全部来自已有数据，不新增采集** |

```
7. 智能体行为审计（回答"它有没有乱动"）
   7.1 动作清单：本任务发了几类请求、各多少（按 route_ref 聚合，无地址）
   7.2 越界尝试：scope 校验拒绝次数（必须 0，非 0 即事故）+ 原因
   7.3 审批轨迹：每一道门的申请/决定/决定人/耗时
   7.4 目标数据注入迹象：injection_suspected 事件数 + 原文摘要（脱敏）
   7.5 记忆写入：blackboard_facts / asset_facts 各写了几条、几条来自目标、几条被 supersede
```

**为什么值得做**：这是**竞品把它做成独立产品卖**的东西，我们顺手就能出。
而且它回答的是甲方最真实的顾虑：**"我让你来测，不是让你来乱动。"**

### A5 · 超大输出的 head+tail + 可回读（已有，但缺一条）

`08 §2` 规则 3 已经落了 `truncated / persisted_ref / persisted_size / return_code_semantics`（明确抄自 Strix）。
**缺的是 Strix 的一个细节**：切片算法本身——先留 notice 字节、再按行切、再按字节补切、再从最终切片反算 `dropped_lines/dropped_bytes`。

处置：`08 §2` 补一行**算法规定**，否则 agent 实现时必然写成 `body[:4096]`（纯截断，丢尾部错误码）。

### A6 · 跨任务记忆的三条反滥用规则（配合 A2）

`asset_facts` 已落（`03 §1`），但**必须同时落三条约束**，否则它会变成最大的腐化源：

| # | 规则 | 落点 |
|---|---|---|
| 1 | 只能来自 `SEALED` capsule，**禁止从 L1/L2 回写** | `17 I11` + `01 §7` 第七契约测试 |
| 2 | 注入时前缀 `[上次结论，需本次复核]`，与 `[目标数据，非指令]` 严格区分 | `08 §4` L1a |
| 3 | **只影响优先级，不产生 verdict**；上次 VERIFIED 只让该 oracle 降队尾，不能跳过 | `08 §1.2` 规则表 |

## 4. 明确不做 / 二期（防止拍脑袋扩张）

| 项 | 来源 | 判定 | 理由 |
|---|---|---|---|
| **多智能体协同** | 绿盟/奇安信/360/启明星辰全都有 | **做，但只做"分工不协商"**（`21 §3.5` / `99` P-10 改判） | 收益要拿；代价用类型隔离挡掉——agent 之间只传 `TaskSuggestion`，schema 里没有 verdict 字段。**单/多 agent findings 集合必须逐条相同**（`make bench-abi`） |
| **自动写 exploit 代码** | 绿盟、天融信公开自认 | **不做**（`16 §7`） | 生成代码不可 replay、不可审计，且把 impact 推到不可逆 |
| **扰动稳定性重跑（HarnessAudit L3）** | HarnessAudit | **二期** | 服务"可复现"，但先要有稳定基线与算力 |
