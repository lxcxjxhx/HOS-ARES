# 20 · 认证体系测试点（JWT / OIDC / mTLS / Session / SAML）

> 车云普遍是 **mTLS + OAuth2/OIDC**，不只是账号密码。
> 本章把"认证体系怎么测"变成清单：每条标明**谁判定**（oracle / 人工 checklist），不假装全自动。

## 1. 分层视图

```
客户端 ──mTLS──▶ 网关 ──OIDC/OAuth2──▶ 授权服务 ──JWT──▶ 业务 API
                                          │
                                     会话/Refresh
```

**测试原则**：每一层都要有"正常路径 + 至少一个拒绝路径"的对照，否则判定不了。

## 2. JWT（自动化，归 `jwt_replay`）

| # | 测试点 | 变体 | 判定 | 自动化 |
|---|---|---|---|---|
| J1 | `alg=none` 可接受 | header `{"alg":"none"}` + 空签名 | 200 且返回受保护数据 | ✅ |
| J2 | 签名未校验 | 改 payload 保签名 | 200 且数据为篡改后主体 | ✅ |
| J3 | `sub` 可篡改提权 | `sub` 改为他人/管理员 | 返回特权数据 | ✅ |
| J4 | `role`/`scope` 可篡改 | 加 `admin` scope | 访问管理接口 200 | ✅ |
| J5 | `kid` 注入 | `kid=../../etc/passwd` / `kid=file:///dev/null` | 服务器报错或降级到空密钥 | ✅ |
| J6 | `jku`/`x5u` 外联 | 指向 OOB 域 | 收到回调（=可注入密钥） | ✅ |
| J7 | `exp` 未校验 | 过期 token | 仍 200 | ✅ |
| J8 | `nbf`/`iat` 未校验 | 未来签发 | 仍 200 | ✅ |
| J9 | 算法混淆（RS256→HS256） | 用公钥当 HMAC 密钥 | 200 | ✅ |
| J10 | 无签名段（两段式） | `header.payload.` | 200 | ✅ |

**共同判定**：`baseline 200 ∧ control（无效签名）401/403 ∧ 变体 200`。
J5/J6 若服务器 500 但泄露堆栈/路径，降级为 `INCONCLUSIVE` + 记 info 级发现。

## 3. OIDC / OAuth2（半自动，归 `oauth_flow` 检查单）

| # | 测试点 | 做法 | 判定 | 自动化 |
|---|---|---|---|---|
| O1 | `redirect_uri` 校验 | 改 `redirect_uri` 到 OOB 域 / 加路径后缀 / 用 `@` 混淆 | 是否跳转并带 code | ✅ 可自动 |
| O2 | `state` 缺失或可预测 | 去掉 state 重放授权请求 | 是否接受 | ✅ |
| O3 | `nonce` 未校验 | 重放 id_token | 是否接受 | ⚠️ 需解码 |
| O4 | PKCE 降级 | 有 challenge 时用 `plain` 或无 challenge 换 token | 是否成功 | ✅ |
| O5 | code 可重放 | 同一 code 换两次 token | 第二次是否成功 | ✅ |
| O6 | token 交换越权 | 用 A 的 code 换 B 的 token | 是否成功 | ⚠️ 需双账号 |
| O7 | 隐式流残留 | `response_type=token` | 是否仍支持 | ✅ |
| O8 | scope 提升 | 请求未授权 scope | 是否授予 | ✅ |

**判定方式**：O 系列多为"是否发生"，用**状态码 + 回调是否到达 + token 能否用**三条件。
无法确定时写 `INCONCLUSIVE` 并附原始响应，不猜。

## 4. mTLS（半自动，归 `mtls_check` 检查单）

| # | 测试点 | 做法 | 判定 |
|---|---|---|---|
| M1 | 客户端证书缺失 | 不带证书直连 | 是否被拒（应 400/403 或 TLS 握手失败） |
| M2 | 过期证书 | 用已过期证书 | 是否被拒 |
| M3 | 自签/非受信 CA | 用自签证书 | 是否被拒 |
| M4 | SAN/CN 不匹配 | 证书 CN 与目标不符 | 是否被拒 |
| M5 | 弱签名算法 | SHA1 证书 | 是否被拒 |
| M6 | 证书吊销未检查 | 用已吊销证书（需 CRL/OCSP 环境） | 是否被拒 |
| M7 | 双向认证只验单向 | 服务端不请求客户端证书 | 无证书也能通 |

**自动化边界**：M1–M5、M7 可脚本化（`httpx` 自定义 SSLContext）；M6 需要 PKI 环境，标人工。
**注意**：M 系列一旦通过，说明整条链路的身份保证失效，severity 直接 critical。

## 5. Session / Cookie（自动化，归 `session_check`）

| # | 测试点 | 判定 |
|---|---|---|
| S1 | 会话固定（fixation） | 登录前后 session id 是否变化（不变 = 漏洞） |
| S2 | Cookie 标志 | `HttpOnly` / `Secure` / `SameSite` 缺失 |
| S3 | 登出未失效 | 登出后旧 cookie 仍可用 |
| S4 | 并发会话无上限 | 同一账号开 N 个会话全部有效（结合 rate_limit） |
| S5 | CSRF token 可预测/可复用 | 换会话后旧 token 仍被接受 |

**判定**：S1/S3/S5 是布尔；S2 是配置项（info/low）；S4 需阈值。

## 6. SAML（人工 checklist，本期不自动化）

| # | 测试点 | 说明 |
|---|---|---|
| X1 | 签名包裹（XSW） | 需要构造多断言 XML，工具化成本高 |
| X2 | XXE | 需解析器行为差异 |
| X3 | 断言重放 | 需 IdP 配合 |
| X4 | 未签名断言被接受 | 手工改 XML |

**本期结论**：SAML 只在报告里给 checklist 与"未覆盖"声明，不做自动判定。**诚实列出来比假装覆盖强。**

## 7. 与 profile 的接口

```yaml
auth:
  providers:
    - id: primary
      type: oauth2
      flow: authorization_code
      client_id: ...
      secret_ref: vault://demo-b/oauth-primary
      scopes: [read]
    - id: mtls
      type: mtls
      cert_ref: vault://demo-b/client-cert
      key_ref: vault://demo-b/client-key
  oidc:
    issuer: https://idp.internal
    redirect_uri: http://tsp-lab.local/callback
  jwt:
    sample_token_ref: vault://demo-b/sample-jwt
```

**规则**：`secret_ref` 只出现引用；`issuer`/`redirect_uri` 必须在 scope 内，否则启动即失败。

## 9. 新增 oracle 的触发条件

| 触发 | 动作 |
|---|---|
| 客户使用 OAuth2 | 提 `oauth_flow` 为正式 oracle（把 §3 的 O 系列判定纯函数化） |
| 客户使用 mTLS | 提 `mtls_check` 为正式 oracle（TLS 层判定，需要自定义 transport 采集握手信息） |
| 客户使用 SAML | 进二期池，先出人工 checklist 模板 |
