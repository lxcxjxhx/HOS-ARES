# 22 · 产品与人机协同（控制台 / 审批 / 降噪 / 三视图）

> 本章回答：**几百条发现怎么让人看得完、敢签字**。
> 不做花哨前端，做一个"能签字"的面：**只读优先、证据可点、越界可见、审批留痕**。

## 1. 交互形态分工（三种读者，三个入口）

| 形态 | 谁用 | 何时用 | 本期 |
|---|---|---|---|
| CLI | 工程师（本人/交付方） | 现场跑、调试、replay | ✅ 主入口 |
| Web 只读控制台 | 甲方安全团队、合规 | 审报告、点开 capsule、看趋势 | ✅ 简版 |
| 导出包（MD/SARIF/JSON） | 客户流程、CI | 归档、工单、代码平台 | ✅ |

**明确不做**：多用户注册、权限体系、在线编辑发现、实时协作。控制台是"看和审"，不是"改"。

## 2. Web 控制台规格（B15）

> **v3 变更**：页面用 `op_id` 标识，不再用路径。
> 控制台自己的路由同样受 `27` 约束——它是"我们的服务"，不是"目标"，但道理一样：
> 写死服务端路由 = 改版就全仓 grep。前端的路由表由 `bindings` 派生。

| 页面（op_id） | 内容 | 关键约束 |
|---|---|---|
| `ui.overview` | engagements 列表、任务计数、发现按严重度分布、最近 7 天 | 只读 |
| `ui.engagement` | 本轮摘要：profile_hash、镜像 digest、路由解析率、断言通过情况 | 显示证据链根哈希 |
| `ui.findings` | 表格：severity / oracle / 资产 / 置信度 / **证据强度** / replay 状态 | 排序、筛选、**批量加入"观察队列"** |
| `ui.finding` | 单条详情：assertion 结构化展示 + 三条 trace 摘要 + **route 来源** + capsule 下载 | 敏感值 `<redacted>`；**只显示 route_ref 前 8 位** |
| `ui.unverified` | 未能验证单列（原因码，含 `SKIPPED` 两类分列） | 措辞中性，禁止"存在" |
| `ui.coverage` | 资产 × oracle 矩阵 **+ 标签 × oracle 矩阵**（已测/未测/阻塞/**零标签命中**） | 一眼看出覆盖缺口 |
| `ui.routes` | **绑定集浏览（只读）**：标签分布、来源分布、置信档、TTL | **只显示摘要，永不显示模板正文** |
| `ui.audit` | 留痕：谁/何时/哪资产/参数哈希/绑定来源 | 只读，导出需审批 |
| `ui.bounds` | 越界事件页（正常应为空） | 非空时页头红色警示 |

**技术选型（最省）**：FastAPI 出 JSON + 一个静态单页（原生 JS + 表格排序 30 行），不上 React。
理由：控制台的价值在数据组织，不在框架。

**`ui.routes` 页的特别说明**：它是 v3 新增的，也是唯一一个"可能泄露攻击面地图"的页面。
所以它做了三件事：只显摘要、只看不算（无导出按钮）、需要额外 token scope（`routes:read`）。
`05 §7` 把 RouteSet 定为 confidential，这一页就是那条定级的落地。

## 3. 降噪队列（让人看得完的核心）

| 机制 | 规则 | 效果 |
|---|---|---|
| 严重度分档 | critical/high 进"立即看"；medium 进"本周"；low/info 折叠 | 默认只看 10 条 |
| 置信度门槛 | `confidence < 0.6` 默认折叠到"低置信" | 挡掉半成品 |
| **证据强度分档** | `route_strength ∈ {crawl, probe}` 单独标"弱证据"，永远不进"立即看" | 防止"猜出来的高危"上头条 |
| 去重合并 | 同 `(asset, oracle, param_signature)` 合并为一条，附"命中 5 处" | 表行数降一个量级 |
| 观察队列 | 人工可标 `watch`，下一轮重点复查 | 形成"关注项" |
| 基线差分 | 与上一轮比，只高亮"新增/复现/已修复/**面已消失**" | 只看变化 |
| 静音规则 | profile 可声明"已知接受的风险"（带审批人），下次不重复报 | 治长期噪音 |

**目标**：一轮 300 条原始 → 人工需要看 ≤20 条。

### 3.1 降噪的排序公式（不许靠"感觉排"）

降噪不是过滤，是**排序 + 折叠**。排序错了，人看的前 20 条全是噪音。

```
priority = 3×severity_score          # critical=4, high=3, medium=2, low=1, info=0
         + 2×route_strength_score    # observed/operator/contract=1, crawl=0.5, probe=0
         + 1×replay_score            # REPLAYED_OK=1, PARTIAL=0.5, 其他=0
         + 1×is_new_since_last_round # 新增=1
         - 3×is_silenced             # profile 声明接受=0（直接折叠）
         - 2×is_duplicate_rolled_up  # 被合并进另一条=0
```

| 规则 | 说明 |
|---|---|
| 同分排序 | `(oracle_id, template_sha256)` 字典序——**不用发现 id**（id 是随机 ulid，不具可比性） |
| 折叠阈值 | `priority < 2.0` 进"低优先"，默认收起（可展开） |
| 弱证据硬规则 | `route_strength ∈ {crawl, probe}` 且 `severity ∈ {high, critical}` **不可能出现**（`09 §3.1` 已禁止），所以公式里不会出现"弱证据高危"这种组合 |
| 静音不可隐藏 | 被静音的条目仍在"已静音"页可查，只是不进默认视图 |

**为什么要给公式**：不给公式，实现者会按"看起来严重的先"排，
而"看起来严重"通常会退化成"标题里有'高危'的先"——那是标题排序，不是风险排序。

### 3.2 批量操作的安全边界（人能一次改多少）

| 操作 | 允许批量 | 限制 |
|---|---|---|
| 加观察队列 | ✅ 任意多 | 无风险（只是标记） |
| 静音 | ⚠️ ≤20 条/次 | **必须填理由 + 审批人**；静音会遮蔽后续报告 |
| 标记误报 | ⚠️ ≤20 条/次 | 会进负样本候选（`99 P-13`），影响 bench 基线 |
| 改 verdict | ❌ 禁止 | verdict 由纯函数给出；人只能"反馈"，不能"改" |
| 删发现 | ❌ 禁止 | 只增不改（`06 §1`） |

**"改 verdict 禁止"是硬约束**：`finding.feedback` 只写 `true_positive/false_positive/unreproducible`，
它是一个**独立事件**，不修改 `finding.state`。报告里两者并列展示——
"系统判定 VERIFIED / 人工标记 FP" 这个组合本身就是最有价值的物料（它指出系统哪里错了）。

**"面已消失"是 v3 新增的一档**：基线差分现在有四种状态，不是三种。
把"端点下线"混进"已修复"，是渗透报告里最伤信任的错误（`06 §5.2` 已把它制度化）。

## 4. 审批门的人工界面（人机交接点）

```
任务转 AWAITING_APPROVAL
  → 控制台 ui.approvals 出现一条卡片：动作、影响、影响的资产、预计请求数、可逆性、绑定摘要
  → 甲方点击"批准/拒绝"，必须填理由
  → 写 approvals(decided_at, decided_by, reason) → 任务恢复
```

| 规则 | 说明 |
|---|---|
| 不可自批 | `decided_by != lease_owner` |
| 有时限 | 1h 过期自动 `EXPIRED`，动作 BLOCKED |
| 影响必展示 | 不写"将执行高危操作"，写"将对 asset X 的 `object_read` 面（3 条绑定）发送 3 个写请求，字段 role" |
| **三类动作分开描述** | 写操作 / 扩范围 / **探测型发现**，三者的风险叙述不同（`05 §3`） |
| 拒绝也留痕 | 拒绝理由进报告附录（合规需要） |

**为什么"影响必展示"里不再出现具体地址**：给审批人看地址会让他以为"这个地址是安全的"，
而审批要判断的是**动作性质**（只读/写/扫描），不是某一串字符。
所以展示的是 `语义面 + 条数 + 字段`，与实际请求一一对应，但不泄露地图。

## 5. 报告三视图的分工（见 09，这里只讲人怎么读）

| 谁 | 看什么 | 建议读法 |
|---|---|---|
| 研发 | `ui.finding` 详情 + trace 摘要 + route 来源 | 先看 assertion，再看复现命令 |
| 合规 | 合规映射章节 + 授权/窗口/留痕 | 只看"是否在授权范围内" |
| 管理层 | 概览页 + 摘要一页 | 只看"几条高危、几条已复现、几条没测" |
| CI | SARIF | 按双 fingerprint 判断新增与结构变更 |

**一句话**：同一份数据，四个视图，四个读者，不写四套内容。

## 6. 反馈闭环（越用越准的唯一路径）

```
人工判定：真（确认）/ 假（误报）/ 无法复现
   ↓ 写 feedback 表（不进权威）
   ↓ make usecase-from-feedback
生成回归用例 → 进 tests/bench/cases.yaml（标记来源）
   ↓ 下一轮 bench 必须复现该判定
```

| 规则 | 说明 |
|---|---|
| 误报必须带原因码 | `control_failed` / `env_diff` / `oracle_limit` / `unknown` |
| 连续 3 次 `control_failed` | 触发该 oracle 的对照逻辑复审（很可能实现错了） |
| 用例来源可溯 | 每条用例带 `source: feedback/<id>` |
| 不自动改判定 | 反馈只改用例，不改 oracle（防"为过测试改判定"） |

## 7. 培训与交接（不写 200 页手册）

| 物料 | 内容 | 形式 |
|---|---|---|
| 一页速查 | 8 条命令 + 4 种故障对应 | A4 打印 |
| playbook | 装不上 / 跑不动 / 结果可疑 / 要立刻停 | 4 段，每段 5 步 |
| 10 分钟录像 | 装 → 跑 → 看报告 → replay → 缩 scope 被拒 | MP4 |
| 现场口述 | 三句话：这是什么 / 它不做什么 / 越界会怎样 | 讲稿 |

## 10. 5 分钟演示脚本（逐句，可直接照读）

| 时间 | 做什么 | 说什么 | 期望看到 | 卡住怎么办 |
|---|---|---|---|---|
| 0:00 | `make up` | "先起环境：Redis、数据库、三个靶场、三个 worker。" | 全部 healthy | 已 `up` 过 → 直接下一步 |
| 0:30 | `make demo` | "提交一个任务：一个客户档、一个资产、九类验证器。注意它现在开始按 oracle 顺序跑。" | 滚动打印 step，能看到 `scope` / `oracle` / `capsule` | 模型慢 → 说"这里会降级到 scripted planner"，同时 `Ctrl-C` 换 `demo-offline` |
| 1:30 | 看 `reports/demo.md` | "三条发现，每条都有 capsule id、置信度、复现命令。" | 表格 + 三条详情 | 文件没生成 → 直接开控制台概览页（`ui.overview`） |
| 2:10 | `make replay ID=1` | "现在把 agent 关掉，只用证据包复现。注意它重发了 baseline、probe、control 三条请求。" | `REPLAYED_OK` | 网络抖动 → 加 `--dry-run` 展示"将发什么" |
| 2:50 | 改 scope 再跑 | "把资产从 scope 里删掉，再跑一次。" | 退出码非 0 + 日志"拒绝" + **零请求** | 若它开始跑 → 这是 bug，当场记下来（这是最该演示的一条） |
| 3:30 | `make bench`（或展示已跑的 bench.md） | "44 个用例三轮，误报 0，越界 0，三轮判定完全一致——因为判定是纯函数。" | 表格 + 未命中用例 | 时间不够 → 只念合计行 |
| 4:10 | `make demo-alt` | "同一份镜像，只换了客户档 YAML。" | 跑通，报告抬头是另一个客户 | 时间不够 → 只展示 `git diff --stat veripen_core/` 为空 |
| 4:40 | 收尾 | "能卖第二家、差异没漏进代码、内网能装、每条发现能复现、有数。五件事都在命令里。" | — | — |

**演示纪律**

1. 每一步先给命令，再给一句话解释，**不念代码**。
2. 任何一步失败，不解释原因，直接切下一条（`demo-offline` 是兜底）。
3. 第 2:50 的"拒绝执行"是全场最重要的一步，**不要因为怕失败跳过**。
4. 全程不用鼠标（除控制台那一步），减少现场变量。
