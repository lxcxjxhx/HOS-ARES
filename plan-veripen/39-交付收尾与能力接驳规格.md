# 39 · 交付收尾与能力接驳规格（v3.6 新增）

> **加入时间：2026-11-02**，触发于 plan-v3.5 全部 33 批 `done` 之后的一次交付前复核。
>
> 本篇回答三个问题：
> ① **v3.5 宣布完成，但现在到底完成到哪一层？**
> ② **为什么"接口全在、能力没有"会被 `done` 掩盖？**
> ③ **到 Strix / Codex / 绿盟驭智 HARNESS 那个档次，还差什么，怎么补，怎么验收？**
>
> **本篇不推翻任何既有条款**：`16` 的范围、`17` 的四态、`21` 的批次照旧。
> 它补的是 **v3.3–v3.5 扩了目标却没扩验收** 留下的那个洞。

---

## 0. 结论先行

| 判断 | 事实 |
|---|---|
| **目标漂移存在，但发生在目标层，不在执行层** | v3.0 的 D-01「验证内核」+ D-05「只打本地靶场」已完整落地；v3.3 起追加的「能打」目标落进了规格，**但没有落进验收** |
| **不是方案跑偏，是方案没收尾** | 173 条 open 里 ~83 条是「形状齐、线没接」；~44 条是真能力缺口；~20 条是有意取舍 |
| **`done` 的定义缺一层** | 当前 DoD 查「表齐、不变量在、oracle 数对」；**不查「这只手能不能拿到东西」** |
| **距 A 档还差三根线 + 一次边界决策** | 见 §4；其中 P2 是业务决策，不是技术债 |

**一句话**：v3.5 交付的是 **B 档顶端（可验证判定内核）+ C 档骨架（平台形状）**；
A 档（真渗透 agent）差 **模型接驳 / 执行接驳 / 沙箱隔离 / 真目标验证面** 四件。

## 1. 目标层的漂移，用规格自己的话作证

### 1.1 初始预期（`17 §3` 已确认表，用户原话）

| # | 决定 |
|---|---|
| **D-01** | 选题是「验证内核」而非「扫描器」 |
| **D-05** | **14 类 oracle、只打本地靶场** —— 边界，已写死 |
| D-07 | 范围不削、批次细化 |
| D-08 | 代码禁硬编码路由；重试只能重发现 |
| **D-10** | **用 REA 逆向对标成熟 agent 产品**（Cursor/Devin/Codex/Strix/PentAGI） |

> **D-10 的动词是「对标/借鉴」，不是「打平」。** 这一条从一开始就写清了。

### 1.2 漂移点：v3.3 自己承认了能力不足

`35` 开篇原文：

> 之前的规划把 agent 的自由度收到「只能选 oracle + 已解析绑定」——
> **代价是打不动新场景：遇到 Strix 能一把梭的场景，我们只能 `BLOCKED`。**

这句话是对的，v3.3–v3.5 连续三波追加（`act.*` / 插件 / 工作台）也是对它的正确回应。
**问题在后面**：目标从「证明」扩成「证明 + 能打」，但 `16 §4` 的断言表只从 A1–A9 加到 A12，
**新增的 A10/A11/A12 三条至今没有可复跑的 `make` 目标**。

### 1.3 硬证据：断言与命令脱节

| 断言 | 规格要求的命令 | 实测 | 说明 |
|---|---|---|---|
| A10 能打同时能证明 | `make bench-leads` | ❌ 不存在 | `act.*` 全仓无调用方 |
| A11 能力可扩展 | — | ❌ 无命令 | 插件无网络客户端，只有纯函数 |
| A12 工作台 | — | ❌ 无命令 | `Executor` 只被测试传入 |
| A2 差异没漏进代码 | `make lint-noleak` | ❌ 不存在 | `lint-noroute` 覆盖了一部分，不是同一件事 |
| A4 不是「我说有洞」 | `make replay ID=n` | ❌ 不存在 | 能力在（`veripen_core/evidence.py`），命令没包 |
| A6 覆盖够宽 | `make coverage-matrix` | ❌ 不存在 | 覆盖矩阵数据在，渲染命令没包 |
| A7 接口能自动覆盖 | `make cases CASES=contract` | ❌ 不存在 | 能力在（`veripen_contract/`），命令没包 |

> **为什么这件事最严重**：规格写了命令，命令不存在，意味着**这条断言从未被任何人跑过**。
> 它和「常量冒充指标」是同一类失败——不报错、不告警，只让 `done` 比事实好看。

## 2. `done` 的定义缺一层（新增 I14）

### 2.1 病灶

`21 §4` 的执行协议要求 DoD 必须贴完整输出。但 v3.3–v3.5 的 DoD 全部长这样：

```
python -m pytest tests            → 1064 passed
python -m mypy --strict ...       → 80 files 0 error
python scripts/lint/*.py          → 0 命中
python scripts/lint/spec_drift.py → missing=0
python scripts/lint/ledger_check.py → 0 问题
```

**这五条全绿，证明的是「形状对」，不是「能力在」。**
`spec_drift` 查的是「表 / 不变量 / oracle 数」——它不知道 `ModelDecider.client` 是空的。

### 2.2 新增不变量 I14：**能力接驳门**

> **任何声称提供能力的批次，其 DoD 必须包含一条「注入点被真实实现替换」的验证；
> 只验证接口形状（协议、类型、签名、闸门）的批次，只能标 `scaffolded`，不许标 `done`。**

三条配套规则：

| # | 规则 | 为什么 |
|---|---|---|
| I14.1 | 批次状态新增 **`scaffolded`**：形状齐、注入点空。`scaffolded` **不计入完成分母** | 现在是二值，只能二选一地撒谎 |
| I14.2 | 每个注入点（`Decider` / `Executor` / `Fetcher` / `Runner` / `Transport`）必须在 `21` 的批次卡里点名「谁提供实现、在哪个批次接上」 | 不写归属 = 没人接 |
| I14.3 | 「能力断言」（A10/A11/A12）必须有可执行命令；**命令不存在 = 断言不成立 = 不许对外讲** | 规格与验收必须同一层 |

### 2.3 注入点全表（`21` 的新增附录）

| 注入点 | 定义位置 | 当前实现 | 归属批次 | 状态 |
|---|---|---|---|---|
| `Decider.client` | `veripen_core/agent/loop.py` | 无（`ModelDecider` 只转结构） | **B18** | scaffolded |
| `workbench.shell.Executor` | `veripen_core/workbench/shell.py` | 无（仅测试传入） | **B19** | scaffolded |
| `actions.exec_tool` 的 `run` | `veripen_core/actions/__init__.py` | 无（只产 argv） | **B19** | scaffolded |
| `plugins` 的 fetch | `veripen_core/plugins/discovery.py` | 无（只有预算计数） | **B20** | scaffolded |
| `asset_facts` 的写入调用点 | `veripen_core/blackboard.py` | 无（seal 后未调） | **B21** | scaffolded |
| `todo` 的持久化 | `veripen_core/workbench/plan.py` | 无（内存） | **B21** | scaffolded |
| `SandboxNetwork` 的真隔离 | `veripen_core/workbench/shell.py` | 无（建模，非隔离） | **B20** | scaffolded |

## 3. 断言 A2/A4/A6/A7/A10/A11/A12 的命令补齐（B18 的前置）

> **原则：命令先落地，且必须能红。** 一条永远绿的命令比没有命令更糟（`B10-h15ledger` 的教训）。

| 断言 | 新增 `make` 目标 | 失败条件（必须能红） |
|---|---|---|
| A2 | `lint-noleak` | `veripen_core/` 出现客户专有串（`profiles/*` 的行业词） |
| A4 | `replay ID=n` | 给一个已篡改 capsule → 必须 `TAMPERED` |
| A6 | `coverage-matrix` | 某 oracle 有 0 条用例 → 列为「未覆盖」并计入分母 |
| A7 | `cases CASES=contract` | 两次 `routeset_sha256` 不同即红 |
| **A10** | **`bench-leads`** | **`act.*` 产 0 条 lead，或闭环率 < 0.60 即红** |
| **A11** | **`plugin-roundtrip`** | **装一个本地 knowledge 插件后 verdict 变一个字即红** |
| **A12** | **`workbench-smoke`** | **`fs.write` 未真落盘 / `shell.run` 未真执行 / `plan.enter` 后仍可写 → 任一即红** |

**这三条（A10/A11/A12）在 B18 之前必然是红的，这正是它们的价值**：
现在没人知道手是空的，补上之后所有人都会知道。

## 4. 到 A 档（Strix / Codex / 驭智 HARNESS）的四件

### 4.1 六维现状

| LLM 自主决策 | 核心 | ❌ 未接（`client` 空） | **接驳**（1–2 天） |

## 6. 停止条件（本篇新增）

| 现象 | 必须做 |
|---|---|
| 某个断言声称成立但命令不存在 | 停线：先把命令落地并证明能红，再谈这条断言 |
| 某批次标 `done` 但存在空注入点 | 改标 `scaffolded`，并在 `21 §2.6` 点名归属批次 |
| 对外材料出现「达到 Strix 档次」类似表述 | 停：A 档四件未齐前，只允许讲「判定证据链更严，执行面更窄」 |
| A10/A11/A12 命令长期红 | 不许删命令、不许放宽阈值；要么接上，要么显式降级为 `99` 二期 |

## 7. 一句话

> **v3.5 交的是「能证明」，v3.6 要补的是「能证明它真的能打」。**
> 前者已经比商业产品严；后者差四件，三件是接线，一件是**你的边界决策**。
> **先把命令落地让红可见，再去接线——顺序反了，就又是一轮「done 但不成立」。**
