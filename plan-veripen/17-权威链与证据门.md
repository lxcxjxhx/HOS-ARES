# 17 · 权威链与证据门

> 本册（`plan-veripen/`）是**规划权威**，不是执行权威。执行权威在真正的项目目录里。
> 本文定义：三者各管什么、当前处于哪一档状态、下一道门是什么、证据怎么分类。

## 1. 权威三层（不许互相抄成三份大文档）

| 层 | 文件（项目建设后路径） | 回答什么 | 本册对应 |
|---|---|---|---|
| 总设计案 | `<project>/总设计案.md` | 做什么、为什么、不做什么、四态决策 | `00-总规划` + `16-完整范围与交付地图` |

## 2. 蓝图档位（本项目该选哪一档）

| 档位 | 条件 | 本项目 |
|---|---|---|
| `single-blueprint` | 单主循环、少量组件 | ❌ 不够：17 批里有 5 个独立验收门 |
| **`blueprint-set`** | 多领域但仍是一个产品，存在独立交付物与验收门 | ✅ **选这个**：深度 2，直属领域蓝图 ≤5 |
| `program-blueprint-set` | 多宿主、多阶段、长期迁移 | ❌ 过度：本项目单宿主、单一产品 |

**定档结果**：`blueprint-set`，`maxDepth=2`，`maxChildren=5`，`runtimePersistentBlueprintBudget=0`。
五个领域蓝图：`BP-CORE`（内核/调度/guard）、`BP-PROFILE`（客户档）、`BP-EVIDENCE`（证据/replay）、`BP-CAPABILITY`（14 类 oracle + 契约生成）、`BP-DELIVERY`（报告/离线包/控制台）。

**渐进提取**：初始化只建索引，**不预建 5 个空壳**；做到对应波次时再提取，ID 分配后不得重排改义。

### 已定默认值（不阻塞开工，driver 可随时改）

> 原则：**规划不能留悬空问题**。每个 OPEN 都给出默认决策 + 改判条件，开工照默认走；
> 你要改，说一句即可，成本都是"改一个配置/一个容器"，不是重写。

| # | 问题 | **默认决策（已生效）** | 改判条件 | 改动成本 |
|---|---|---|---|---|
| O1 | demo-b 用 OpenAPI 解析还是手写路径 | **复用 B8 的解析器**（40 op 自动派生 `resource_paths`） | 客户 OpenAPI 不规范时降级为手写 | 半天 |
| O2 | 报告中文 only / 中英双份 | **中文**（`lang: zh-CN`） | 有海外客户 → 加 `en-US` 模板 | 2 小时 |
| O3 | SQLite / PG | **compose 变量切换**：默认 SQLite，交付档 `DB=postgres` | 客户要求高可用 | 1 小时（已预留） |
| O4 | 审批门演示程度 | **拒绝 + 批准各一次**（批准走 `scope_expand`） | 演示时间紧 → 只留拒绝 | 30 分钟 |
| O5 | 模型 Ollama / 网关 | **Ollama 容器**（离线是卖点），`VERIPEN_MODEL` 可切网关 | 客户有 GPU/网关 | 1 小时 |
| O6 | 控制台给不给"下载 capsule" | **给**（脱敏后，只读） | 客户禁止导出 | 30 分钟 |

**与 v1.1 的差异**：v1.1 把 O3/O5 标成"卡 D1 必须先决"——那是把决策成本转嫁给用户。
v2 改为"给默认值 + 说清改判成本"，开工不被卡住。

### 已否决（保留理由，避免复活）

| # | 否决项 | 理由 |
|---|---|---|
| R-01 | 分布式锁代替租约 | 锁要释放、会残留；租约自带过期 |
| R-02 | 引入 Kafka/RabbitMQ | 3 worker + 单 Redis 足够，MQ 增加故障面 |
| R-03 | 让模型参与判定 | 直接摧毁可复现性与 FP=0 |
| R-04 | 语义相似度检索历史证据 | 会张冠李戴 |
| R-05 | 首版上 K8s | 瓶颈是容器数不是编排器 |
| R-06 | 时间盲注进本期 | 抖动大，需采样框架 |
| R-07 | **为了"稳妥"砍到 2 个 oracle**（v1.1 做法） | agent 辅助下写代码不是瓶颈；砍范围等于砍卖点。改为批次细化 |
| R-08 | 一次性把 17 批交给 agent | 失败无法定位，回滚范围是整个仓库 |
