# 03 · 数据模型与状态机

> 目标：任何"卡住/重复/丢结果"的问题，都能在表结构和状态机上找到答案。

## 1. 表结构（SQLite 起步，DDL 与 PG 兼容）

```sql
-- 任务：一切调度的中心
CREATE TABLE tasks (
  id            TEXT PRIMARY KEY,           -- ulid
  engagement_id TEXT NOT NULL,
  idem_key      TEXT NOT NULL,              -- sha256(engagement|asset|oracle|params)
  profile_name  TEXT NOT NULL,
  profile_hash  TEXT NOT NULL,
  asset_id      TEXT NOT NULL,
  oracle_ids    TEXT NOT NULL,              -- json array
  state         TEXT NOT NULL DEFAULT 'QUEUED',
  lease_owner   TEXT,                       -- worker_id
  lease_until   INTEGER,                    -- unix 秒（Redis 授时）
  heartbeat_at  INTEGER,
  attempt       INTEGER NOT NULL DEFAULT 0,
  max_attempts  INTEGER NOT NULL DEFAULT 3,
  error_class   TEXT,                       -- retryable|terminal|needs_human
  error_code    TEXT,
  budget_json   TEXT NOT NULL,              -- 已消耗 steps/tokens/wall/cost
  result_json   TEXT,
  created_at    INTEGER NOT NULL,
  updated_at    INTEGER NOT NULL
);
CREATE UNIQUE INDEX ux_tasks_idem ON tasks(idem_key);
CREATE INDEX ix_tasks_pick   ON tasks(state, lease_until);
CREATE INDEX ix_tasks_engage ON tasks(engagement_id, state);

-- 事件流：step.jsonl 的库内镜像（可观测性主表）
CREATE TABLE task_events (
  seq        INTEGER PRIMARY KEY AUTOINCREMENT,
  task_id    TEXT NOT NULL,
  ts         INTEGER NOT NULL,
  kind       TEXT NOT NULL,   -- plan|preflight|http|oracle|judge|capsule|budget|scope|throttle|approval|error
  oracle_id  TEXT,
  tool       TEXT,
  elapsed_ms INTEGER,
  tokens     INTEGER DEFAULT 0,
  ok         INTEGER NOT NULL,
  err_class  TEXT,
  detail_json TEXT
);
CREATE INDEX ix_events_task ON task_events(task_id, seq);

-- 发现：只引用证据，不复制证据
CREATE TABLE findings (
  id            TEXT PRIMARY KEY,
  task_id       TEXT NOT NULL,
  asset_id      TEXT NOT NULL,
  oracle_id     TEXT NOT NULL,
  oracle_version TEXT NOT NULL,
  title         TEXT NOT NULL,
  severity      TEXT NOT NULL,              -- info|low|medium|high|critical
  confidence    REAL NOT NULL,              -- 规则算出，非模型
  cwe           TEXT,
  state         TEXT NOT NULL,              -- CANDIDATE|VERIFIED|REFUTED|UNVERIFIABLE|BLOCKED
  capsule_id    TEXT,                       -- NULL 且 state=VERIFIED 视为不合法
  created_at    INTEGER NOT NULL
);
CREATE UNIQUE INDEX ux_finding_run ON findings(task_id, oracle_id, asset_id);

-- 证据包：内容寻址，sealed 后不可变
CREATE TABLE capsules (
  id           TEXT PRIMARY KEY,            -- = self_sha256
  finding_id   TEXT NOT NULL,
  path         TEXT NOT NULL,               -- out/capsules/<id>.json
  self_sha256  TEXT NOT NULL,
  prev_sha256  TEXT,                        -- 哈希链
  sealed_at    INTEGER NOT NULL,
  replay_status TEXT DEFAULT 'NEVER',       -- NEVER|OK|FAILED|BLOCKED
  replay_at    INTEGER
);

-- 审批门
CREATE TABLE approvals (
  id           TEXT PRIMARY KEY,
  task_id      TEXT NOT NULL,
  action_class TEXT NOT NULL,               -- reversible_write|scope_expand
  impact_json  TEXT NOT NULL,
  state        TEXT NOT NULL DEFAULT 'PENDING', -- PENDING|APPROVED|REJECTED|EXPIRED
  requested_at INTEGER NOT NULL,
  decided_at   INTEGER,
  decided_by   TEXT,
  reason       TEXT
);

-- 跑分
CREATE TABLE bench_runs (
  id            TEXT PRIMARY KEY,
  profile_name  TEXT NOT NULL,
  started_at    INTEGER NOT NULL,
  cases_total   INTEGER NOT NULL,
  tp INTEGER, fp INTEGER, fn INTEGER, tn INTEGER,
  precision     REAL, recall REAL, f1 REAL,
  replay_pass   INTEGER,
  first_finding_steps INTEGER,
  tokens        INTEGER,
  cost_usd      REAL,
  wall_s        REAL,
  voided        INTEGER DEFAULT 0,           -- 越界即 1，该次跑分作废
  notes         TEXT
);
```

## 2. 任务状态机（8 态，闭环）

```
                     POST /tasks（idem_key 去重）
                              │
                              ▼
                          ┌───────┐   取消(人工)   ┌───────────┐
                          │QUEUED │───────────────▶│ CANCELLED │
                          └───┬───┘                └───────────┘
                     领租约 │ ▲ 租约过期回收(attempt+1)
                              ▼ │
                          ┌───────┐
                          │LEASED │
                          └───┬───┘  开始执行
                              ▼
                          ┌───────┐   遇高危动作   ┌──────────────────┐
                          │RUNNING│◀──────────────▶│AWAITING_APPROVAL │
                          └───┬───┘   审批通过/拒绝  └──────────────────┘
                    ┌─────────┴─────────┐
              成功  ▼                   ▼ 失败
                ┌──────┐          ┌────────┐
                │ DONE │          │ FAILED │
                └──────┘          └───┬────┘
                                      │ attempt ≥ max_attempts 或 terminal
                                      ▼
                                ┌─────────────┐
                                │ DEAD_LETTER │
                                └─────────────┘
```

**迁移唯一入口**：`store.transition(task_id, from_state, to_state, **fields)`，带 `WHERE state=from` 条件更新，返回影响行数；0 行说明被抢，调用方必须放弃当前工作（防双跑）。

```python
def transition(task_id, frm, to, **fields) -> bool:
    n = db.execute("UPDATE tasks SET state=?, updated_at=?, "+set_clause+
                   " WHERE id=? AND state=?",
                   [to, now(), *fields.values(), task_id, frm]).rowcount
    if n == 0:
        log.warn("transition_lost", task_id=task_id, frm=frm, to=to)  # 被别人抢了
    return n == 1
```

**没有这一步，"重复执行"必然发生。** 这是幂等之外的第二道闸。

## 3. 租约规则（数字先定死）

| 参数 | 值 | 说明 |
|---|---|---|
| 心跳间隔 | 5 s | worker 每 5 s 续租并写 `heartbeat_at` |
| 租约 TTL | 30 s | `lease_until = now + 30` |
| 回收扫描 | 5 s | `SELECT id FROM tasks WHERE state IN ('LEASED','RUNNING') AND lease_until < now()` |
| 重排规则 | `attempt+1`；`attempt ≥ 3` → `DEAD_LETTER` | 重排保留已产出的 capsule，不重跑已验证 oracle |
| 心跳超时但进程还活着 | 立即自杀式退出（`os._exit`） | 避免双跑；日志写明 `lease_lost_suicide` |

**为什么是租约不是分布式锁**：锁要释放、会残留；租约自带过期，worker 崩了无需他人善后。

## 4. 发现状态机

```
CANDIDATE ──judge=VERIFIED──▶ VERIFIED       （必须有 capsule，否则降级）
    ├─────judge=REFUTED────▶ REFUTED         （进负样本库，可回灌用例）
    ├─────judge=INCONCLUSIVE▶ UNVERIFIABLE   （报告"未能验证"单列）
    └─────guard 拒绝───────▶ BLOCKED         （越界/未授权/超额，永不进报告正文）
```

**硬约束**：`state='VERIFIED' AND capsule_id IS NULL` 在 04 的日检里视为数据损坏，报告渲染直接拒绝。

## 5. capsule 状态

```
DRAFT ──seal()──▶ SEALED ──replay()──▶ SEALED(replay_status=OK|FAILED|BLOCKED)
                    │
                    └─ profile_hash 变更 ─▶ STALE（仍可读，replay 时提示需重跑）
```

SEALED 后禁止字段修改（`evidence.py` 只暴露不可变 dataclass）。要改就新建 capsule，旧的保留 —— 审计要求可追溯而不是可覆盖。

## 6. 索引与容量预算（避免"跑两天就慢"）

| 表 | 30 天预估行数 | 处理 |
|---|---|---|
| task_events | ~50 万（120 步 × 4000 任务） | 按月分区；`detail_json` 只存 <=2KB；完整 trace 落 `out/` 文件 |
| tasks | ~1 万 | 保持热表 |
| capsules | ~1 万 | 文件在盘上，库只存索引与哈希 |
| bench_runs | 数百 | 永久保留（对外可信度） |

**归档策略**：`task_events` 90 天后导出 parquet 并清表；capsule 文件永不删（WORM 语义，见 06）。

## 7. 一致性自检（`make doctor --deep` 包含）

```sql
-- 1 重复幂等键（应为 0）
SELECT idem_key, COUNT(*) c FROM tasks GROUP BY idem_key HAVING c>1;
-- 2 卡死任务（LEASED/RUNNING 且租约过期 >5 分钟，应为 0）
SELECT id FROM tasks WHERE state IN('LEASED','RUNNING') AND lease_until < strftime('%s','now')-300;
-- 3 无证据的已验证发现（应为 0）
SELECT id FROM findings WHERE state='VERIFIED' AND capsule_id IS NULL;
-- 4 孤儿 capsule（应为 0）
SELECT c.id FROM capsules c LEFT JOIN findings f ON f.id=c.finding_id WHERE f.id IS NULL;
-- 5 越界事件（必须 0，出现即事故）
SELECT COUNT(*) FROM task_events WHERE kind='scope' AND ok=0 AND detail_json LIKE '%VIOLATION%';
```

第 5 条是**上线门禁**：不为 0 不许交付。
