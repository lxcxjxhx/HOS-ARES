# 40 · 验证方案与批次规划

> **本篇不新增能力，只回答一个问题：接下来的每一条"已达成"，凭什么算数。**
>
> `39` 解决的是"形状与实现脱节"，本篇解决的是"结论与验证脱节"。
> 一个批次可以 `done` 而它的结论仍然没人验过——`39 §6` 第一条防前者，本篇防后者。

---

## 0. 结论先行

| 问题 | 现状 | 本篇怎么处理 |
|---|---|---|
| 模型到底有没有用 | **只证到"不影响判定"**（冲突 0），没证过"能自己找" | B29 用 `--discover` 模式专测 |
| 真实资产的检出与误报 | **只在一处自建靶场跑过** | B30 要求至少一个非自建目标 |
| 换模型还能不能用 | 只测过 `deepseek-v4.1-flash` | B31 三模型对照 |
| 成本能不能日常跑 | 只有单轮 8238 tokens / 70.8s | B32 十目标分布 |
| 三档能力怎么对外讲 | 分散在 B18–B28b 的账本里 | B33 汇总成一张带命令的表 |

**总原则**：每批次必须有**失败时会红**的判据。判据不达标本批就算未通过，
**不许改判据让它变绿**（`39 §6` 同源，本篇 `§4` 把它写成 D1–D4 四条红线）。

## 1. 基线（本方案起算点）

以下数字全部来自本仓库实测，不是估计：

| 项 | 值 | 来源 |
|---|---|---|
| 批次账本 | 76 批：68 `done` / 7 `done(legacy-scope)` / 1 `blocked` | `.veripen/batches.jsonl` |
| 单元 + 集成测试 | 1114 passed / 2 skipped | `pytest tests` |
| 类型 | 96 files, 0 error | `mypy --strict` 五目录 |
| 静态闸门 | 十道 lint 全 exit=0 | `scripts/lint/*.py` |
| 评测 | `findings_diff: OK（44 条一致）`，TP26/FP0/FN2 | `run_bench.py --rounds 3` |
| A10 闭环 | 6/6 lead，闭环率 1.00，act 12 / verify 42 同实例 | `cmd_bench_leads` |
| 真模型 | 11 步 / prompt 7485 + completion 753 / 70.8s / 冲突 0 | `scripts/b26/agent_live.py` |
| 真实资产通道 | 8 条绑定 / 10 个 oracle / 84 次真请求 / 带凭据 6 条确认 | `cmd_hunt` |

**起算点带一条负结论**：固定 `pending` 下，模型挑的 oracle 与 `ScriptedDecider`
完全相同，多花 8238 tokens 换 0 增量（B27）。B29 的主要目的就是判定这条结论的适用边界。

## 3. 批次规划（B29–B34）

### B29 · 模型"找"的能力〔P0，最高价值〕

**要回答**：把"该验什么"从用例里拿掉，模型还能不能自己挑对。

| 项 | 内容 |
|---|---|
| **目标** | 分离"排序能力"与"发现能力"——B27 只测了前者 |
| **方法** | 新增 `--discover` 模式：`state.pending` 只给**候选池**（不排序、不指明该验哪些），模型必须靠 `list_routes` 的返回自己判断 |
| **判据 A** | 模型自选集合对"该验集合"的**召回 ≥ 0.8**；标注写进夹具，**不得事后调整** |
| **判据 B** | 相对 scripted 顺序跑，**新增检出 ≥ 1**；为 0 则如实记"模型无发现能力" |
| **判据 C** | 出现 `escalate` 即记一次降级；降级后结果仍须与 scripted 一致 |
| **产出** | `out/b29/discover.json`：自选集合、召回、差集、token、降级次数 |
| **依赖** | 无（仍在 lab 内，不触发 D-05） |
| **成本** | 单轮 70–120s、1 万 tokens 量级；跑 3 轮取稳定 |

两类结果都有用：通过 → B27 负结论被限定为"固定 pending 下无增量"；
不通过 → 负结论升级为普遍结论，"能打"靠 scripted + oracle 库。

### B30 · 真实资产覆盖率〔P0〕

| 项 | 内容 |
|---|---|
| **目标** | 在**非自建**目标上验证检出与误报 |
| **方法** | 优先 DVWA / Juice Shop（容器）；无 docker 时用公开教学靶场，或 operator 指定资产 |
| **判据 A** | 对目标官方漏洞清单**召回 ≥ 0.6** |
| **判据 B** | 抽样 5 条 VERIFIED 人工复核，**误报 ≤ 1 条** |
| **判据 C** | 同目标连跑 2 次，`findings` 集合**逐条相同** |
| **产出** | 召回 / 误报 / 可复现三张表 + 每条 finding 的请求证据 |
| **依赖** | **docker**（`B20-sandbox` blocked）或 operator 指定目标 |
| **成本** | 依赖环境，未测 |

### B31 · 弱模型鲁棒性〔P1〕

| 项 | 内容 |
|---|---|
| **目标** | 确认 B29 的结论不绑在单个模型上 |
| **方法** | 换 2 个更弱模型重跑 B29 同一用例 |
| **判据** | 与 `deepseek-v4.1-flash` 的判定**冲突 0**；允许降级，降级后结果仍一致 |
| **产出** | 三模型 × 同用例对照表 |
| **依赖** | 网关可用模型（模型的 list 接口已返回多个 id，需确认可用性） |

### B32 · 成本与规模〔P1〕

| 项 | 内容 |
|---|---|
| **目标** | 回答"能不能日常跑" |
| **方法** | B29 通过后，`--discover` 跑 10 个不同目标（lab 的多资产变体） |
| **判据** | 单目标 ≤ 2 万 tokens；P95 时延 ≤ 3 分钟 |
| **产出** | 成本分布 + 瓶颈定位 |
| **依赖** | B29 通过 |

### B33 · 三档证据汇总〔收口〕

| 项 | 内容 |
|---|---|
| **目标** | 一张能对外讲、每条带可复跑命令的表 |
| **方法** | 把 B29–B32 的判据逐条落成 `make` 目标 |
| **判据** | 每条断言都有能红的反例；`make assertions` 一次跑完且命令 missing=0 |
| **产出** | `16 §4` 断言表更新 + 命令列 |
| **依赖** | B29–B32 |

### B34 · 凭据管理〔P2〕

| 项 | 内容 |
|---|---|
| **目标** | 凭据不落命令行明文 |
| **方法** | `--token-file` / env 变量 / keyring 三选一；命令行传值改为 deprecated |
| **判据** | 进程命令行与 `hunt.json` 里都搜不到 token 明文 |
| **产出** | 凭据读取模块 + 测试 |
| **依赖** | 无 |

## 4. 判据红线（D1–D4）

四条**任何阶段都不许越**的线，与 `39 §6` 同级：

| # | 红线 | 具体禁止 |
|---|---|---|
| **D1** | **缺输入 ≠ 没漏洞** | 没给 token / OOB / 符号导致的判定，只能是 `BLOCKED` / `INCONCLUSIVE`，不许算进 `REFUTED`，更不许计入"无漏洞" |
| **D2** | **判据不达标不许改判据** | 召回不到 0.8 就写"未达标"；要改门槛必须先写"原门槛为何不合理"，再改，改完重跑全部历史 |
| **D3** | **未测过的数不许出现** | 对外材料里任何百分比都必须有命令支撑；`out/` 里的临时结果不算 |
| **D4** | **负结论与正结论同等交付** | 模型没有发现能力、真实资产召回为 0，都必须写进账本与对外材料，删掉等于自欺 |

D1 的落地检查已经在 `cmd_hunt` 里体现：空 token 不发 `Authorization` 头
（发一个空的 `Bearer ` 出去，目标会记成"无效凭据尝试"，掩盖"根本没带身份"这件事）。

## 5. 执行顺序

```
B29（模型能不能找）── 不依赖任何决策，先做这个
   ↓
   ├─ 通过 → B31（弱模型）→ B32（成本）
   └─ 不通过 → 记负结论，跳过 31/32，直接 B30
   ↓
B30（真实资产）── 卡在 docker / 指定目标
   ↓
B33（汇总）── B34 可随时插队（它不依赖任何前置）
```

B29 与 B30 可并行，但 B30 有环境前置。

## 6. 决策项（需 operator 拍板，不是技术债）

| # | 决策 | 影响 | 未拍板时的默认 |
|---|---|---|---|
| 1 | B30 用哪个目标 | 决定能否测真实召回/误报 | 不做 B30，记为未验证 |
| 2 | `D-05` 是否正式选 B | 选 B 才允许对外讲"能打真实资产" | 保持 A，外部只讲"验证内核" |
| 3 | 是否允许用网关其他模型 | 决定 B31 可行性 | B31 记为未验证 |

**这三条都不能由实现方替 operator 决定**，因为它们改变对外承诺。

## 7. 文件管理

产出按以下规则落位，避免"跑完之后找不到证据"：

| 产物 | 路径 | 保留期限 |
|---|---|---|
| 每批次证据 JSON | `out/<batch>/<stage>.json` | 本会话（`out/` 已 gitignore） |
| 判据结论 | `.veripen/batches.jsonl` 的 `dod` / `evidence` 字段 | 永久（只增不改） |
| 能红的测试 | `tests/` 下对应文件 | 永久 |
| 对外用的表 | `16 §4` 断言表 | 永久 |

三条纪律：

1. **`out/` 不进版本库**，证据靠账本的 `evidence` 字段指向；
2. **每批一个 commit**，message 里带判据结论（通过 / 不通过 / 未验证）；
3. **不通过也提交**——负结论和正结论一样是交付物（D4）。

## 8. 停止条件

| 现象 | 必须做 |
|---|---|
| 判据不达标但想改判据 | 停：先写"为什么原判据不合理"，再改，改完重跑全部历史（D2） |
| B29 不通过却仍对外讲"模型能打" | 停：负结论必须进对外材料（D4） |
| B30 未做却讲"真实资产召回 X%" | 停：没测过的数不许出现（D3） |
| 某批产物只在 `out/` 里、账本没记 | 停：证据没有指针等于没有证据 |
| 三档对照表里出现无命令支撑的行 | 停：补命令，或删该行 |
