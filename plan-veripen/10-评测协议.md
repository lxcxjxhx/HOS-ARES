# 10 · 评测协议（bench）

> 金句：**没有 FP 率的"效果很好"，都是自说自话。**
> 本文规定"怎么算分、跑几次、什么门槛、什么情况作废"。评测协议不随代码改动。

## 1. 固定用例集（进 Git，禁止 cherry-pick）

| 项 | 规格 |
|---|---|
| 位置 | `tests/bench/cases.yaml`（正样本 28 + 负样本 16 = **44 例**，覆盖 14 类 oracle；Tier A 20 例见 11 §4，扩展 24 例见 18 各档） |
| 冻结 | 用例增删必须走 PR 并在 `13-风险登记册` 记录，**跑完再删用例视为作弊** |
| 每例字段 | `case_id, asset, selector, oracle, expect_verdict, seeds, notes`（**无 `endpoint`**：用例只描述语义面，地址由 discovery 解析，`27`） |
| 正样本 28 | 14 类 oracle × 2 例（不同难度：直接/需参数/需对照） |
| 负样本 16 | 14 类 oracle × 1–2 例（看似漏洞实则安全：整站 200、公开资源、URL 回显、签名强校验、正确鉴权） |

用例清单见 `11-测试策略与靶场用例.md` §4。

## 2. 跑分协议

```
make bench                  # 默认 3 轮 × 44 例 = 132 次判定
  ├─ 每轮：清空状态 → 同一 profile → 温度 0 → 固定 seed
  ├─ 中间不复用 capsule（独立任务），避免缓存掩盖问题
  └─ 输出 bench.json + bench.md
```

| 参数 | 值 | 理由 |
|---|---|---|
| 轮次 | 3 | 够看稳定性，成本可接受 |
| 温度 | 0.0 | 尽量压非确定性 |
| seed | 固定（框架支持时） | 同上 |
| 模型 | 每轮记录 `model_name + version` | 换模型必须重跑基线 |
| 预算 | 默认 profile 预算 | 不许为跑分放宽预算（放宽=作弊） |
| 网络 | 全本地靶场 | 无外网抖动 |

## 3. 指标定义（口径写死，不许改）

| 指标 | 定义 | 合格线（本期） |
|---|---|---|
| TP | 正样本判 VERIFIED 的数量 | ≥ 26/28 |
| FP | **负样本判 VERIFIED** 的数量 | **= 0**（硬门槛） |
| FN | 正样本非 VERIFIED 的数量 | ≤ 2 |
| TN | 负样本判 REFUTED/INCONCLUSIVE | ≥ 8 |
| Precision | TP/(TP+FP) | ≥ 0.90 |
| Recall | TP/(TP+FN) | ≥ 0.85 |
| 复现通过率 | replay_status=OK 的比例 | ≥ 0.95 |
| 首次发现步数 | 第一条 VERIFIED 的 step 序号（中位数） | ≤ 25 |
| token 成本 | 全轮 token 总和 / 判定数 | 记录即可，暂无门槛 |
| 墙钟 | 44 例总耗时 | ≤ 30 min（单例 ≤40s） |
| **越界** | post_connect 违规次数 | **必须 0，一次即整轮作废** |
| **路由一致性** | 三轮 `routeset_sha256` 是否相同 | **必须相同**（N6） |
| **路由解析率** | 有标签且能解析到绑定的 oracle 例数 / 总例数 | ≥ 0.95（低于此值说明 discovery 退化） |
| **跳过构成** | `SKIPPED(no_selector_match)` vs `SKIPPED(route_unresolved)` | 后者必须 = 0 |

### 3.0 为什么"路由一致性"是硬指标（v3 新增）

同一份 profile、同一份靶场快照、同一个 resolver 版本，三轮跑出来的 `routeset_sha256` 必须完全一致。
不一致意味着三件事之一：

| 症状 | 真因 | 危险度 |
|---|---|---|
| 三轮 routeset 不同 | resolver 里有隐藏非确定性（并发顺序、字典序、时间） | 高：判定不可复现 |
| 三轮 routeset 同但 verdict 不同 | judge 不纯 | 最高：架构被破坏 |
| routeset 同、verdict 同，但 URL 实际不同 | 有人绕过了 resolver 直接拼地址 | **最高：这就是 hardroute** |

第三种最难发现，因为**所有指标都好看**。所以 bench 额外做一件事：
**每轮结束后比对 `steps[*].request.path_rendered_sha256` 与 `route.template_sha256` 的对应关系**，
任何一步的渲染结果无法由该轮 `RouteSet` 推出 → 整轮作废。这条比 `lint-noroute` 更狠，
因为它是**运行时验证**，能抓出"绕过 lint 的字符串拼接"（例如从数据里读出来的地址）。

### 3.1 为什么 FP 门槛是 0 而不是 0.05

渗透报告的误报会让甲方安全团队白干一天，第二次就没人用了。
**FP 有硬门槛、TP 只要够用**——这个取舍要能讲出来（这是产品判断力的证据）。

### 3.2 为什么"路由解析率"单独计量

只看 TP/FP 发现不了一个退化：**如果 discovery 变保守了**（少解析出一些面），
TP 会下降但 FP 仍是 0——看起来"很稳"，实际上覆盖率悄悄掉了。
所以必须单独记"有标签的例子里有多少能解析到绑定"，并把
`SKIPPED(route_unresolved)` 单列为**必须为 0** 的项（`11 §4.4`）。

> 一句话：FP=0 证明"不说错话"，路由解析率=0.95 证明"还愿意说话"。
> 两个都要，否则要么乱说，要么不说。

## 4. 评分（对外展示用，权重刻意偏保守）

```
score = 0.5 × Precision + 0.3 × Recall + 0.1 × 成本得分 + 0.1 × 报告质量
成本得分 = clamp(基准成本 / 实际成本, 0, 1)     # 基准由首轮基线确定
报告质量 = 见 09 §7（0..1）
硬否决：越界 > 0 → score = 0
```

## 5. 判读规则（避免"数字好看结论错"）

| 情况 | 判读 | 动作 |
|---|---|---|
| 3 轮 TP 波动 > 2 | 环境或模型不稳 | 查靶场 healthcheck、模型超时日志，**先修环境再看代码** |
| TP 稳但 FP 有 1 个 | 优先修 oracle 的对照逻辑 | 把该负样本加入 judge 单测 |
| Precision 高但首次发现步数 > 40 | 策略啰嗦 | 改 agent 提示与 oracle 排序，不动判定 |
| **oracle verdict 三轮不一致** | 违反"判定纯函数"契约 | 视为架构 bug，最高优先级 |
| **`routeset_sha256` 三轮不一致** | resolver 有隐藏非确定性 | 停线修；不允许"多跑几次取多数" |
| **渲染结果推不出绑定** | 有人绕过 resolver（hardroute 复活） | 停线，用 `git log -S` 定位那次提交，整段回退 |
| **`SKIPPED(route_unresolved)` > 0** | discovery 退化 | 先修来源适配器，再谈指标 |
| token 突然翻倍 | 工具输出未截断或重试风暴 | 查 `step.jsonl` 的 truncation 与 retry |
| **重发现次数异常高** | 端点不稳定或 TTL 设太短 | 查 `rediscovery` 轨迹；先修 TTL 或靶场，别放宽配额 |

**最重要的一条**：`judge()` 是纯函数，所以**同一输入下 verdict 三轮必须 100% 一致**。
不一致 = 有隐藏 IO/时钟/随机 → 直接停线修，不允许"多跑几次取多数"糊过去。

**第二重要的一条**（v3）：**地址必须能由 `RouteSet` 推出**。
一旦推出不来，说明系统里出现了第二个"地址来源"——那就是 hardroute，
哪怕它现在工作正常、指标漂亮。这一条是这一版所有改动的最终目的。

## 6. 回归阈值（改 prompt / 改参数 / 换模型时）

| 变化 | 允许波动 | 超过则 |
|---|---|---|
| Precision | -0.02 | 阻止合并 |
| Recall | -0.05（且 TP 不少 ≥2） | 阻止合并 |
| 首次发现步数 | +20% | 需说明原因 |
| token 成本 | +30% | 需说明原因 |
| 越界 | 任何 >0 | 阻止合并 + 复盘 |
| **路由解析率** | 任何下降 | 阻止合并（说明 discovery 退化） |
| **`routeset_sha256` 变化** | 契约/resolver 未变时必须为 0 | 阻止合并 + 查非确定性 |
| **`SKIPPED(route_unresolved)`** | 必须恒为 0 | 阻止合并 |

## 7. 人工基线（对外可信度的另一半）

| 项 | 做法 |
|---|---|
| 谁打 | 1 名渗透工程师，同一靶场、同 44 例、同样窗口 |
| 比什么 | **覆盖率与一致率**（不是速度）。速度只作为参考列 |
| 产出 | `bench-human.md`，与 `bench.md` 并列展示 |
| 结论话术 | "双账号对照类我们与人工一致率 100%，差分类 90%；人工在业务逻辑类明显更强，这也是我们二期的方向" |

**不许说"比人快 10 倍"**——那会引导对方问"那你们准确率呢"。

## 9. 反作弊清单（自己卡自己）

| 作弊方式 | 防法 |
|---|---|
| 跑完删掉失败的用例 | 用例集有 git 历史 + case_id 连续性校验 |
| 放宽预算让 agent 跑更久 | 预算取 profile 默认值，bench 不允许覆盖 |
| 只展示最好一轮 | 必须列 3 轮 + 合计 |
| 负样本改成正样本 | 负样本单独目录，`expect_verdict: REFUTED`，改即需 PR |
| 手工补 capsule | capsule 有 `runner_id` 与时间序，bench 校验生成链路完整 |
| 隐藏越界 | `task_events` 与 capsule `peer_ip` 交叉校验，越界不可隐藏 |
| **把 `SKIPPED(route_unresolved)` 记成 `SKIPPED(no_selector_match)`** | 两者在报告里分列；bench 校验分类来自 resolver 的返回码，不由用例自报 |
| **手写一份"好看"的 RouteSet 塞进夹具** | L0 夹具带 `routeset_sha256` 与来源 sha；`make record-routes` 是唯一生成入口 |
| **让 discovery 只解析"确定能打中"的面，把解析率做成 1.0** | 解析率的分母是"有标签的例数"，不是"解析成功的例数"；标签来自契约，不来自我们 |

前六条防"改数字"，后三条防"改方法"——后者更隐蔽，所以在设计上把分母钉死。
