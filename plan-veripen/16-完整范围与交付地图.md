# 16 · 完整范围与交付地图（v2 全量）

> v1.1 的"第一版合同"是**裁剪版**，它假设 agent 写不快、要保底。
> 修正后的事实：**agent 写代码很快，瓶颈在验证与集成**，所以不削范围，改削"批次粒度"。
> 本文是全量范围的唯一权威；"先做什么"看 `21-实现批次与Agent执行计划.md`，不再另设"第一版"裁剪。

## 1. 范围原则（v2）

| 原则 | 含义 |
|---|---|
| 范围不削 | 14 类 oracle、3 worker、三视图报告、离线包、Web 只读控制台、双客户档、OpenAPI 生成器 —— 全做 |
| 批次细化 | 17 个可独立验收批次（`21`），每批一条 DoD 命令 |
| 证据先行 | 每批 DoD 必须有可执行输出，没有"应该可以" |
| 内核零客户串 | 任何批次都不许往 `core/` 写客户信息（`lint-noleak` 守） |

**"完整"的定义**：本文 §3 的 12 项能力全部有代码、有 DoD、有证据，且 `21` 的 17 批全 `done`。

## 6. 成长轨道（仍在，但不再是"首版之后"）

v1.1 的 G1–G7 改为**批次顺序**（`21` §2），轨道概念保留给"能力边界扩张"：

| 轨道 | 内容 | 进哪一波 |
|---|---|---|
| T1 验证器扩容 | 14 类 → 二期加业务逻辑类 | W2 / W4 |
| T2 契约驱动 | OpenAPI → GraphQL → 时序图 → 用例 | W2 |
| T3 交付形态 | CLI → 只读控制台 → 导出包 | W4 |
| T4 规模化 | 3 worker → 多租户 / K8s | 二期（不进本册） |

## 7. Parking Lot（仍然不做，理由不变）

| 项 | 理由 |
|---|---|
| 业务逻辑类（改价 / 竞态 / 状态机跳步） | 需业务建模，二期；但**报告里要能讲"我们识别了但未覆盖"** |
| 时间盲注 | 抖动，需采样框架 |
| 白盒 SARIF in→out | 需 tree-sitter + 调用图，二期 |
| 交互式工具（msf / sliver） | 靶场不需要；交付给客户时按需加 |
| 多模态车机 | 另一条产品线 |
| SAML 全自动化 | 工具化成本高，本期给 checklist |
| 多租户 / RBAC / K8s | 第二个付费客户之后 |

## 9. 与 v1.1 的差异（一句话）

> v1.1 问"最少做多少能证明思路对"；v2 问"**全量怎么拆才能让 agent 一批批吃掉而不失控**"。
> 答案：范围不动，把验证点从 4 个拆到 17 个，每批一条命令。
