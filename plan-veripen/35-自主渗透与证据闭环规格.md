# 35 · 自主渗透与证据闭环规格（v3.3 新增）

> **这篇是本项目对"能不能真的自动打"的正面回答。**
>
> 之前的规划（`08 §1`）把 agent 的自由度收到了"只能选 oracle + 已解析绑定"——
> 换来 A9 与六态 replay，**代价是打不动新场景**：遇到 Strix 能一把梭的场景，我们只能 `BLOCKED`。
>
> 本篇的解法**不是**开第二个模式（那样就分裂了），而是：
> **在同一个循环里加一类动作 `act.*`，它的产物永远只是"线索"（lead），
> 而线索必须在本次运行内被 `verify.*` 闭环，否则任务不许标 `DONE`。**

---

## 0. 一句话

> **能打 = 允许自由动作；能证明 = 自由动作产生的每条线索都必须被纯函数验证。**
> 两者在同一条时间线上，用同一份黑板、同一套预算、同一次运行完成。

---

## 1. 两类动作，语法不同，产物不同

| | `verify.*`（验证动作） | `act.*`（自由动作） |
|---|---|---|
| 谁发起 | Planner 选一个 oracle | Planner 选一个 act 工具 / 自由命令 |
| 载荷从哪来 | `oracle.plan()` 参数化生成 | 模型/规则**当场构造** |
| 地址从哪来 | `RouteBinding`（唯一来源） | **同样只能来自 RouteBinding**（见 §5，这条不能破） |
| 产物类型 | `Judgement` + `capsule` | `Observed` + `list[Lead]` |
| **能否出 verdict** | ✅ 只有它能 | ❌ **类型上没有** |
| 证据等级 | A（可 replay） | **C（仅线索，未验证）** |
| 计入覆盖矩阵 | ✅ | ✅（但标 `act_only`） |

**这张表的核心**：物理上分不开（同一个循环、同一份预算），但**类型上必须分得开**。

```python
# 错误的做法（会退化成 Strix）
def act_shell(cmd) -> Judgement: ...        # ← 禁止：act 不许返回判定

# 正确的做法
def act_shell(cmd: ShellAction) -> Observed:
    ...
def find_leads(obs: Observed) -> list[Lead]: ...   # 只是"可疑点"
```

## 2. Lead 的结构（线索账本）

```python
@dataclass(frozen=True)
class Lead:
    lead_id: str                  # ulid
    task_id: str
    asset_id: str
    source_action: str            # 哪个 act.* 产生的
    raw_ref: str                  # out/act/<sha>.json —— 完整输出（含脱敏）
    summary: str                  # ≤200 字，机器生成的"一句话线索"
    # ★ 下面三个字段决定它能不能被闭环
    verifiable_by: list[str]      # 哪些 oracle 可能验它（必须非空，否则是死线索）
    selector_hint: str | None     # 需要哪个语义标签
    confidence_hint: float        # 0–1，仅用于排序，**不进 finding**
    state: Literal["pending", "verifying", "verified", "refuted",
                   "unverifiable", "expired"]
    created_at: int
```

**三条硬约束**：

1. **`verifiable_by` 必须非空**——说不清"能用哪个 oracle 验"的线索，是**垃圾线索**，
   在产生时就直接 `expired`，不占预算。
2. `confidence_hint` **只用于排序**，绝不进 `finding.confidence`（后者必须由规则算出）。
3. Lead 只增不改：状态变化写新记录 + `supersedes`（与 `03` I10 同源）。

## 3. 强制闭环（这是"同时能证明"的全部机制）

```
产生 lead 的那一刻，写入两条约束：
  ① tasks.pending_leads += 1
  ② next_action **必须** 从该 lead 的 verifiable_by 里选（除非 verifiable_by 为空→已 expired）

收敛条件（08 §3）追加一条：
  ③ pending_leads == 0 才允许 DONE
```

| 情况 | 行为 | 报告怎么写 |
|---|---|---|
| lead 被 verify 成 VERIFIED | lead → `verified`，生成 finding | 正常出洞 |
| lead 被 verify 成 REFUTED | lead → `refuted`，进负样本候选 | 不出洞，但"打过且否掉"可查 |
| lead 的所有 oracle 都 `BLOCKED(route_unresolved)` | lead → `unverifiable` | **报告"线索未验证：缺 X 面"** |
| 预算耗尽仍有 pending | 任务 `budget_exhausted=leads` | **报告"N 条线索未验证"**（不许藏） |
| 人工 cancel | pending → `expired` | 同上 |

**"不许藏"是这篇规格存在的理由**：
传统扫描器打了 500 个探针、报了 3 个洞，另外 497 个去哪了没人知道。
我们要能做到**"打了 500 个，其中 3 个已证、480 个已否、17 个未能验证（原因见附表）"**。

## 4. 自由动作集（`act.*`，白名单）

| # | action | 干什么 | 沙箱要求 | 典型线索 |
|---|---|---|---|---|
| A1 | `http_raw` | 用**已解析绑定**发任意方法/头/体的请求 | 出网白名单 | 异常状态码/回显/头缺失 |
| A2 | `http_fuzz` | 对已解析绑定的参数做变形喷射 | 同 A1 + 速率 | 差分异常 |
| A3 | `exec_tool` | 跑**白名单二进制**（nmap/nuclei/ffuf/curl/jq） | 容器 + 只读根 + 无特权 | 开放端口/指纹/已知 POC 命中 |
| A4 | `decode` | 解码/解包（base64/jwt/protobuf/gzip） | 无网络 | 结构线索 |
| A5 | `compare` | 两份响应做差分（结构化） | 无网络 | 疑似 IDOR/信息泄露 |
| A6 | `compose` | 拼装候选载荷（**只生成文本，不发**） | 无网络 | 载荷候选 |

**白名单的四个理由**（不是不信任模型，是为了可审计）：

1. 每个二进制都有确定的输出格式 → 能被 `find_leads` 稳定解析；
2. 沙箱配置可枚举 → 能写进 `05` 的边界表，不用每次改代码；
3. 出网行为可统一收口到 `egress_allowlist`；
4. **`compose` 与 `exec_tool` 强制分离**——拼载荷和发载荷是两步，中间必须过门控。

**明确不在白名单里的**：`msfconsole` / `sliver` / `sqlmap` / `metasploit` 模块 / 任意脚本解释器。
理由：这些是**二次编程载体**（它们自己会加载代码），一旦放开，`05` 的边界表就失去意义。
→ `99 P-08` 维持"三期"。

## 5. `act.*` 怎么遵守"地址不入库"（这是最容易被骂的一条）

| 入口 | 允许 | 禁止 |
|---|---|---|
| `http_raw` / `http_fuzz` | 只接受 `route_ref` | **不接受任何 host/url/path 字符串** |
| `exec_tool` | 目标只能来自 `RouteBinding` 的**解析结果**，由框架注入 | 命令里不许出现字面地址（`lint-act-cmd` 静态检查） |
| `compose` | 纯文本生成 | 不许执行 |

**`exec_tool` 的做法**（关键设计）：

```python
# 模型只能这样"要求"
exec_tool(binary="nmap", preset="top_ports", target_ref="route://contract/7f3a...")

# 框架做的事：
# 1) 从 RouteBinding 解析出真实 host:port（这一步在 resolver 内，模型看不见）
# 2) 用模板拼 argv（不是字符串拼接，是数组展开，杜绝注入）
# 3) 交给沙箱执行
```

**所以"跑 nmap 打客户"这件事仍然是零地址的**——
模型说"对这条绑定跑 top_ports"，解析与拼装都在框架内。
`lint-act-cmd` 会扫 `actions/` 下所有 argv 模板，**出现任何 host/ip/端口的字面量即红**。

**代价（诚实写）**：`nmap` 只能打"已解析出来的面"所在的 host，**不能扫整个网段**。
要扫网段 = 需要新资产 + `scope_expand` 审批门。这是刻意的——**扫网段是另一门生意**。

## 6. 与 `verify.*` 的关系（不是两套，是一套）

```
        ┌──────────── 同一次运行、同一份预算 ────────────┐
act.* ──┤ 产出 Lead ──▶ 强制闭环 ──▶ verify.* ──▶ Judgement ├──▶ capsule
        └───────────────────────────────────────────┘
```

| 对比项 | 分裂成两个模式（错误做法） | 本篇（正确做法） |
|---|---|---|
| 预算 | 两套 | **一套**（`04 §7`，`leads` 只加一条 `budget.lead_verify`） |
| 黑板 | 两份 | **一份**（`blackboard_facts` 同时收两种事实） |
| 证据 | 可 replay / 不可 replay 混杂 | **leads 不可 replay，capsules 必须可 replay**，报告分列 |
| 收敛 | 两个循环 | **一个循环，多一个终止条件 `pending_leads==0`** |
| 人的感受 | "两个工具" | **"一个会打、并且会把打过的东西都证完的工具"** |

## 7. 指标（怎么证明它真的变强了）

| 指标 | 定义 | 门槛 |
|---|---|---|
| **线索产出率** | 每条 `act.*` 产生的 lead 数 | 记录（低了说明白打） |
| **闭环率** | `verified+refuted` / 总 leads | **≥ 0.60**（<0.6 说明线索质量差或面不够） |
| **未验证率** | `unverifiable` / 总 leads | 记录并**分原因**（缺面/预算/审批） |
| **闭环耗时** | lead 产生到被 verify 的步数中位数 | ≤ 10 步（超了说明闭环是被动触发的） |
| **A6 扩展** | 覆盖矩阵新增一列 `act_only` | 空格必须有原因 |
| **A8+** | 换模型 finding 差 ≤5% | 见 `08 §5` |

**闭环率 ≥0.6 是最关键的一条**：它同时约束两头——
太低说明 `act.*` 在瞎打，太高（接近 1.0）反而要怀疑是不是只打"肯定能验"的软柿子。

## 8. 验收（B12.7 收尾）

1. `act.*` 六个动作各自跑通，且**每个都产出至少一条 lead**。
2. `test_actions_cannot_import_verdict`：`actions/` 下 import `Verdict|Judgement` 即红。
3. `test_pending_lead_forces_verify`：手动造一条 pending lead → 下一动作必来自它的 `verifiable_by`。
4. `test_lead_without_verifier_expires`：`verifiable_by=[]` 的 lead 直接 `expired`，不占预算。
5. `pending_leads>0` 时任务**不能 DONE**（造一次预算耗尽，看是否标 `budget_exhausted=leads`）。
6. `lint-act-cmd`：argv 模板里塞一个字面地址 → 红。
7. 闭环率在 bench 上 ≥0.6，并写进 `bench.md`。
8. 报告新增「线索」章节：已证 / 已否 / 未验证（分原因），**与 finding 分开列**。

---

## 9. 明确不做

| 项 | 理由 |
|---|---|
| 二次编程载体（msf/sliver/解释器） | 它们会自己加载代码，`05` 边界表失效（`99 P-08` 维持三期） |
| 网段扫描 / 资产发现 | 属"发现面"不属"验证"，且需要 `scope_expand` 审批（`16 §7`） |
| 自动写 exploit 代码并执行 | 生成代码不可 replay；但**可以生成载荷文本**（`compose`），人审后由 `verify.*` 参数化发出 |
| 让 `act.*` 自己判 "这是不是洞" | 这是本篇的第一条铁律。要判，走 `verify.*` |

> **最后一句**：我们不是"不能打"，是**"打了的每一下都要能说清"**。
> 上面这九节就是让这句话成立的工程做法——不是靠纪律，是靠类型、预算和终止条件。
