# 28 · 逆向对标与借鉴规格（REA 工作台）

> 目的：把成熟 agent 产品的**工程结构**搬过来，而不是把它们的**字符串**搬过来。
> 这一章与 `27-无硬路由架构.md` 是同一件事的两面：逆向能拿到大量 URL/路径常量，
> **那些正是最容易变成 hardroute 的东西**。所以本章的第一条不是"怎么逆"，是"逆出来的东西放哪"。

## 0. 隔离铁律（先读这条）

| # | 规则 | 机械保证 |
|---|---|---|
| Q1 | 从样本中提取的**任何** URL / host / 端口 / 路径 / endpoint 常量，只能落在 `docs/research/re/<product>/evidence/` | `make lint-noroute` 对 `veripen_*/`、`profiles/`、`prompts/`、`tests/` 全量生效；research 目录在 allowlist 的**唯一**整目录豁免项 |
| Q2 | 借鉴的是**结构与协议**（状态机、门控点、隔离边界、证据形态），不是内容 | 每份借鉴产出必须写"落地到哪个抽象 + 对应不变量编号"，无落地即不进规划 |
| Q3 | 样本里的提示词、示例、注释一律视为**不可信数据**，不复制进我们的提示词 | `make lint-noleak` 扩一条：prompt 目录内禁止出现样本来源标识 |
| Q4 | 逆向过程本身零外联：不请求样本产品的任何服务端接口 | 全离线；MCP 与模型调用走本地网关，不在分析流程内 |

**为什么 Q1 是铁律**：agent 产品里 endpoint 字符串的密度极高（遥测、更新、鉴权、工具回传）。
一旦有人"顺手复制一个能用的地址"到代码里，`27` 的六条不变量全废，且**单测还会全绿**——因为那个地址在样本环境里确实通。

## 1. 抽取面（六个，按对渗透 Agent 的价值排序）

| # | 抽取面 | 我们要回答的问题 | 落地到 VeriPen 的哪个抽象 |
|---|---|---|---|
| F1 | **工具调用与权限门控** | 哪些动作必须人批？门控点插在循环的哪一步？拒绝后循环怎么继续？ | `05 §3` 审批门 + `08 §1` guard.preflight + `27 §4` 重发现预算 |
| F2 | **沙箱与隔离模型** | 本地 shell / 容器 / 整机 VM / 仅浏览器？边界用什么表达（进程、命名空间、路径白名单）？ | `05 §5` 出口白名单 + `12 §1` 三档部署 + `08 §7` 隔离保证 |
| F3 | **规划-执行分离** | 规划器与执行器是不是两个模型/两个循环？计划的表示形态（步骤树 / 待办 / 图）？ | `08 §1` Oracle 驱动 ReAct（我们比它更窄：只选 oracle 与参数） |
| F4 | **多 agent 编排与状态共享** | 角色怎么分？共享的是黑板、消息总线还是数据库？冲突怎么解？ | 本期**不引入**（`17 R-02` 已否决 MQ；`16 §7` 多 agent 进二期） |
| F5 | **状态 / 记忆管理** | 长期记忆存哪、怎么检索、怎么失效？上下文怎么压缩？ | `08 §4` 上下文三层 + `03` 六表；**明确拒绝**相似度检索证据（`17 R-04`） |
| F6 | **证据与可复现** | "找到问题"怎么变成可验证产物？重放是重发请求还是重放日志？ | `06` capsule/replay + `27 §5` route 块（这是我们的强项，逆向主要看它们的**失败处**） |

> 结论先行：F1/F2/F3 值得深入抄结构；F4 本期抄不了（与我们单宿主单产品定位冲突）；
> F5 抄"分层与失效"，不抄"向量检索"；F6 我们是**领先方**，逆向只用来验证"它们确实没做到"。

## 3. REA 工作台协议（每个目标照做）

```
0  建目录：docs/research/re/<product>/{manifest.json, evidence/, notes.md, extracts/}
1  身份：open_binary / inspect_* 拿到 sha256、架构、签名、打包形态 → 写 manifest.json
2  面：先跑 list_strings（summary 详情）+ list_procedures（summary）建索引，
       **只记录计数与类别分布**，不导出原始字符串
2b **先 grep 调用点，再读实现**：安全相关的模块（sandbox/guard/scope/approval）先数引用数。
       零调用的"安全模块"是最重要的发现——它说明设计有此意图但未接线
       （实证见 `29 §4 反例②`）
3  结构：按 F1–F6 选 1–2 个面做定点分析（decompile / xrefs / call graph），
        产出"结构描述"（状态机、门控点、边界表达），写 notes.md
4  证据：需要的原始证据（符号、结构片段）导出 evidence bundle，落在 evidence/
5  隔离：从 evidence 里抽出的 URL/路径，**只允许出现在 evidence/ 与 notes.md 的引用块内**
6  落地：extracts/<n>-<主题>.md，固定七段（见 §5），必须写"对应不变量编号"
7  收口：close_binary；manifest.json 记 sha256 + 分析日期 + 结论置信度
```

**第 2 步的"只记录类别"是关键**：`list_strings` 在 Electron 应用上会吐几千条 URL。
直接导出到笔记，下一步就会有人把它当"参考地址"用。**先分类统计，再定点取**，从流程上避免污染。

### 3.1 字符串分类法（第 2 步的具体做法）

不导出原文，只按"形状"归类并计数。**分类本身就已经是情报**：

| 类 | 判据（正则形状，不落原文） | 计数之后看什么 |
|---|---|---|
| `telemetry` | 含 `analytics/track/event/collect/beacon` | 有无出站上报、是否可离线关闭 |
| `update` | 含 `update/upgrade/version/manifest` | 自更新通道是**攻击面**还是**持久化面** |
| `auth` | 含 `oauth/token/refresh/jwks/login` | 鉴权形态（这决定 F1 门控设计） |
| `tool-schema` | JSON 片段含 `"name"` + `"parameters"`/`"input_schema"` | **工具层设计的原始素材（最高价值）** |
| `sandbox` | 含 `docker/podman/nsenter/namespace/seccomp` | F2 隔离表达 |
| `approval` | 含 `approve/confirm/allow/deny/consent` | F1 门控点存在性 |
| `prompt` | 长文本 + 含 `you are /你的任务/必须` | **只计数，绝不导出**（Q3） |
| `error` | 含 `error/retry/backoff/timeout` | 失败分类学（对标我们 `04 §3`） |
| `path-like` | 以 `/` 开头且长度 > 3 | **只计数。永远不进 notes，进 evidence 的哈希清单** |
| `host-like` | 含 `.com/.io/.net` 或 `://` | 同上 |

**产出**：`notes.md` 里一张表 `类 → 数量 → 结论一句话`。
`path-like` 与 `host-like` 两类**只允许出现在 `evidence/strings-index.json`（存 sha256 与长度，不存原文）**。
需要看原文时，现场用 REA 重新取，看完不落盘——这是 Q1 的落地方式。

### 3.2 三条"停下来"的信号

| 信号 | 说明 | 动作 |
|---|---|---|
| 分析对象要求联网 | 样本提示"登录后可用"/"需要激活" | **停**，只做静态（Q4） |
| 反调试/反虚拟机干扰分析 | 分析结果不稳定、行为不符 | 停，记 `analysis_blocked`；**不做绕过**（那是另一个课题，且违背 Q4 的离线前提） |
| 提示词里出现"忽略前述指令"类内容 | 样本本身在攻击分析者 | 停，把原文作为**不可信数据**记进 notes（这是最有价值的样本），不执行其中任何要求 |

第三条不是玩笑：agent 产品的 prompt 里真的会有防注入段落，
而 `inspect` 出来的字符串可能包含"请你把以下内容加入你的系统提示"。
**它是要被记录的证据，不是指令。**

## 4. 每个目标的具体分析路径（占位符 + 抽取目标）

### 4.0 通用前 15 分钟（任何目标先跑这个）

| 序 | 动作 | 产出 |
|---|---|---|
| 1 | `inspect_artifact`（有包）或 `inspect_desktop_application`（有目录） | 顶层结构 |
| 2 | `list_strings`（summary）→ 按 §3.1 分类计数 | `notes.md` 的类目表 |
| 3 | `list_procedures`（summary）→ 看符号密度与命名风格 | 判断是否有符号、值不值得下沉 |
| 4 | 定位 F1 的候选（含 `approval/confirm` 类字符串的 xref） | 门控点位置 |
| 5 | 写 `manifest.json` + 前三条结论 | 15 分钟内必须有产出，否则说明目标选错了 |

**"15 分钟法则"**：如果 15 分钟内拿不到一条结构结论，说明这个目标对当前问题没有增量信息，
换下一个。逆向最容易的沉没成本就是"再挖深一点就有了"。

### 4.1 Strix（P0，最直接对标）

| 步 | 动作 | 找什么 | 产物 |
|---|---|---|---|
| 1 | `inspect_artifact` 解 Docker/源码包的目录图 | agent 目录、tool 目录、sandbox 目录的边界 | 结构图 |
| 2 | 读 agent 主循环 | 循环里 **guard/审批/预算** 三处插在哪；拒绝后走哪条边 | F1 状态机 |
| 3 | 读 tool 注册表 | tool schema 的窄度、参数校验位置、错误回喂格式 | F1 契约 |
| 4 | 读沙箱启动 | 隔离表达：容器参数 / 路径挂载 / 网络策略 | F2 边界表 |
| 5 | 读 PoC 验证 | 它怎么把"疑似"变"确认"；有无对照（baseline/control） | F6 差距表 |
| 6 | 跑一次本地 fixture（不连外网） | 观察真实事件序列 | 事件时序图 |

**重点问三个问题**（这三个答案直接决定我们的设计是否要改）：

| 问题 | 若答案是"它做对了" | 若答案是"它没做" |
|---|---|---|
| 拒绝后循环怎么继续？ | 抄它的状态机 | 我们已有（`05 §3`：拒绝 → 该动作 BLOCKED，任务继续） |
| 有没有"对照"？ | 看它怎么定义 control | 我们领先（三条件合取），写进 `28 §6` 差距表 |
| 沙箱是进程级还是容器级？ | 记参数清单 | 我们已定（`12 §1` 三档） |

### 4.2 PentAGI（P0）

| 步 | 动作 | 找什么 |
|---|---|---|
| 1 | 后端目录结构 | planner / executor / memory / tool 四层的依赖方向 |
| 2 | 状态持久化 | 存什么、TTL、失败恢复点（对应我们的租约与 `transition`） |
| 3 | 人机协作点 | 哪些步骤阻塞等人（对应审批门 `05 §3`） |
| 4 | 知识图/记忆 | 用图还是向量；**我们只抄失效策略，不抄检索** |

**额外一问**：它的 planner 输出是什么形态（步骤树 / 待办列表 / 自然语言）？
这决定 F3 的判断——我们的选择是"不允许自由 tool-call"，要确认这个取舍的代价有多大。

### 4.3 Codex CLI（P0，本机可跑）

| 步 | 动作 | 找什么 |
|---|---|---|
| 1 | `--help` 子命令树 | 审批模式的命名与粒度 |
| 2 | 二进制 strings 分类统计 | 审批相关提示语**类别**（不导出原文） |
| 3 | 逆向审批分支 | 状态机：请求 → 展示 → 决策 → 恢复 |
| 4 | 对比我们 | 我们缺"一次批准=一次动作"还是"一次批准=一类动作"（本期是后者，`05 §3 when:first_time`） |

**这是唯一能在本机跑起来的目标**，所以额外做一件别人做不了的事：
**观察它的审批提示文案结构**（不是内容）——是"一句话 + 影响 + 选项"还是"长解释"。
这直接影响我们 `22 §4` 的卡片设计。

### 4.4 Cursor（P1，Electron 双层）

| 层 | 入口（占位） | 找什么 |
|---|---|---|
| 打包层 | `APP_DIR/resources/app`（asar） | 工具定义清单、工具 schema |
| 主进程/原生 | `EXE_PATH` + 同目录 native 模块 | 真正的执行边界：文件写入是否走审批、终端是否沙箱 |
| 进程模型 | `inspect_desktop_application` / `inspect_electron_fuses` | 是否有 renderer→main 的能力白名单 |

**只看结构**：语义索引策略、上下文裁剪策略（F5）。
**不抄**：任何遥测/更新/鉴权地址（Q1）。
**特别注意**：Electron 应用的 strings 里 `path-like` 密度最高。按 §3.1 只计数，
不要因为"看着像 API 路径"就去导出——那些恰恰是最危险的一类。

### 4.5 Devin Desktop（P1）

| 步 | 动作 | 找什么 |
|---|---|---|
| 1 | 客户端二进制与资源 | 与远端沙箱的**会话协议形状**（消息种类、心跳、任务分发） |
| 2 | 本地能跑的部分 | 本地执行与远端执行的分界在哪 |
| 3 | F2 结论 | "整机 VM"型隔离的**接口表达**：我们学它怎么把"沙箱"抽象成可替换组件 |

**它对我们最有价值的一点**：把"沙箱"做成可替换组件。
`12 §1` 的三档部署（本地/内网/离线）本质上是同一个问题——**执行环境必须可插拔**。

### 4.6 HexStrike / Cline / OpenCode（P2）

- **HexStrike**：只抄工具层设计——150+ 工具如何统一 schema、如何标注"只读/写入/危险"。
  这直接对应我们的 `impact: read_only | reversible_write`（`01 §3.1`）与三类审批门（`05 §3`）。
  **要回答的具体问题**：它的"危险"标注是**静态元数据**还是**运行时判定**？
  我们选静态元数据（可在 profile 里覆盖），因为运行时判定没法在启动期 fail-closed。
- **Cline / OpenCode**：作为**最小可读实现**，用来校准我们对 `08 §1` 循环形态的判断。
  我们比它窄（不允许自由构造报文），要确认这个"窄"没有窄到做不成事。

### 4.7 框架层（P3，只读 API 形状）

| 框架 | 只读什么 | 目的 |
|---|---|---|
| Claude Agent SDK | 工具注册 + 权限回调的签名 | F1 门控点的接口形态 |
| OpenAI Agents SDK | handoff / guardrail 的类型 | F1（guardrail 与我们 preflight 的对应） |
| LangGraph | 检查点（checkpoint）的粒度与恢复语义 | F5（对应我们的 `transition` + 租约） |
| CrewAI | 角色与任务的绑定方式 | F4 **反向参考**（我们不做，看它为什么需要） |

**框架层的价值不在功能，在"接口设计的成熟度"**：
它们踩过的坑（比如检查点该存什么）已经写在类型签名里了，比读文档快。

### 4.8 复现实验（不是每个目标都做）

只对**本机可跑**的目标做（Codex CLI、开源项目）。协议：

| 步 | 动作 | 记录 |
|---|---|---|
| 1 | 隔离环境（容器或独立用户），断网 | 环境描述 |
| 2 | 给一个**已知答案**的任务（如"在这个本地 fixture 上找出那个越权"） | 输入 |
| 3 | 观察事件序列（不用它的 UI，看日志/文件/进程） | `events.jsonl` |
| 4 | 记录**它没做对的地方** | 最有价值的部分 |
| 5 | 不留任何它的输出作为我们的数据 | 隔离纪律 |

**第 4 步是重点**：抄优点谁都会，**看它在哪里翻车**才是真收获。
比如"它把一个 404 当成'不存在漏洞'"——那正是我们六态 replay 要解决的问题。

**预期收获**：多 agent 的分工粒度、沙箱参数清单、验证流程的缺口（我们补 control 三条件）。
**预期风险**：它的 prompt 里可能内嵌样例目标 → 按 Q3 只读不抄。

### 4.5 Devin Desktop（P1）

| 步 | 动作 | 找什么 |
|---|---|---|
| 1 | 客户端二进制与资源 | 与远端沙箱的**会话协议形状**（消息种类、心跳、任务分发） |

## 5. 借鉴产出的固定格式（`extracts/<n>-<主题>.md`）

```
## 抽取出处：<product> @ <sha256 前 12>
## 面：F1 / F2 / F3 / F5 / F6 / F7
## 它怎么做（结构描述，<=200 字，不含任何地址/路径）
## 我们的差异（为什么不能照抄）
## 落地项
   - 目标文档：<NN> §x
   - 目标批次：B<nn>
   - 对应不变量：N1..N6 / S1..S8 / A1..A9
## 证据：evidence/<file>（sha256）
## 置信度：observed / derived / inferred
```

**七段各管什么（少一段就不算完成）**

| 段 | 不许写成 | 必须写成 |
|---|---|---|
| 抽取出处 | "Cursor 最新版" | `Cursor @ <sha256 前 12>`（可复现到具体二进制） |
| 面 | "整体架构" | 一个 F 编号；跨面的拆成多份 extracts |
| 它怎么做 | 功能复述 / 贴字符串 | **状态机、门控点、边界表达**——只有结构 |
| 我们的差异 | "我们更好" | 具体的约束差异（如"我们单宿主，它多租户"） |
| 落地项 | "值得参考" | 文档号 + 批次号 + 不变量编号；**三者缺一不算落地** |
| 证据 | 截图 | evidence bundle 路径 + sha256 |
| 置信度 | "确定" | observed（亲眼在二进制里看到）/ derived（推断）/ inferred（猜） |

**规则**：
- 无"落地项"的借鉴**不进规划**（可留在 notes，但不写进 extracts）。
- 有落地项但改 `core` 的，必须回答 `14 §3` 的三问。
- 置信度是 `inferred` 的落地项，**只能进 `99-二期池`**，不能进当前批次。

## 6. 已完成的对照结论（结构层，先给出判断）

| 面 | 我们的选择 | 与主流产品的差异 | 理由 |
|---|---|---|---|
| F1 门控 | 动作类审批 + 默认全拒 + 不可自批 | 多数产品是"命令级提示"，粒度太细导致点不完 | 渗透动作天然成类；`05 §3` |
| F2 隔离 | 应用层白名单 + compose 内网 + post_connect 复核 | 多数是"容器/VM 就完事" | 我们要防 DNS rebinding / 跳转 / CDN 回源，容器不管这个；`05 §1` |
| F3 规划 | Oracle 驱动（模型不能构造报文） | 多数是自由 tool-call | 可复现与限流的前提；`08 §1` |
| F4 多 agent | 本期不做 | 主流在堆角色 | 单宿主单产品，角色编排增加故障面；`17 R-02` |
| F5 记忆 | 四层 + id 取证据 | 主流用向量检索 | 相似度召回会张冠李戴，渗透里致命；`17 R-04` |
| F6 证据 | capsule + 六态 replay + 三条件合取 | **多数产品只有日志/截图** | 这是我们相对商业产品的真正差异点 |
| **F7 地址来源** | **运行时解析，代码零地址** | **主流把 endpoint 写成常量或配置项** | **这是我们相对所有对标产品的结构性差异** |

> 这张表就是"逆向对标"的产出结论：**抄结构、抄边界表达、抄门控位置；不抄字符串、不抄角色数量、不抄检索方式。**

**F7 值得单独说**：上面六个面我们都是"与对标产品同一水平线，各有取舍"。
只有 F7 是**我们没有在别人身上看到过的**——所有 agent 产品最终都会把工具目标写成常量或配置，
因为"这样能跑"。我们选择不这么做，代价是多一层抽象，收益是它不会腐化。
这条要能讲清楚，否则会被当成"过度设计"。

**反驳"过度设计"的三个论据**（答辩时直接用）：

| 质疑 | 回答 |
|---|---|
| "多一层抽象，慢" | `route_discovery` 只在任务开始跑一次（首轮 <=1s，命中缓存后 0 请求），不是每步都跑 |
| "配置里写地址更简单" | 配置里写地址 = 换环境改配置 = 客户现场改文件 = 出错；而且它会被复制进代码 |
| "反正只有几个接口" | 本项目 40 op；车云客户数百 op。手写是 O(n) 人力，解析是 O(1) |

## 8. 质量门（逆向产出也要被审）

| 项 | 门槛 |
|---|---|
| `manifest.json` 完整 | sha256 + 分析日期 + 工具版本 + 面选择，缺一不可 |
| `extracts` 段数 | 七段全有；落地项三段（文档/批次/不变量）齐全 |
| `evidence/` 与 `extracts/` 的地址纪律 | `evidence/` 在 `docs/research/re/` 内（整目录豁免）；**`extracts/` 不豁免**——落进去的地址会被 `lint-noroute` 抓 |
| 可独立读懂 | 不需要读 notes 就能理解结论 |
| 复核 | 由第二人（或第二轮分析）核对"它怎么做"是否夸大 |
| "它怎么做"必附证据路径 | 防止"看到相似状态机就宣布它也是这么做的" |

**最后一条最重要**：逆向最容易自欺——看到一段相似的状态机就宣布"它也是这么做的"。
所以规定：**"它怎么做"这段必须附证据路径**，且按 §5 末段如实标注置信度。

## 9. 不做什么（划清边界）

| 不做 | 理由 |
|---|---|
| 破解/绕过样本的授权校验 | 与分析目的无关 |
| 提取样本的模型权重/训练数据 | 不是我们要解决的问题 |
| 复刻样本的 UI/交互 | 我们不做同类产品 |
| 对商业闭源产品做行为探测（发请求） | Q4：零外联 |
| 把样本的工具清单直接搬成我们的工具 | 工具是**我们问题的解**，不是别人的解 |

**最后一条是本节核心**：抄"工具设计方法"（schema 窄度、错误回喂格式、权限标注），
不抄"工具清单"（150 个渗透工具我们不需要全集；14 类 oracle 是我们的边界）。
