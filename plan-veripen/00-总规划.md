## 0. 一句话

> 一份 `scope` + 一份客户档进来说明打谁、打到什么程度；
> **路由由发现得来、判定由确定性 oracle 给出、LLM 只负责找路**；
> 每条发现产出一条可 `replay` 的 proof capsule；
> 换客户只换 YAML，内核不动，地址不存在于任何静态文件里。

代号 **VeriPen**（verify + pentest）。产品定位一句话：
**「可审计、可复现、可离线部署的渗透验证内核」** —— 不是扫描器，是验证器。

## 1. 为什么是这个选题

用户要的三件事是同一件事：

| 需求 | 工程约束 |
|---|---|
| 适用于所有大型企业 | 换客户**只改配置不改代码**；**连地址也不进代码** |
| 兼容本地化/内网 | 全容器 + 离线镜像包 + 本地模型 + 零外网依赖 |
| 当前企业只是第一步 | 内核与客户解耦，**第一家客户的信息（含其路由地图）不进内核** |

所以项目要证明的不是"会打洞"，而是**"这套东西能卖第二家"**。
而"通用"无法演示——除非用两条命令打同一份二进制。

## 2. 十二条可演示断言（项目的真正交付物）

| # | 断言 | 命令 | 证明 |
|---|---|---|---|
| A1 | 能卖第二家 | `make demo` / `make demo-alt` | 同镜像、只换 profile，跑通两个客户形态 |
| A2 | 差异没漏进代码 | `make lint-noleak` | `core/` grep 客户标识为空 |
| A3 | 内网能装 | `make package-offline` + `make doctor` | `docker load` 即跑；缺什么当场报 |
| A4 | 不是"我说有洞" | `make replay ID=n` | 独立复现 + 七态（含两种路由态） |
| A5 | 有数 | `make bench` | 44 例 × 3 轮，TP/FP/耗时/成本 |
| A6 | 覆盖够宽 | `make coverage-matrix` | 14 类 × 资产 + 标签 × oracle，空格必须有原因 |
| A7 | 接口能自动覆盖 | `make cases CASES=contract` | 40 op → 200 绑定，`routeset_sha256` 字节稳定 |
| A8 | 模型不是瓶颈 | `make bench MODEL=none` | 无模型（确定性策略）仍跑完，判定不变 |
| **A9** | **地址不存在于代码** | **`make lint-noroute`** | **全仓 0 处路径/URL/host/端口字面量；重试用重发现；找不到面就 BLOCKED** |
| **A12** | **能读写能执行（v3.5）** | **`make bench-workbench`** | **`fs.*` 五工具 + `shell.run`（python/bash）跑通；脚本内地址字面量静态即拒；容器内直连失败、走代理成功；`plan` 模式零副作用** |
| **A11** | **能力可扩展（v3.4）** | **`make plugin-check`** | **能从 GitHub 搜到并装 knowledge/act 类插件；oracle 类必过 44 例；插件不能直连目标；一次刷新上游请求 ≤2** |
| **A10** | **能打的同时能证明（v3.3）** | **`make bench-leads`** | **自主动作（`act.*`）可自由跑工具；每条线索强制闭环（`pending_leads==0` 才 DONE）；报告线索与 finding 分开列；闭环率 ≥0.6** |

> 面试/答辩时只讲这十二条，其余都是它们的展开。
>
> **A9 是 v3 的核心**。前八条证明"这套东西好用"，A9 证明"这套东西不会腐化"。
> 没有 A9，前八条随时可能在一次"顺手"里全部失效——因为硬编码一个路径能让八个断言同时变绿。

## 3. 边界（冻结，禁止扩张）

```
靶场   真实开源靶场（DVWA / juice-shop / OWASP crAPI / vAmPI / WebGoat）
       + tsp-lab 适配层（真实数据快照 + 真实契约 + 故意缺陷）；不打任何外网
       —— 靶场只发布契约与语义标签，不发布端点（25 §2）
漏洞   14 类（A 档 6 / B 档 5 / C 档 3），目录见 18；默认启用 9 类，4 类需授权
客户档 2 个：demo-a（通用企业 SaaS 形态）、demo-b（车云 API 形态）；零地址、零明文凭据
规模   1 API + 3 worker + Redis + SQLite→PG + 只读控制台，docker compose 一键起
代码   9,000–13,000 行（含测试；比 v2 多约 1,000 行，是路由层）
不做   内网 AD / C2 / 车机多模态 / 白盒全量 / 模型微调 / 交互式工具（msf、sliver）/
       多租户 / K8s / SAML 全自动化 / 路径爆破找洞
新需求 一律进 docs/99-二期池，不进本期代码
```

**扩范围的代价换算（对外统一口径）**：加一类 oracle = 半天（agent 辅助 1–2 小时 + 用例 + 负样本）；
加一个客户档 = 半天；加一种报告框架 = 2 小时（纯 YAML 映射）；
**加一个路由来源（如新的契约格式）= 半天**（新增 `routes/sources/*.py`，不改内核）。

## 4. 成功标准（七条，不达标不加时间，只砍批次）

1. 冷机器 `make up && make demo` 一次成功，无手工步骤
2. `make demo-alt` 同镜像只换 YAML 跑通第二份客户档，`core/` diff 为空
3. 报告每条发现可 `replay`；缺 capsule 的发现不进报告
4. 缩小 scope 后 agent 必须**拒绝退出**，不允许"尽力而为"
5. 14 类 oracle 覆盖矩阵无空格，有空格必须写明原因（未授权 / 无标签命中 / 不适用）
6. `make bench MODEL=none` 与真实模型跑的判定完全一致（证明判定与模型解耦）
7. **`make lint-noroute` 0 命中，且删掉一条绑定后系统重发现而不是报错**（证明地址与代码解耦）

|---|---|---|---|---|

| **W3.7 能打能证** | **B12.6–B12.8** | `act.*` 自由动作 + 容器沙箱、线索闭环、操作台 L0/L1 | **A10**：能跑白名单工具 + 每条线索闭环 + 线索与 finding 分列 | 沙箱起不来 → 先只做 `http_raw`/`http_fuzz`，`exec_tool` 延后 |
| **W3.8 能力市场** | **B12.10–B12.13** | 插件发现/注册/装配/UI，兼容 npx·pip·MCP | **A11**：搜到并装 knowledge/act；oracle 门禁生效；插件不能直连目标；刷新请求 ≤2 | 沙箱未就绪 → 先只开放 knowledge 与 raw 适配器 |
| **W3.9 通用工作台** | **B12.14–B12.16** | `fs.*`/`code.search`、`shell.run`+代理、`plan`/`todo` | **A12**：能读写能执行，且脚本内地址静态即拒、容器直连失败 | 代理做不通 → **先只做 `fs.*`（B12.14）**，`shell.run` 必须等代理 |
| **W4 平台化** | B14–B17 | Tier C 3 类 + 只读控制台 + demo-b 档 + 交付物料 | A1/A2/A6/A7 + 演示一次过 | 模型超时 → `make demo-offline` 预录兜底 |

**冷启动门的理由**：compose 一上来拼 5 个服务 + 3 worker，任何一环坏了都看不到"能跑"的样子。
W1 的验收不是"服务起来了"，而是**最小端到端路径跑通**——壳子先立，再往里长。

**为什么 B1.5 在 B2 之前**：`guard` 的四处校验与 `capsule` 的 `route` 块都依赖路由层类型。
先写 oracle 再补路由 = 14 个 oracle 全部返工。这是 v3 从 v2 学到的最贵的一课。

**为什么是 30 批而不是 1 次全给**：agent 写 9,000 行只要几小时，但一次产出无法定位失败，
回滚范围是整个仓库。分批的收益不是"写得快"，是**每批都有可回滚边界**。

## 9. 术语表（全文统一，不许换词）

| 词 | 含义 |
|---|---|
| 客户档 / profile | `profiles/<name>/*.yaml`，唯一允许出现客户差异的地方（**但不含地址**） |
| 内核 / core | `veripen_core`，禁止出现任何客户标识、**禁止出现任何地址** |
| **RouteRef** | 路由的不透明身份，`route://<source>/<opaque16>`，不含路径字符 |
| **RouteBinding** | 解析后的可执行绑定（method/template/schema/auth/来源/置信/TTL），只存内存与 capsule |
| **RouteSet** | 一次 discovery 的不可变结果集，`routeset_sha256` 内容寻址 |
| **route_discovery / resolve_routes** | 唯一能产出 `RouteBinding` 的函数/技能 |
| **selector / 语义标签** | profile 的 `routes.selectors` 与 `18 §6` 标签字典：说"打哪一类"，不说"打哪个地址" |
| **重发现 / rediscovery** | 路由类失败后的唯一正确反应；受 `max_rediscovery` 配额约束 |
| oracle | 确定性验证器插件，输入请求对、输出 verdict |
| capsule | 一次验证的证据包，可独立 replay |
| finding | 一条发现，引用 capsule |
| verdict | `VERIFIED / REFUTED / INCONCLUSIVE / BLOCKED` |
| replay 态 | `REPLAYED_OK / PARTIAL / ASSERTION_NOT_REPRODUCED / BLOCKED / ROUTE_UNRESOLVED / ROUTE_DRIFT` |
| impact class | `read_only / reversible_write` |
| 断言 A1–A12 | 第 2 节的十二条可演示断言 |
| 批次 / batch | `21` 定义的 18 个可独立验收单元（B1, B1.5, B2–B17） |
| 波 / wave | 4 个批次组（W1 内核 / W2 能力 / W3 工程 / W4 平台） |
| lane | 可并行的工作流（L-CORE / L-ORACLE / L-SURFACE） |
| **N1–N6** | `27 §2` 的六条不变量，A9 的可执行形式 |
