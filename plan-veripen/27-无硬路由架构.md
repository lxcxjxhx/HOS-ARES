# 27 · 无硬路由架构（Route Resolution Layer）

> 本文是 v3 的**架构冻结文档**，优先级高于 `01` 的 §3.1 与 `07` 的变体写法。
> 一句话：**系统里不存在"路径"这个概念，只存在"被解析出来的绑定"。**
>
> 为什么单独立一章：v2 的硬路由不是笔误，是**三个思维习惯**的产物（见 §0.2）。
> 不把这三个习惯换成结构，下一版还会长回来。

## 0. 一、根因与判据

### 0.1 判据（唯一）

> 任何一行代码、任何一份配置、任何一段提示词，如果它**能被打包成一次 HTTP 请求**，
> 那它的目标只能来自 `route_discovery` 的返回值。否则违规。

### 0.2 根因（上一版为什么会长出硬路由）

| # | 习惯 | v2 里的表现 | 结构替代 |
|---|---|---|---|
| C1 | 把"示例"当契约 | `02` 的 `resource_paths: ["/api/..."]`、`06` 的 capsule 样例 URL | 示例里只许出现 `ROUTE_REF`，不许出现可运行的字面量 |
| C2 | 把"夹具"当常量 | `11` 用例表直接写 `?id=`、`?next=`、`?file=` | 用例只描述**能力**（tag / 参数形状 / 期望对照），路径在运行时解析 |
| C3 | 把"靶场端点"当知识 | `25` 的 V1–V10 端点表、healthcheck 探活路径 | 靶场只发布**契约 + 语义标签**，端点由契约解析得到 |

**结论**：硬路由的敌人不是"记不住规则"，是"示例太好写"。所以本章的每条不变量都必须是**机器能抓的**，不能是"请注意不要"。

## 1. 术语与类型（全文统一，不许换词）

| 词 | 定义 | 允许出现的形态 |
|---|---|---|
| `RouteRef` | 路由的**身份**，不含任何路径字符 | `route://contract/7f3a…`、`route://observed/b21c…`（`<source>/<opaque16>`） |
| `RouteSet` | 一次 discovery 的不可变结果集，内容寻址 | `routeset_sha256` 进 capsule 与 bench |
| `RouteBinding` | `RouteRef` 解析后的**可执行绑定**：method / path template / 参数 schema / 认证句柄 id / 来源 / 置信度 / TTL | 只存在于内存与 capsule，**不是配置项** |
| `RouteProvenance` | 绑定从哪来：`contract` \| `observed` \| `crawl` \| `probe` \| `operator` | 必填，结论级字段 |
| `confidence` | 规则算出（来源等级 + 佐证数），不让模型给 | 0.0–1.0，四档见 §3.3 |
| `route_discovery` / `resolve_routes` | **唯一**能产出 `RouteBinding` 的函数（CLI/技能同名） | 见 §3 |

**类型铁律（N1 的可执行形式）**

```python
RouteRef   = NewType("RouteRef", str)      # 只能由 routes.resolver 构造
RouteText  = NewType("RouteText", str)     # 路径/URL 文本，构造函数不导出
# tools.http 的签名只接受 RouteBinding，不接受 str
def send(binding: RouteBinding, params: dict, auth: AuthHandle) -> HttpTrace: ...
```

`RouteText.__new__` 不在包内导出 → 核心包内**没有语法路径**可以拼出一个 URL；要拼必须走 resolver，而 resolver 的所有字符串都来自来源适配器（§3.3）。

## 2. 六个不变量（每条都有机械检查）

### 2.1 N1 的完整形态（为什么必须两层）

单靠 lint（N3）挡不住，因为绕过方式不是写字符串，而是**从数据里读**：

```python
# 这个写法 lint 一个都抓不到
base = profile.meta.some_field        # 数据里有个看起来无害的值
send_raw(base + suffix)               # 拼出来就是一个地址
```

所以 N1 把"发送能力"和"地址文本"分成两个类型，且**只有 resolver 能造后者的实例**：

```python
# veripen_core/routes/types.py
RouteRef  = NewType("RouteRef", str)     # 导出；只能由 resolver 构造
RouteText = NewType("RouteText", str)    # 不导出（无 __all__ 条目，私有 _RouteText）

# veripen_core/tools/http.py
def send(binding: RouteBinding, params: dict[str, str], auth: AuthHandle) -> HttpTrace:
    ...                                   # 唯一签名；没有 send(str) 重载
```

| 层 | 拦什么 | 拦不住什么 |
|---|---|---|
| 类型（N1） | 任何人手写 `send("...")` | 用 `cast()` 强行转换 |
| AST（N2） | 在非 resolver 模块构造 `RouteBinding` | 反射/`__getattr__` |
| lint（N3） | 字面量 | 从数据拼装 |
| 运行时 bench（N6） | **渲染结果推不出绑定** | — |

**四层里只有 N6 是运行时验证**，前三个都是静态的。静态查不出的东西，必须有一层运行时的。
这也是为什么 `10 §3.0` 的"渲染结果必须能由 routeset 推出"不是锦上添花，是 N1 的兜底。

## 3. `route_discovery` 规格

### 3.1 输入（`RouteQuery`，全部是"约束"不是"地址"）

```python
@dataclass(frozen=True)
class RouteQuery:
    asset: AssetRef                  # 不透明句柄，值来自 profile 的 asset 注册
    hints: RouteHints                # 见下
    auth: AuthHandle | None          # 需要鉴权的探测才带
    budget: DiscoveryBudget          # 请求数/时长/并发上限
    prior: RoutesetRef | None        # 上一次结果（用于增量刷新）
    reason: DiscoveryReason          # INIT | STALE | NOT_FOUND | DRIFT | OPERATOR
```

`RouteHints` 只允许四类提示，**都不含路径**：

| 提示 | 例 | 用途 |
|---|---|---|
| `semantic_tag` | `object_read`、`admin_function`、`url_fetch`、`file_read`、`token_issue` | 选候选，不选地址 |
| `param_shape` | `{kind:int, name_hint:*id*}`、`{kind:url, name_hint:*url\|uri\|target*}` | 打分 |
| `response_shape` | `{ct:json, has_field:*id*}` | 打分与验证 |
| `auth_requirement` | `none \| primary \| secondary \| mtls` | 过滤 |

### 3.2 五个来源（优先级从高到低，全部是接口，不在这里写死任何具体地址）

| 源 | 输入从哪来 | 产出 | base_confidence |
|---|---|---|---|
| `contract` | 资产自述的机器可读契约（OpenAPI / GraphQL SDL / proto / 自定义 schema），**契约的获取位置本身也是 `RouteRef`**（见 §3.8） | 完整 op 表 + 参数 schema | 0.90 |
| `observed` | 已有流量证据：capsule、录制夹具、HAR、代理会话 | 真实发生过的请求 | 1.00 |
| `crawl` | 从已知入口可达的链接/清单（入口由 `contract`/`operator` 提供；**只读 HTML，不跑 JS**） | 可达面 | 0.70 |
| `probe` | 从配置来的**词表**做受控探测（受全局限流与资产并发约束，挂 `discovery_probe` 门） | 存在性 | 0.50 |
| `operator` | 客户/操作者在 `bindings` 里显式登记 | 直接可用 | 0.95 |

> `probe` 的词表是**配置数据**，不是代码常量；词表为空时 `probe` 源直接不参与，
> 系统降级为"仅契约+观测"，**不报错、不猜路径**。

### 3.3 置信度：由规则算出，不许赋值

**`N6 §` 硬约束**：`confidence` 是**函数返回值**，任何地方出现 `confidence = 0.9` 这类字面赋值都是违规（`tests/routes` 有一条 AST 检查）。

```
confidence = base_confidence(source)                  # 见 §3.2 表
           + 0.05 × (len(sources_all) - 1)            # 多源佐证，每个额外来源 +0.05
           + 0.05 × min(verifications, 2)             # 实测确认次数（每次成功探测/观测 +0.05，上限 2 次）
           - 0.10 × param_ambiguity                   # 参数形状与 selector 的偏离度（0/1/2 档）
clamp(0.0, 1.0)
```

| 项 | 取值 | 为什么这样算 |
|---|---|---|
| `base_confidence` | 见 §3.2 | 来源本身就是最强的信号 |
| `sources_all` | 去重后的来源集合 | 契约+观测同时命中，比单独契约可信 |
| `verifications` | 成功发出并收到**预期形状**响应的次数 | 只有"真的通"才算佐证，不数"看起来像" |
| `param_ambiguity` | 参数类型不符=1，参数名完全不匹配=2，否则 0 | 形状偏离越多越可疑 |

**设计取舍**：不做加权平均，做**加性修正 + 夹取**。
理由：加权平均会让一个 0.50 的 probe 命中拉低一个 0.90 的 contract（明明两者说的是同一条），
而加性修正确保"多一个佐证只会更可信"，符合直觉也符合审计。

**分档门槛（用于"能不能发请求"）**

| 档 | confidence | 可否用于判定 | 报告最高严重度 |
|---|---|---|---|
| `observed` 级 | ≥ 0.95 | ✅ 直接判定 | critical |
| `contract` 级 | 0.85–0.95 | ✅ 直接判定 | critical |
| `crawl` 级 | 0.65–0.85 | ⚠️ 仅基线探测；出判定需一次 `observed` 佐证 | medium |
| `probe` 级 | 0.45–0.65 | ⚠️ 仅探测；连续 2 次一致才升到 crawl 级 | low |
| `inferred` | < 0.45 | ❌ **禁止发请求**（只用于排序） | — |

> 这张表与 `09 §3.1` 是同一套数字的两个用法：这里管"能不能打"，那里管"能说多重的活"。
> 两处必须同步改——所以数字只在本文定义，`09` 引用它。

### 3.4 合并：`structural_key` 的完整定义

v3 草案里的 `sha256(method|template|param_name_set)` **漏了两个维度**，会导致两类真实碰撞：

| 漏掉的维度 | 碰撞后果 | 严重度 |
|---|---|---|
| `auth_requirement` | 同一模板的"登录后可见"与"管理员可见"被合并 → 低权结论套到高权面上 | **高（会直接制造 FP）** |
| `body_shape_sha256` | 同 method+path 但 body schema 不同（如 PATCH 与 PUT 语义不同）被合并 | 中 |

**最终定义（冻结）**

```python
structural_key = sha256(
    method
  | normalized_template        # 参数段归一为 {param}，末尾斜杠归一，大小写归一（path 区分大小写？见下）
  | sorted(param_name_set)
  | auth_requirement           # ★ 新增
  | body_shape_sha256          # ★ 新增（无 body 用常量 "nobody"）
)
```

**路径大小写**：按 RFC 3986，path **区分**大小写。
所以 `normalized_template` **不**做大小写归一——只做三件事：参数段归一、末尾斜杠归一、百分号编码归一。
（v3 草案写"大小写归一"是错误的，会把 `/api/User` 与 `/api/user` 合并成一条。）

**合并算法（保证确定性）**

```
groups = group_by(structural_key, candidates)
for key, group in groups:                      # 按 key 排序遍历，不依赖输入顺序
    winner = max(group, key=lambda c: (confidence(c), -source_rank(c), c.template_sha256))
    winner.ref = f"route://{winner.source}/{opaque16(structural_key)}"   # ← ref 由 key 派生
    winner.sources_all = sorted({c.source for c in group})
    winner.verifications = max(c.verifications for c in group)
    winner.confidence = recompute(winner)      # 依 §3.3 重算，不是取 max
```

| 关键点 | 为什么 |
|---|---|
| `ref` 由 `structural_key` 派生 | 同一条面在不同来源/不同轮次里**拿到同一个 ref**；这是 replay 能对上号的根 |
| `ref` 是 `opaque16` 而不是完整 hash | ref 会进报告；截断到 16 hex 既够唯一（64 bit）又不冗长 |
| `winner` 用三元组排序而非 `max(confidence)` | 同分时行为必须确定（`-source_rank` 让 contract 优先于 probe） |
| `confidence` 重算而非取 max | 多源佐证应当加分，取 max 等于忽略了佐证 |
| `sources_all` 排序 | 进 canonical JSON，顺序必须稳定（否则 `routeset_sha256` 抖） |

### 3.5 歧义裁决：一个 selector 命中多条绑定怎么办

这是最容易"看起来没事、其实在瞎打"的地方。**规则：不裁决，只排序 + 限量。**

| 情形 | 行为 |
|---|---|
| 命中 0 条 | `unresolved: [{selector, reason: no_candidate}]` → 依赖它的 oracle `BLOCKED(route_unresolved)` |
| 命中 1 条 | 直接用 |
| 命中 2–5 条 | 按 §3.6 排序，**全部交给 oracle**，oracle 自己决定遍历还是取样（如 idor 取前 3 条） |
| 命中 > 5 条 | 按 §3.6 排序取前 5，其余记 `truncated` 计数进 `unresolved`（**不静默丢弃**） |

**禁止**：按"看起来最像"选一条。那等于让 resolver 做语义判断，而它只有结构信息——
这正是"猜路径"的现代变体。resolver 只排序，判定权在 oracle，取证权在 capsule。

**为什么允许"全部交给 oracle"**：idor 需要多条（不同对象、不同 id 区间）；
ssrf 只需要一条（第一个 `url_fetch`）。这是**oracle 的领域知识**，不该硬编码在 resolver 里。

### 3.6 排序（唯一的排序规范，全文引用它）

```
sort_key = (
    -confidence,                  # 高置信在前
    source_rank,                  # observed=0, operator=1, contract=2, crawl=3, probe=4
    template_sha256,              # 同分同源时按结构哈希定序（确定性）
)
```

**为什么第三键是 `template_sha256` 而不是 `op_id`**：`op_id` 来自契约的 `operationId`，
客户改个命名就全乱；模板哈希只取决于结构，改命名不影响（`19 §4` 也用它）。

### 3.7 缓存与并发（不写清就会重复解析或被目标打崩）

| 项 | 规格 |
|---|---|
| 缓存键 | `sha256(asset_id | query_hash | profile_hash | resolver_version)` |
| 缓存值 | `RouteSet`（内容寻址，落在 `routesets` 表 + `out/routes/<sha>.json`） |
| TTL | `profile.routes.ttl_s`（默认 900s）；**过期不删，只标记 stale**（审计要能看旧解析） |
| 并发去重 | **single-flight**：同缓存键的并发请求只有一个真跑，其余等待同一 Future |
| 失败缓存 | `ROUTE_UNRESOLVED` 结果缓存 **60s**（短），防止对目标连打；但**不缓存到 TTL** |
| 跨任务复用 | 允许（同一 asset + 同 profile_hash + 未过期）；`oracle run` 的幂等键含 `routeset_sha256`，所以复用的证据天然一致 |
| 进程内并发 | 每个 asset 同时最多 **1 个** discovery（防把目标打崩）；跨 asset 并行度 = `per_asset_concurrency` 的反向：discovery 是轻量的，允许 2 个资产并行 |

**single-flight 为什么是必须的**：3 个 worker 同时启动、同一 asset、同一 profile →
3 次并发解析 → 3 倍请求量 + 可能拿到 3 个不同结果（如果目标在变动）。
这把"确定性"和"不打崩目标"两件事同时破坏。

### 3.8 契约位置本身怎么解析（自举，必须有终止条件）

契约在哪，也是路由问题。这是个**自举**：要解析 A 需要 B，要解析 B 可能又需要 A。

**三级定位，逐级降级，最多 3 跳**

| 级 | 手段 | 终止条件 |
|---|---|---|
| 1 `observed` | 从既有证据里找"曾经取到过契约"的记录（capsule 里 `content-type` 为 schema 类） | 找到即停 |
| 2 `well_known` | 从 `config/bindings/sources.yaml` 的符号取"契约自述位置"（由部署注入，如惯例路径） | 找到即停 |
| 3 `operator` | 操作者在 `bindings` 里显式登记契约位置 | 找到即停 |

**终止铁律**：
- 每一跳的 `route_ref` 必须**互不相同**（防环）；出现重复即 `CONTRACT_LOCATOR_UNRESOLVED` 并记录环。
- 总跳数 > 3 → 停止，返回 `CONTRACT_LOCATOR_UNRESOLVED`。
- 拿到的文档**必须通过"是不是契约"的机械判定**（`19 §2` 的解析器能解析出 ≥1 个 operation），
  否则视为未找到，进入下一级。
- **不允许**"试几个常见位置"——那是 probe 源的事，且必须挂 `discovery_probe` 门（`05 §3`）。

> 这一节存在的理由：v3 草案说"契约位置也是 RouteRef"但没说怎么拿到第一个。
> 没有终止条件的自举 = 无限循环；没有机械判定 = 把 404 页面当契约解析。

### 3.9 失败语义（**这一节替代所有"兜底路径"**）

| 情形 | 返回码 | 分类 | 上层行为 |
|---|---|---|---|
| 所有来源都无结果 | `ROUTE_UNRESOLVED` | ROUTE | `BLOCKED(route_unresolved)`；进"未覆盖"，**不发包** |
| 绑定过期（TTL 到） | `ROUTE_STALE` | ROUTE | 触发 `rediscovery(STALE)`，**复用旧绑定重试是违规** |
| 结构漂移（`template_sha256` 变） | `ROUTE_DRIFT` | ROUTE | 触发 `rediscovery(DRIFT)`；同一 ref 连续 2 次 → 标 `suspect` |
| 有绑定但不在当前 RouteSet | `UNBOUND_ROUTE` | **程序 bug** | `tools.http` 直接抛；不进重试路径 |
| 置信度低于 `min_confidence` | `ROUTE_TOO_WEAK` | 门禁 | `BLOCKED(route_too_weak)`；**不降级、不放宽** |
| 契约自举失败 | `CONTRACT_LOCATOR_UNRESOLVED` | ROUTE | 降级到 crawl/operator；仍无则 `ROUTE_UNRESOLVED` |
| 重发现超配额 | `QUOTA_EXCEEDED` | 门禁 | 停止重发现，剩余标 BLOCKED，`budget_exhausted: rediscovery` |
| 来源适配器内部异常 | `SOURCE_ERROR(source)` | RETRYABLE | 该来源本轮跳过，**其余来源照常合并**；不整体失败 |

**最后一行是重要的韧性设计**：一个来源坏了（比如契约取不到）不应该让整个 discovery 归零。
只要还有别的来源能给出候选，就继续——但**记录 `sources_failed`**，让报告能说"这次只有观测面"。

**禁止事项（写进 lint）**：`fallback_path`、`default_route`、`DEFAULT_ENDPOINT`、`retry_with_literal`、
`if not found: path = ...`。任何形如"找不到就用 X"的代码即违规，一律重写。

## 4. 重试 = 重发现

```
attempt(binding) ──ok──▶ judge
      │
      └─fail(class)──▶ classify(class)
                          ├─ ROUTE_STALE / 404 / 405 / 410 / 重定向到未知 / schema 漂移
                          │     → resolve_routes(RouteQuery(reason=STALE|DRIFT, prior=routeset))
                          │     → 新 binding 再 attempt（**不重放旧绑定**）
                          ├─ 网络抖动 / 429 / 5xx（且基线也 5xx）
                          │     → 退避重试**同一 binding**（这是允许的：绑定没失效）
                          └─ 触达 max_rediscovery 或 无候选
                                → BLOCKED(route_unresolved) 或 NEEDS_HUMAN
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `max_rediscovery` | 3 / 任务 | 超过即 `BLOCKED`，不无限重试（也防把目标打挂） |
| `rediscovery_cooldown` | 2s 起，指数 ×2 | 与 `04 §5` 的令牌桶共用预算 |
| 重发现是否计数 | **是**，计入 `steps` 与 `requests` | 防止"用重发现绕过预算" |
| 同一 `RouteRef` 连续 2 次 `STALE` | 该 ref 降级为 `suspect`，不再自动使用 | 进报告"未覆盖" |

**为什么网络抖动允许复用绑定**：绑定失效是**路由语义**问题，网络抖动是**传输**问题。
把两者混成一个"重试"分支，就是上一版会写死路径的心理起点。

### 4.1 参考实现伪码（B1.5 照这个写，不要自由发挥）

```python
# veripen_core/routes/resolver.py   —— 全仓唯一构造 RouteBinding 的地方（N2）
def resolve_routes(q: RouteQuery) -> RouteSet:
    # 0 单飞：同缓存键并发只有一个真跑（§3.7）
    key = cache_key(q)
    return single_flight(key, lambda: _resolve_uncached(q))

def _resolve_uncached(q: RouteQuery) -> RouteSet:
    # 1 缓存命中且未过期
    hit = cache.get(key_of(q))
    if hit and not hit.expired(now=clock.now()) and q.reason is DiscoveryReason.INIT:
        return hit

    # 2 逐源采集。任一来源失败只跳过它，不整体失败（§3.9 SOURCE_ERROR）
    candidates, failed = [], []
    for src in ordered_sources(q.hints):          # 按 profile.routes.sources 顺序
        try:
            candidates += src.collect(q)          # 各源返回 RouteCandidate（无地址文本外泄）
        except SourceError as e:
            failed.append(src.name)               # 记录但不中断
    if not candidates:
        rs = empty_routeset(q, failed=failed, reason=ROUTE_UNRESOLVED)
        cache.put_short(rs, ttl_s=60)             # 失败缓存 60s，防止对目标连打
        return rs

    # 3 合并（§3.4）：按 structural_key 分组，组内选 winner，confidence 重算
    merged = merge_by_structural_key(candidates)

    # 4 过滤低于门槛的（§3.3）——注意：不是删除，是标不可用
    for b in merged:
        b.usable = b.confidence >= q.min_confidence

    # 5 排序（§3.6）——唯一排序规范
    merged.sort(key=lambda b: (-b.confidence, source_rank(b.source), b.template_sha256))

    # 6 定 ref（由 structural_key 派生，保证跨轮次同一面拿到同一 ref）
    for b in merged:
        b.ref = f"route://{b.source}/{opaque16(b.structural_key)}"

    # 7 组装 + 内容寻址
    rs = RouteSet(
        resolver_version=RESOLVER_VERSION,       # 常量，进 capsule，用于三年后重算
        asset_id=q.asset.id,
        query_hash=sha256(canonical_json(q)),
        created_at=clock.now(),
        expires_at=clock.now() + q.ttl_s,
        sources_used=sorted({b.source for b in merged}),
        sources_failed=failed,                   # ← 报告要能说"这次只有观测面"
        unresolved=collect_unresolved(q, merged),# ← 0 命中 / 超 5 条被截断，都要记
        bindings=merged,
    )
    rs.routeset_sha256 = sha256(canonical_json(rs.without_sha()))   # N6 的锚
    cache.put(rs)
    return rs
```

**这段伪码里有四个"不许改"的位置**（改任何一个都会破坏不变量）：

| 位置 | 不许改成 | 为什么 |
|---|---|---|
| `except SourceError` 只跳过不中断 | `raise` 整体失败 | 一个来源坏掉不该让 discovery 归零（§3.9） |
| `if not candidates: return empty` | 用默认绑定兜底 | **这就是 hardroute** |
| `b.usable = ...` 只标不删 | `merged = [b for b in merged if ...]` | 删掉就无法解释"为什么没打这个面" |
| `ref = opaque16(structural_key)` | `uuid4()` | ref 必须跨轮次稳定，否则 replay 对不上 |

### 4.2 来源适配器接口（新增来源只实现这四个方法）

```python
class RouteSource(Protocol):
    name: Literal["contract", "observed", "crawl", "probe", "operator"]
    rank: int                       # 排序用；observed=0 … probe=4

    def available(self, q: RouteQuery) -> bool:
        """本环境是否具备该来源的条件（如 probe 词表为空 → False，不报错）。"""

    def collect(self, q: RouteQuery) -> list[RouteCandidate]:
        """返回候选。**不得**返回已渲染地址；只返回结构（method/template/params/auth）。"""

    def verify(self, cand: RouteCandidate, q: RouteQuery) -> bool:
        """可选：是否真的可达/形状相符。用于增 confidence 的 verifications 计数。"""
```

**接口的三条铁律**

1. `collect()` 的返回值里**没有** `url`/`full_path` 字段——只有 `template`（含 `{param}` 占位）。
   渲染发生在 `tools.http.send()`，不在来源层。
2. `available()` 返回 False 是**正常降级**，不是错误。它让"没有词表"与"词表坏了"可区分。
3. `verify()` 内部如需发请求，必须走 `tools.http`（受令牌桶、scope 四处校验、post_connect 复核）；
   **来源层不得自建 HTTP 客户端**（`tests/routes` 有一条 import 检查）。

> 第三条经常被违反：写 probe 源的人会本能地 `import requests` 去"试一下"。
> 那一瞬间，route_discovery 就绕过了整个安全边界。

## 5. 与判定、证据的耦合

### 5.1 Oracle 只能看到绑定

```python
class Oracle(Protocol):
    def plan(self, ctx: TargetContext, base: RouteBinding) -> list[RouteCall]: ...
    def judge(self, pairs: list[RequestPair]) -> Judgement: ...   # 纯函数，不变
```

`RouteCall = (route_ref, method_override?, params, role)`。
`plan()` 的返回值里**没有 URL 字段**——类型上就写不出来。

### 5.2 capsule 新增 `route` 块（`capsule_version: 1.1`）

```json
"route": {
  "routeset_sha256": "sha256:…",
  "ref": "route://contract/7f3a…",
  "source": "contract",
  "sources_all": ["contract", "observed"],
  "confidence": 0.90,
  "template_sha256": "sha256:…",
  "resolver_version": "1.0.0",
  "resolved_at": "2026-11-01T02:13:58Z",
  "ttl_s": 900,
  "discovery_evidence_ids": ["ev_…"]
}
```

要求：
- **不存明文模板**在报告正文（模板进 capsule，报告只给 `ref` 前 8 位 + 来源）。
- 与 `steps[*].request` 的关系：`steps` 存的是**实际发出的那一次**（用于 replay），`route` 存的是**它从哪解析来的**（用于可信度）。二者缺一不可。

### 5.3 replay 新增两态（`06` 的四态扩为六态）

| 状态 | 含义 |
|---|---|
| `REPLAY_ROUTE_UNRESOLVED` | 当前环境下该 `RouteRef` 已无法解析（端点下线/契约变更）→ **不是失败**，是"环境不再持有该面" |
| `REPLAY_ROUTE_DRIFT` | 解析到了不同模板（`template_sha256` 变）→ 需人工确认后再判 |

这两态让 replay 在"目标改版"时给出**准确**结论，而不是笼统的"未复现"。

## 6. 我们自己的服务也不写死

内部 API 同样走 op 表，理由一致：一旦服务端路由写进代码，改版就是全仓 grep。

| 层 | 形态 |
|---|---|
| 契约 | `op_id` 符号表：`OP.TASK.SUBMIT`、`OP.FINDINGS.GET`、`OP.CAPSULE.REPLAY`（见 `24`） |
| 绑定 | `config/bindings/service.yaml`：`op_id → transport`（transport 由部署配置给出，代码内无默认值） |
| 调用 | `client.call(OP.TASK.SUBMIT, payload)`；直接构造 transport 的 API 不导出 |
| 控制台/MCP | 同样以 `op_id` 暴露；MCP 的 tool name = `op_id` 的小写点号形式 |

**收益**：改服务端路由 = 改一份 binding；改客户端 = 零改动。

**`lint-noroute` 的规则表**（误报靠 allowlist 解决，不靠放宽规则）

| 规则 | 匹配 | 内建放行（不需要 allowlist） |
|---|---|---|
| `R-PATH` | 引号内以 `/` 开头的字面量 | `/dev/null`、`/tmp`、`/<尖括号占位>` |
| `R-URL` | `scheme://` | `route://` `vault://` `op://`（**我们自己的不透明引用**）、`file:///`（载荷）、`*.invalid`（RFC 2606 保留域）、`json-schema.org` / `w3.org` / `openapis.org` / `sarif` 等标识符 |
| `R-HOST` | `localhost` / `127.0.0.1` / `0.0.0.0` / `*.local` / `*.internal` / `*.svc` / `*.cluster.local` | `*.invalid` |
| `R-PORT` | `port=<数字>` / `:<数字>/tcp|udp` | 无 |
| `R-VERB` | `"GET /…"` 形式的字符串 | 无（**仅扫代码/配置，不扫散文**） |
| `R-DEFAULT` | `fallback_path` / `default_route` / `retry_with_literal` / `DEFAULT_ENDPOINT` / `DEFAULT_PATH` | 无（同上：仅扫代码/配置） |

**两条扫描范围的设计（实测必要）**

| 规则类 | 扫描范围 | 为什么 |
|---|---|---|
| `R-PATH` / `R-URL` / `R-HOST` / `R-PORT` | **全部文件**（含 `.md`） | 文档里的路径会被复制进代码，必须一样管 |
| `R-VERB` / `R-DEFAULT` | **仅代码/配置**（`.py/.ts/.js/.json/.yaml/.sql/.sh/...`） | 文档必须能写出"禁例长什么样"才能把规则讲清楚 |

另外两份文件整体豁免：`27-无硬路由架构.md` 与 `28-逆向对标与借鉴规格.md`——
**它们是规则的定义文档**，必须引用反例。豁免是写死文件名的，新增豁免要改代码（等于强制 review）。

allowlist 是**行级 + 理由**的：

```
# noroute.allowlist   每行：<正则> <TAB> <理由>
^\s*"\$schema": "https://json-schema.org/  → JSON Schema 标识符，非路由
^source_ref:                               → 公开数据集溯源符号，非路由
```

**不许多于 6 行**。超过说明有真路由混进来了，先修代码再谈加白。

**闸门已实测（不是"应该能抓"）**

| 输入 | 期望 | 实测 |
|---|---|---|
| 一个含 URL + 路径 + 端口的 `.py` | 3 条规则各命中 | ✅ 4 处命中，exit 1 |
| allowlist 加 1 行（带理由） | 该行豁免，其余仍报 | ✅ 剩 2 处，exit 1 |
| allowlist 7 行 | 拒绝运行 | ✅ exit 2 + "先修代码"提示 |
| allowlist 某行缺理由 | 拒绝运行 | ✅ exit 2 + 指出该行 |
| 本规划包自身 | 0 命中 | ✅ 0 命中（37 文件） |

**这五行是本节的全部价值**：一个从没被违反过的闸门，等于没有闸门。
所以 `make lint-noroute` 的验收要求里有一条是"用 bad fixture 证明它真的会红"（`11 §2`）。

## 8. 反例库（"看起来没问题、其实违规"）

| 反例 | 为什么违规 | 正确写法 |
|---|---|---|
| `if resp.status == 404: path = path + "/index"` | 把猜测写成代码 | `resolve_routes(reason=NOT_FOUND)` |
| `DEFAULT = "…/api"` 放在常量模块 | 常量也是字面量 | 走 `config/bindings`；无常量 |
| 单测里 `httpx.get("http://…/x")` | 测试是代码 | 用录制的 `RouteSet` 夹具 + `RouteQuery` |
| 提示词里写"通常管理接口在 …" | 模型会照抄 | 提示词只说"用 `resolve_routes` 找 `admin_function` 标签" |
| `fixture.yaml` 里存完整 URL | 夹具是配置 | 存 `RouteQuery` + 期望 `semantic_tag`；URL 在录制时由 resolver 产生 |
| "兜底：先用 profile 给的路径" | 就是把硬路由合法化 | 没有兜底；解析不到 = `ROUTE_UNRESOLVED` |
