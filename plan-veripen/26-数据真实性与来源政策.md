# 26 · 数据真实性与来源政策（禁用 mock）

> **硬规则：全项目禁止 mock / stub / fake / dummy / 手写假数据。**
> 原因：假数据会让"能跑通"和"真能用"变成两件事——靶场是假的时候，bench 的每个数字都不成立，
> 交付到客户现场才发现接口形状、字段语义、数据分布全对不上，这是最贵的一种失败。
>
> 允许且只允许三种真实来源。本章定义它们、它们的证据、以及怎么机械检查。

## 1. 禁用词与禁用形态

| 禁用 | 例 | 为什么 |
|---|---|---|
| `mock` / `stub` / `fake` / `dummy` | `mock_client.py`、`fake_user.json` | 命名即心态：一旦允许叫 mock，就会开始编数据 |
| 硬编码小样本 | 代码里写死 3 条用户/2 台车 | 只能验证"能跑"，验证不了分布、分页、边界 |
| 手写响应体当夹具 | `{"id":1,"name":"test"}` 直接塞进测试 | 字段名/类型/嵌套常与真实接口不符，判定逻辑被"喂"成错的 |
| 只在前端挡的假后端 | 返回固定 JSON 的 `/api/*` | 让"越权测试"变成测空气 |
| 随机生成但不固定种子 | `random.choice(...)` 造数据 | 不可复现，bench 无法对比 |

**替代原则**：要"可控"，用**固定种子 + 快照 + 校验和**，不用"编数据"。

## 2. 允许的三种来源

### 来源 A · 真实开源靶场（首选）

真实代码、真实框架、真实漏洞（设计如此），有社区维护与版本号。

| 靶场 | 域 | 为什么选它 |
|---|---|---|
| `dvwa` | PHP 经典注入 | 布尔/报错注入的稳定基准 |
| `juice-shop` | 现代 SPA + REST | IDOR / JWT / 存储型 XSS |
| `OWASP crAPI` | **车辆售后服务域**（社区/工单/技师） | 与车云业务形状最接近的真实开源项目 |
| `vAmPI` | 精简 REST（用户/资源） | 批量赋值、BOLA 的最小真实样本 |
| `WebGoat` | 教学型多漏洞 | 补充认证与会话类 |

**规则**：镜像用 digest 锁定；**不自建"假靶场"**，自建只允许"适配层"（见来源 C）。

### 来源 B · 公开数据集 / 公开 API 的离线快照

用于给适配层喂**真实形状的数据**。

| 数据 | 来源 | 许可 | 用途 |
|---|---|---|---|
| VIN 解码 | NHTSA vPIC（公开 API + bulk CSV） | 美国政府公开数据 | 车辆实体、VIN 校验位 |
| VIN 结构规则 | ISO 3779（公开规则） | 规范知识 | 生成**校验位合法**的 VIN（不是随便编） |
| 遥测/OBD 样本 | 公开数据集（Kaggle/HuggingFace 上许可明确者） | 按数据集许可 | 时序数据、里程、电量 |
| 充电会话 | 公开城市开放数据（如充电桩使用记录） | 开放数据许可 | 订单/会话实体 |

**强制要求**：每份数据必须有 `data/real/<name>/manifest.json`：

```json
{
  "name": "nhtsa-vpic-vin",
  "source_url": "https://vpic.nhtsa.dot.gov/api/",
  "retrieved_at": "2026-10-29T12:00:00Z",
  "license": "public-domain-us-gov",
  "sha256": "…",
  "rows": 12840,
  "fields": ["vin", "make", "model", "year", "plant_country"],
  "distribution": {"year_min": 1980, "year_max": 2026, "makes_top5": ["…"]},
  "transform": "scripts/data/build_vin_snapshot.py",
  "pii": false
}
```

`make data-verify` 校验：sha256 对得上、行数对得上、字段齐全、`pii: false`（否则必须脱敏后重新快照）。

### 来源 C · LLM 生成的拟真数据集（仅当 A/B 不可得）

**这不是 mock**：它是一份有 schema、有分布、可复现、经抽检的数据集，和真实数据一样受管。

| 要求 | 做法 |
|---|---|
| Schema 先行 | 先定 `schemas/dataset/<name>.schema.json`，生成结果必须通过校验 |
| 固定种子 | `seed=20261029`，同种子同输出（写入 manifest） |
| 分布断言 | 生成后跑断言：VIN 校验位合法率 100%、时间戳单调、用户-车辆归属比 1:1.2、金额分布符合对数正态 |
| 规模下限 | ≥ 200 行/实体，覆盖边界（0 值、超长字符串、Unicode、极值） |
| 人工抽检 | 随机 20 行人工看一遍，记录在 manifest 的 `reviewed_by` |
| 溯源 | manifest 标 `source: "llm-synthetic"` + 生成脚本 + prompt 版本 |
| **不得伪装真实** | 文件名与 manifest 明确标 synthetic，不许叫 `real_*.json` |

生成脚本：`scripts/data/gen_synthetic.py --schema <name> --rows 500 --seed 20261029`
**它调 LLM 只产出"数据"，不产出"结论"**——判定永远来自 oracle 纯函数。

## 3. 三种来源的使用边界

| 场景 | 允许来源 | 禁止 |
|---|---|---|
| 单元测试（judge） | **录制回放夹具**（从真实靶场录的请求/响应） | 手写响应体 |
| 集成测试（L2） | A（真实靶场） | 任何自建假服务 |
| 端到端（L3） | A + C（适配层喂真实/拟真数据） | 返回固定 JSON 的假后端 |
| 演示 | A + C | 预录假数据当实时结果 |
| bench | A + C（同一份快照，固定种子） | 每次跑换数据 |

### 3.1 录制回放夹具（替代 mock）

```
make record --oracle idor_cross_account --asset juice
  → tests/fixtures/idor_cross_account/<case>.json
     {request, response, recorded_at, target_image_digest, note}
```

- 夹具是**真实流量的快照**，不是手写的。
- 录制时记录靶场镜像 digest；靶场升级后夹具标 `stale`，需重录。
- `judge` 单测只吃夹具，所以离线、秒级、且与真实形状一致。

## 4. 适配层（唯一允许"自建"的东西）

车云形态的真实开源靶场不存在完全对应的项目，所以允许一层**适配层**：

```
真实数据（NHTSA vPIC / 遥测快照 / crAPI 数据模型）
        │
        ▼
tsp-lab 适配层（FastAPI，暴露真实 OpenAPI 契约，按真实数据行返回）
        │  故意保留鉴权缺陷（这是"靶场"的定义，不是"假数据"）
        ▼
被测对象
```

**判据（区分"适配层"与"假后端"）**：

| 维度 | 适配层（允许） | 假后端（禁止） |
|---|---|---|
| 数据来源 | 真实数据集快照或受管拟真集 | 代码里写死的 3 条 |
| 契约 | 真实 OpenAPI（40 op，含分页/错误码/边界） | 只有被测的那两个端点 |
| 行为 | 真实鉴权/限流/序列化，只**故意**留漏洞 | 永远 200 |
| 可验证 | `make range-selftest` 能证明它按契约工作 | 无法证明 |

## 5. 机械检查（写进 CI，不靠自觉）

### 5.1 `make lint-nodata-stub`

```bash
# 命中即失败
grep -rniE '\b(mock|stub|fake|dummy)\b' --include='*.py' --include='*.yaml' --include='*.json' \
  veripen_core veripen_oracles veripen_contract api worker web tests | grep -v 'lint-nodata-stub'
# 硬编码小数组（>=5 行的字面量列表）
python scripts/lint/hardcoded_rows.py --min-rows 5
# 未登记的数据文件
python scripts/lint/data_manifest.py   # data/ 下每个目录必须有 manifest.json 且通过 schema
# 未固定种子的随机
grep -rnE 'random\.(choice|randint|random)\(' --include='*.py' . | grep -v 'seed('
```

### 5.2 白名单（唯一豁免）

| 豁免 | 条件 |
|---|---|
| 变量名含 `mock` | 不允许；改名 |
| 第三方库自带 `mock` 模块 | 只允许 `unittest.mock.patch` 用于**打桩外部网络**（不是造数据），且必须在测试文件内、且被 patch 的对象是网络客户端 |
| 文档里的"禁用词"示例 | 本文件与 lint 脚本自身 |

> 即使 `unittest.mock.patch`，也只许用来**阻断真实网络**（离线跑测试），不许用来**伪造返回值**。

## 6. 数据目录结构

```
data/
├─ real/                     真实数据集快照（带 manifest）
│  ├─ nhtsa-vpic-vin/        manifest.json + data.parquet
│  └─ telemetry-sample/
├─ synthetic/                LLM 拟真集（带 manifest + 生成脚本版本）
│  └─ users-vehicles-orders/ manifest.json + data.jsonl + gen.log
└─ fixtures/                 录制回放夹具（真实流量）
   └─ idor_cross_account/
```

**全部进 Git 或进 LFS**；快照不许在运行时联网下载（离线可跑是硬要求）。
`make data-fetch` 只在**维护者机器**上跑，用于更新快照，产物进 Git。

## 7. 新增数据集的 SOP

```
1 选来源：优先 A（开源靶场自带数据）→ B（公开数据集）→ C（LLM 拟真）
2 写 manifest（source_url / license / retrieved_at / sha256 / rows / fields / distribution / pii）
3 跑 make data-verify
4 加分布断言（tests/data/test_<name>_distribution.py）
5 在 25 的靶场表里登记它服务于哪个端点
6 更新 bench 基线（数据变了，数字不可比）
```

## 8. 这条政策怎么被检验

| 检查 | 通过标准 |
|---|---|
| `make lint-nodata-stub` | 0 命中 |
| `make data-verify` | 全部 manifest 校验通过 |
| `make range-selftest` | 真实靶场按契约工作（含 10 漏洞 + 10 安全孪生） |
| 人工抽检 | 每份 synthetic 数据集 `reviewed_by` 非空 |
| 代码审阅 | 任何 PR 出现"造数据"即打回（写进 CONTRIBUTING） |
