# 38 · 通用工作台规格（v3.5 新增）

> **本文回答的是"为什么它是死板的"以及"怎么长出手"。**
>
> 依据：`37` 已确证 Codex / Cursor / Claude Code 三家的工具面**完全同构**（读、写、编辑、搜、执行、计划），
> 而我们的 `08 §2` 只有 7 个安全语义工具、`35 §4` 只有 6 个安全动作——**一个文件都读不了、一行代码都改不了**。
>
> 所以本文补的不是"更多安全动作"，而是**通用工程工作台**（Workbench）。
> 它在安全层**之下**，产出永远是 `Lead`，永不产 `verdict`——这样"能打"与"能证明"不冲突。

---

## 0. 一句话

> **先长出两只手（读/写/搜/跑），再谈怎么打得准。**
> 工作台产出 `Observed` → `Lead`；安全层产出 `Judgement` → `Capsule`。
> **两层之间只有一条单向管道，不可逆。**

---

## 1. 为什么必须有这一层（失败模式复述）

| 场景 | 有工作台 | 我们现在（v3.4） |
|---|---|---|
| 响应是自定义加密 | 写 20 行 Python 解开 | `decode` 只认 4 种格式 → **完不成** |
| 需要特定 fuzz 变体 | 写脚本 | 8 种 `Transform` 表达不了 → 已在 `B7` 暴露 |
| 前端 bundle 藏 API | grep + 解析 | 只能靠契约/爬取 |
| 多步漏洞（注册→提权→读） | 自由编排 | playbook 的 8 个 action 表达不了 |
| **靶场跑不通** | 看日志改配置 | **只能人来** |

**根本原因**：动作集是**闭集**（13 个），而真实渗透的动作空间是**开集**。
闭集遇上开集，必然退化成"只能打设计者想到的那几种"。

---

## 2. 四层位置（插在 `33 §1` 的 L4 之内）

```
L4 动作层
├── workbench.*   通用工程能力（本文）         ← 新增
│    fs.read / fs.write / fs.edit / fs.glob / fs.grep
│    shell.run / code.search / todo.* / plan.*
└── act.*         安全动作（35 §4 已有 6 个）
     verify.*     验证动作（07/18）
```

**关键规则**：

| 规则 | 说明 |
|---|---|
| 工作台**只在内核之上** | 位于 `veripen_core/workbench/`，不碰 `veripen_oracles/` |
| 工作台**产出 `Observed`/`Lead`** | 类型上没有 `Judgement`（`17 I12` 扩展到工作台） |
| 工作台的写与执行**必须过 guard** | 与 `act.*` 同一套 `05` 边界，不减免 |
| 工作台**路径全部相对** | 抄 Cursor（`37 零件 A`）：绝对路径 schema 直接拒 |

## 3. 文件工具（`fs.*`，五个）

```python
# 全部参数为"相对工作区路径"，绝对路径在 schema 层拒绝
fs.read(relative_path: str, start_line: int = 1, end_line: int | None = None,
        max_bytes: int = 262144) -> Observed
    # 输出：{content, total_lines, truncated, sha256, persisted_ref}

fs.write(relative_path: str, content: str, if_exists: Literal["fail","overwrite"] = "fail",
         create_dirs: bool = False) -> Observed
    # 默认 fail：不许静默覆盖（I8 只增不改的延伸）

fs.edit(relative_path: str, patch: EditPatch, instructions: str) -> Observed
    # EditPatch = {find: str, replace: str, expect_count: int = 1}
    # expect_count 必须精确匹配，否则整体失败（防误替换）

fs.glob(pattern: str, max_results: int = 200) -> Observed
fs.grep(pattern: str, include: str | None = None, exclude: str | None = None,
        case_sensitive: bool = False, max_matches: int = 200) -> Observed
```

### 3.1 三条硬约束

| # | 约束 | 理由 |
|---|---|---|
| 1 | **无 `fs.delete`** | `17 I8` 只增不改；要删走审批门 + 人工 |
| 2 | **`fs.write` 默认 `if_exists=fail`** | 覆盖是最容易造成不可复盘的动作 |
| 3 | **`fs.edit` 必须带 `instructions`** | 抄 Cursor（`37 零件 B`）：为什么改 与 改成什么 都要进 capsule |

### 3.2 `fs.edit` 的实现形态（本期只做结构化）

```jsonc
{
  "relative_path": "scripts/probe.py",
  "instructions": "把超时从 5s 提到 15s，因为目标响应在 8s 左右",
  "patch": { "find": "TIMEOUT = 5", "replace": "TIMEOUT = 15", "expect_count": 1 }
}
```

**为什么不做 Codex 的 heredoc 自由文本 patch**（`37 零件 E`）：
自由文本会让 `lint-noroute` 的静态扫描失效——一段 patch 里塞个 URL，静态检查看不见。
结构化 patch 的 `find/replace` 是可文本化校验的，能继续扫地址。
→ heredoc 形态进 `99` 二期，前提是"能对 patch 内容做同样的静态检查"。

## 4. 执行工具（`shell.run`，一个但要求最严）

```python
shell.run(
    script: str,                         # 脚本内容（不是命令字符串）
    interpreter: Literal["python","bash"],   # 仅两种
    cwd: str = ".",                      # 相对工作区
    timeout_s: int = 120,
    risk_declared: Literal["low","medium","high"],   # 抄 Cursor（37 零件 C）
    require_user_approval: bool = False,             # 抄 Cursor
    env_allowlist: list[str] = [],       # 只透传白名单环境变量
) -> Observed
```

### 4.1 五道闸（缺一不可）

```
① schema      interpreter 只能是 python/bash；script 长度 ≤ 64KB
② 静态扫描    对 script 做 lint-noroute 同规则 + 危险调用表（subprocess/socket/os.system）
③ 风险双判    risk_declared 与策略判定不一致 → 拒 + 记事件（抄 Cursor 但更严）
④ 沙箱执行    容器：只读根 + 可写 /work + 无 NET_ADMIN + 出网走代理
⑤ 产物归档    全程 stdout/stderr → out/workbench/<sha>.log；脚本本身 → out/workbench/<sha>.py
```

### 4.2 与 `27`（地址不入库）的桥接——这是本文最关键的设计

**问题**：脚本里可以写 `requests.get("TARGET_URL")` 这样的字面地址，直接绕过 guard。

**解法**：**脚本的网络出口只有一个，且必须经过 harness 代理。**

```
┌─ 容器 ────────────────────────────────┐
│  script.py                            │
│    ↓ 只能访问 PROXY_LOOPBACK           │
│  harness-proxy（宿主机，做 scope 校验） │
│    ↓ 校验通过才转发                     │
│  目标                                  │
└───────────────────────────────────────┘
```

| 项 | 规格 |
|---|---|
| 容器出网 | **只有回环上的代理端口**（`PROXY_LOOPBACK` 符号），其余全部 DROP |
| 代理职责 | 每个出站请求过 `05 §1` 的四处校验；越界即拒并记 `scope ok=0` |
| 脚本感知 | 通过 `HTTP_PROXY`/`HTTPS_PROXY` 环境变量注入，**脚本不需要知道目标地址** |
| 地址来源 | 脚本里出现字面地址 **→ 静态扫描 ② 直接拒**（这是"地址不入库"延伸到脚本层） |

**这条设计让"能写脚本"和"地址不入库"同时成立**，代价是脚本不能直连——可以接受。

### 4.3 静态扫描的具体规则

| 规则 | 命中 | 处理 |
|---|---|---|
| S-URL | `https?://` 字面量 | 拒（除 `PROXY_LOOPBACK` 占位符） |
| S-IP | IPv4/IPv6 字面量 | 拒（除 `IP_ANY` / 回环占位符） |
| S-PORT | `:8080` 形式 | 拒 |
| S-DANGER | `os.system` / `subprocess` / `ctypes` / `eval` / `exec` / `__import__` | 拒（除非在 `99` 白名单里显式放行） |
| S-NET | 直接 `socket`/`ssl` 建连 | 拒（必须走代理） |

**误报处理**：与 `26` 一致——不许为了让脚本跑起来而放宽规则；确有需要走 `allowlist` 带理由。

## 5. 计划与任务工具（`plan.*` / `todo.*`）

### 5.1 `plan` 模式（抄 S3，`37 零件 D`）

| 工具 | 行为 |
|---|---|
| `plan.enter(reason)` | 进入计划模式：**一切写/执行动作被 guard 拒绝**，只允许 `fs.read`/`fs.grep`/`fs.glob`/`code.search` |
| `plan.exit(plan_text, actions[], risks[])` | 产出计划；**必须由人确认**（审批门）后才解锁执行 |
| `plan.abort()` | 退出计划模式，不解锁 |

**为什么两个工具而不是一个提示词开关**：提示词开关靠模型自觉，两个工具是**状态机**，guard 能硬拒。

### 5.2 `todo.*`（抄 S3 的 6 个工具，本期只做 3 个）

```python
todo.write(items: list[TodoItem]) -> Observed     # 全量替换（不是增量）
todo.list() -> Observed
todo.update(id: str, state: Literal["pending","in_progress","done","blocked"]) -> Observed
# TodoItem = {id, text, state, evidence_ref?}
```

**与 `35` 的关系**：`must_verify_next` 产生的"待验证 lead"**自动进 todo**，
这样"线索闭环"这件事在 agent 的视野里是可数的（`pending_leads==0` 就等价于 `todo` 里没有 `in_progress`）。

## 6. 代码检索（`code.search`，替代语义检索）

`37 §6` 已判定：**不抄 `codebase_search`（向量语义检索）**，理由是不可复现 + 需嵌入模型。

替代方案：

```python
code.search(query: str, kind: Literal["symbol","reference","definition"] = "symbol",
            max_results: int = 50) -> Observed
```

| 实现档 | 用什么 | 本期 |
|---|---|---|
| **L1 结构化（本期）** | 正则 + AST（Python `ast`、TS 用 tree-sitter 可选） | ✅ |
| L2 LSP（二期） | 起语言服务器 | ❌ |
| L3 向量（不做） | 嵌入 | ❌ 违 I1 可复现 |

**本期够用的理由**：渗透场景里"找符号"主要发生在**读目标的前端 bundle / 契约文件**，
正则 + AST 足以覆盖 80%；真正的语义理解交给模型读代码。

## 7. 与既有不变量的关系（逐条核对）

| 不变量 | 影响 | 结论 |
|---|---|---|
| **I1 判定纯函数** | 工作台不参与 judge | ✅ 不触碰 |
| **I2 三条件** | 同上 | ✅ |
| **I4 模型不参与判定/不指定地址** | 工作台**能写脚本**，但脚本网络强制走代理、地址字面量被静态拒 | ✅ 强化（多两道闸） |
| **I5 scope 四处** | 代理层做第四处（`post_connect` 的延伸） | ✅ 强化 |
| **I8 只增不改** | `fs.write` 默认 fail、无 `fs.delete` | ✅ 强化 |
| **I12 行动作不产 verdict** | 扩展到 `workbench.*`（`01 §7` 第九契约） | ✅ 扩展 |
| **I10/I11 记忆** | 工作台不写 `asset_facts` | ✅ 不触碰 |

**新增不变量 I13**：**工作台的脚本网络必须经代理，且脚本内地址字面量在静态期即被拒**。
—— 这是让"能跑脚本"与"地址不入库"共存的唯一机械保证。

## 9. 明确不做

| 项 | 理由 |
|---|---|
| `fs.delete` | 违 I8；要删走审批 |
| 语义向量检索 `codebase_search` | 不可复现 + 需嵌入模型（`37 §6`） |
| heredoc 自由文本 patch | 让静态检查失效（`37 零件 E`），进 `99` |
| `computer_use` / 全 CDP 浏览器 | 与本项目隔离模型冲突（`37 §6`） |
| 脚本直连网络 | 违 I13 |
| LSP 全套 | 二期（`99`） |

## 11. 一句话

> 我们过去把"严格"做成了"没有手"。

> **手能干活，但干不出不可审计的事。**
