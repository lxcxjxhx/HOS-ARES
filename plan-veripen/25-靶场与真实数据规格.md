# 25 · 靶场与真实数据规格

> 靶场是**测量工具**：靶场不真，bench 的每个数字都不成立。
> 本章只允许真实开源靶场 + 真实数据集（政策见 `26-数据真实性与来源政策.md`）。
> 自建的只有一层**适配层**（`tsp-lab`），它跑的是真实数据、真实契约，故意保留鉴权缺陷。

## 1. 靶场清单

| 靶场 | 来源 | 性质 | 覆盖 oracle |
|---|---|---|---|
| `dvwa` | `vulnerables/web-dvwa` | 真实开源（PHP） | sqli_bool_diff / sqli_error_based / xss_reflected_ctx |
| `juice` | `bkimminich/juice-shop` | 真实开源（Node/SPA） | idor_cross_account / jwt_replay / xss_stored_probe / rate_limit |
| `crapi` | `owasp/crAPI` | **真实开源，车辆售后服务域** | bola_functional / idor / jwt / mass_assignment |
| `vampi` | `erev0s/VAmPI` | 真实开源（精简 REST） | mass_assignment / idor / bola（最小样本） |
| `webgoat` | `webgoat/webgoat` | 真实开源（教学） | 认证/会话类补充 |
| `tsp-lab` | **自建适配层**（§3） | 真实数据 + 真实 OpenAPI + 故意缺陷 | ssrf_oob / path_traversal / open_redirect / cors / graphql / 车云形态 IDOR |

**为什么还需要 `tsp-lab`**：车云形态（VIN、遥测、mTLS、GraphQL）在现成开源靶场里没有完全对应的项目；
但"没有对应靶场"不等于"自己编数据"——所以它只做适配：**真实数据 + 真实契约 + 故意缺陷**。

**明确不做**：不写返回固定 JSON 的假后端；不在代码里硬编码 <5 行样例数据；不用随机且不固定种子的生成器。

## 2. 外部靶场的固定配置

| 项 | 配置 |
|---|---|
| DVWA 安全级别 | `low`（登录后设置一次，写进 init 脚本） |
| DVWA 账号 | `admin/password`（镜像默认）；profile 里用 `secret_ref` |
| Juice 账号 | 两个固定账号（`primary`/`secondary`），`scripts/seed-juice.sh` 注册 |
| crAPI / vAmPI 账号 | 用项目自带注册接口创建两个账号，**数据落在其真实数据库里**（不是我们编的） |
| 重置 | 容器重建 + 各项目自带 reset；`tsp-lab` 用 `__admin/reset` 重放同一份快照 |
| healthcheck | 各靶场探"真实业务端点"（不是 `/`）：DVWA 探 `/login.php`、juice 探 `/rest/products`、crAPI 探 `/identity/api/v2/user/dashboard`、vAmPI 探 `/users/v1`、tsp-lab 探 `/healthz` |

## 3. `tsp-lab` 适配层规格

### 3.1 形态与数据来源

```
tsp-lab (FastAPI, python:3.12-slim)
├─ 数据层：data/real/*（快照）+ data/synthetic/*（受管拟真集）
│   ├─ nhtsa-vpic-vin      → 车辆实体（VIN/品牌/年款/产地），校验位合法
│   ├─ telemetry-sample    → 遥测时序（速度/电量/里程），真实采样率
│   └─ users-vehicles-orders → 用户-车辆-订单关系（拟真，固定种子，人工抽检）
├─ 契约层：openapi.yaml（40 operation，真实分页/错误码/边界）
└─ 行为层：真实鉴权/序列化/限流，**故意**保留 §3.3 的 10 处缺陷
```

**判据**：每个端点返回的行都必须能追到 `data/` 里的某一行（`make data-trace ENDPOINT=...` 可查）。

### 3.2 端点与数据映射

| 分组 | op 数 | 数据来源 | 说明 |
|---|---|---|---|
| auth | 4 | users-vehicles-orders | token / login / refresh / logout |
| vehicles | 8 | nhtsa-vpic-vin + telemetry-sample | 列表/详情/遥测/控制（控制类只读） |
| users | 6 | users-vehicles-orders | me / 详情 / 设置 / 头像 |
| orders | 6 | users-vehicles-orders | 列表/详情/取消 |
| files | 3 | 真实静态文件（含系统文件路径缺陷） | 下载/上传（上传到临时卷）/列表 |
| admin | 4 | users + orders 聚合 | users / audit / reports / config |
| proxy | 2 | 真实 HTTP 客户端 | fetch（无白名单）/ proxy（白名单） |
| graphql | 1 | vehicles + orders | 单端点，含一个受限 mutation |
| meta | 6 | — | healthz / openapi / reset / version / metrics / docs |

### 3.3 故意保留的 10 处缺陷（靶场的定义）

| # | 端点 | 缺陷 | 对应 oracle | 判定要点 |
|---|---|---|---|---|
| V1 | `GET /vehicles/{vin}` | 不校验归属 | idor_cross_account | B 读 A 的车 200 且 body 相同 |
| V2 | `GET /internal/reports` | 无功能级鉴权 | bola_functional | 低权 200 且有报表数据 |
| V3 | `GET /fetch?url=` | 服务端拉任意 URL | ssrf_oob | OOB 收到 nonce |
| V4 | `POST /auth/token` | 接受 `alg=none` | jwt_replay | 无签名 token 200 |
| V5 | `GET /files?name=../../etc/passwd` | 路径穿越 | path_traversal | 命中 `root:x:0:0` |
| V6 | `GET /login?next=https://oob/` | 开放跳转 | open_redirect | Location 指向 oob |
| V7 | `GET /api/vehicles` | ACAO 回显任意 Origin + credentials | cors_misconfig | 响应头回显 |
| V8 | `POST /auth/login` | 无限流 | rate_limit_absent | 10 并发全成功 |
| V9 | `POST /graphql` | introspection 开 + 受限 mutation 无鉴权 | graphql_introspection | 低权 mutation 成功 |
| V10 | `PATCH /users/me` | 接受 `role` 字段 | mass_assignment | 回读 role=admin |

### 3.4 安全孪生端点（负样本来源，10 条）

| # | 端点 | 为什么安全 |
|---|---|---|
| S1 | `GET /vehicles/me` | 正确校验归属，读他人 403 |
| S2 | `GET /admin/users` | 低权 403（V2 的缺陷在**另一条**路径 `/internal/reports`，两者不重叠） |
| S3 | `GET /proxy?url=` | 白名单，只允许同域 |
| S4 | `GET /files?name=` | 规范化后限制在 `static/` |
| S5 | `GET /login?next=` | 只允许 `/dashboard`、`/settings` |
| S6 | `GET /api/safe` | ACAO 精确匹配自己的域 |
| S7 | `POST /auth/login-safe` | 5 次/分钟限流 |
| S8 | `POST /graphql`（header 关闭 introspection） | 关闭路径生效 |
| S9 | `PATCH /users/me-safe` | 忽略 `role` |
| S10 | `GET /api/users/{id}` | 正确对象级校验（对照 V1） |

> **铁律**：同一条路径不能既是缺陷又是安全样本，否则负样本失效。V2 因此改用 `/internal/reports`。

### 3.5 确定性

| 项 | 规格 |
|---|---|
| 数据 | 全部来自快照，运行时**不联网**、不随机 |
| 时间戳 | 统一 `2026-01-01T00:00:00Z`（来自快照字段，不是 `now()`） |
| ID | 来自快照，稳定 |
| 重置 | `POST /__admin/reset` 重放同一份快照，幂等，2s 内完成 |
| 指纹 | `GET /__admin/fingerprint` 返回数据快照 sha256（供 bench 校验"数据没变"） |

## 4. 数据集（真实与受管拟真）

| 数据集 | 来源类型 | 许可 | 行数目标 | 服务于 |
|---|---|---|---|---|
| `nhtsa-vpic-vin` | B（公开数据快照） | public-domain (US gov) | ≥10,000 | vehicles 实体、VIN 校验 |
| `telemetry-sample` | B（公开数据集快照） | 按数据集许可 | ≥50,000 点 | 遥测时序 |
| `users-vehicles-orders` | C（LLM 拟真，固定种子 + 抽检） | 内部 | ≥500 用户 / ≥600 车 / ≥2,000 单 | 用户/订单/归属关系 |

**每份数据集必须有 `manifest.json`**（schema 见 `schemas/dataset-manifest.schema.json`），字段含
`source_url / license / retrieved_at / sha256 / rows / fields / distribution / pii / reviewed_by`。

**`pii` 必须为 false**：真实数据里的个人信息一律脱敏后快照；不脱敏不进仓库。

## 5. OOB 通道（离线可用）

| 项 | 规格 |
|---|---|
| 服务 | `oob` 容器：HTTP listener(8080) + DNS listener(5353) |
| 域名 | `oob.internal`（compose 内 DNS） |
| 记录 | `{nonce, ts, method, path, headers, src_ip}` 落内存 + 文件 |
| 查询 | `GET /__oob/events?nonce=x` |
| 清理 | `POST /__oob/reset`；每任务开始前清该任务 nonce 前缀 |
| 无外网 | 全在 docker 内网，不依赖任何公网服务 |
| 自测 | 从 worker 容器 `curl oob.internal/<nonce>` 必须命中 |

## 6. 靶场自测（`make range-selftest`）

**目的**：证明"靶场是好的"。它失败时 bench 数字一律不可信，`make bench` 内部会先跑它。

| 断言 | 方法 |
|---|---|
| 外部靶场按契约工作 | 各打一个真实业务端点，断言 200 + 期望字段 |
| 10 处故意缺陷存在 | 用**独立脚本**（不走 oracle 代码）直接断言状态码/内容 |
| 10 处安全孪生安全 | 同上，断言 403/白名单生效 |
| 数据快照完整 | `make data-verify`：sha256 + 行数 + 字段 + `pii:false` |
| 数据可追溯 | 任取 3 行响应，能在 `data/` 快照里定位到源行 |
| OOB 可回连 | worker → `oob.internal/<nonce>` → 事件表命中 |
| 重置幂等 | 连续 reset 两次，`__admin/fingerprint` 相同 |
| 无随机字段 | 同请求两次，响应体 sha256 相同（nonce 回显除外） |
| 探活稳定 | 连续 30 次探活全 200 |

## 7. 版本与锁定

| 项 | 规格 |
|---|---|
| 镜像 | 全部 digest 锁定（`image@sha256:…`），禁 `latest` |
| `tsp-lab` | 自建镜像，`Dockerfile` + `pyproject` 锁定；digest 进 capsule `env.image_digest` |
| 数据 | 快照 sha256 进 `tests/range/VERSIONS.md` 与 capsule 的 `env.data_fingerprint` |
| 变更 | 靶场或数据变更 = bench 基线失效，必须重跑并更新 `bench.md` |
| 记录 | `tests/range/VERSIONS.md`：5 个靶场 digest + 3 份数据快照 sha256 |

## 8. 常见坑（提前写死）

| 坑 | 处理 |
|---|---|
| DVWA 首次访问要初始化 DB，前 20s 500 | healthcheck 探 `/login.php` 且 body 含表单 |
| juice-shop SPA 首屏慢 | 探 `/rest/products` |
| crAPI 依赖多个子服务，启动慢 | `depends_on` + 每 5s 重试，最多 3 分钟 |
| vAmPI 的 `/users/v1` 需要先注册 | init 脚本注册两个账号并落库 |
| 数据快照体积过大 | 只留"够覆盖分布"的抽样（≥下限行数），完整版放 LFS |
| 固定时间戳被框架改写 | 禁用 `datetime.now()`，全部读快照字段 |
| 容器时区 | 全部 `TZ=UTC` |
| 端口冲突 | 靶场不映射宿主端口，只走 compose 内网 |
| 数据残留 | `down -v` + `__admin/reset` 双保险 |
| 真实数据含个人信息 | 快照前脱敏，manifest `pii:false`；否则不进仓库 |
