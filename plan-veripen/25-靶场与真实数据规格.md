# 25 · 靶场与真实数据规格

> 靶场是**测量工具**：靶场不真，bench 的每个数字都不成立。
> 本章只允许真实开源靶场 + 真实数据集（政策见 `26-数据真实性与来源政策.md`）。
>
> **v3 改写（关键）**：本章**不再列出任何端点、healthcheck 路径、缺陷 URL**。
> 理由：v2 的那张端点表是全仓最密集的硬路由来源——它既被文档引用，又会被测试代码抄。
> 现在靶场只对外发布两样东西：**机器可读契约**（含语义标签）+ **缺陷语义清单**。
> 具体地址由 `route_discovery` 从契约解析（`27`）。

## 1. 靶场清单

| 靶场 | 来源 | 性质 | 提供标签（`18 §6`） |
|---|---|---|---|
| `dvwa` | 真实开源（PHP） | 传统 Web 表单 | `param_injectable`、`echo_param` |
| `juice` | 真实开源（Node/SPA） | SPA + REST | `object_read`、`protected_read`、`content_write/read`、`rate_sensitive` |
| `crapi` | 真实开源（车辆售后域） | REST + 多角色 | `object_read`、`admin_function`、`profile_write`、`token_issue` |
| `vampi` | 真实开源（精简 REST） | 最小样本 | `profile_write`、`object_read`、`bola` 对照 |
| `webgoat` | 真实开源（教学） | 认证/会话 | `token_issue`、`protected_read` |
| `tsp-lab` | **自建适配层**（§3） | 真实数据 + 真实契约 + 故意缺陷 | 全标签集（含 `url_fetch`、`file_read`、`redirect_entry`、`graphql_endpoint`、`api_read`） |

**为什么还需要 `tsp-lab`**：车云形态（VIN、遥测、mTLS、GraphQL）在现成开源靶场里没有完全对应的项目；
但"没有对应靶场"不等于"自己编数据"——所以它只做适配：**真实数据 + 真实契约 + 故意缺陷**。

**明确不做**：不写返回固定 JSON 的假后端；不在代码里硬编码 <5 行样例数据；不用随机且不固定种子的生成器。

## 2. 外部靶场的接入方式（v3 改写）

| 项 | 规格 |
|---|---|
| 接入点 | 通过 `.env` 的 `ASSET_*` 符号注入（与客户档同一机制），**不写进任何文档或代码** |
| 标签来源 | 每个靶场附带一份**标签适配契约**（`tests/range/adapters/<name>.yaml`），声明"该靶场的哪些 operation 具有哪些语义标签" |
| 适配契约的地位 | 它是**数据**，不是代码；由 reviewer 逐条确认；改它必须走 PR（`13` 变更记录） |
| 账号 | 靶场真实注册的账号（primary/secondary），凭据进 vault，`secret_ref` 进 profile |
| 重置 | 容器重建 + 各项目自带 reset；`tsp-lab` 用 `__admin/reset` 重放同一份快照（该路径由 bindings 提供，不写死） |
| 就绪探测 | **探"契约可达"而不是探某个页面**：`contract_locator` 能拿到契约即视为就绪（`27 §3.8`） |

**为什么就绪探测改成"契约可达"**：v2 的 healthcheck 探的是具体业务页面，
那等于在部署配置里写死了一堆路径。改成探契约后，探测目标由 `contract_locator` 解析，
和业务路由无关。

### 2.1 适配契约的最小形态

```yaml
# tests/range/adapters/<name>.yaml   —— 只有语义，没有地址
target: <range-name>
contract_locator: observed        # 由 routes 的契约定位策略去取
labels:
  - selector: object_read
    match: {operation_hint: "读取单个资源", param_kind: int}
    review: {by: <reviewer>, at: <date>}
  - selector: url_fetch
    match: {operation_hint: "服务端取用外部 URL", param_format: uri}
    review: {by: <reviewer>, at: <date>}
```

`operation_hint` 是人读描述，**不参与匹配**（匹配由 `19 §3` 的结构规则做）。
它存在的目的只有一个：让 reviewer 确认"这条标签确实是这个意思"。

## 3. `tsp-lab` 适配层规格

### 3.1 形态与数据来源

```
tsp-lab (FastAPI, python:3.12-slim)
├─ 数据层：data/real/*（快照）+ data/synthetic/*（受管拟真集）
│   ├─ nhtsa-vpic-vin      → 车辆实体（VIN/品牌/年款/产地），校验位合法
│   ├─ telemetry-sample    → 遥测时序（速度/电量/里程），真实采样率
│   └─ users-vehicles-orders → 用户-车辆-订单关系（拟真，固定种子，人工抽检）
├─ 契约层：自述 OpenAPI（真实分页/错误码/边界）+ 语义标签扩展
└─ 行为层：真实鉴权/序列化/限流，**故意**保留 §3.3 的 10 处缺陷
```

**判据**：每个 operation 返回的行都必须能追到 `data/` 里的某一行（`make data-trace OP=<op_id>` 可查）。
注意 v3 把追踪键从"端点"改成 `op_id`——追踪的是语义操作，不是地址。

### 3.2 交付面（v3：改为按能力分组，不列端点）

| 分组 | op 数 | 数据来源 | 提供的标签 |
|---|---|---|---|
| 认证类 | 4 | users-vehicles-orders | `token_issue`、`protected_read` |
| 对象类 | 8 | nhtsa-vpic-vin + telemetry-sample | `object_read`、`object_list`、`param_injectable` |
| 用户类 | 6 | users-vehicles-orders | `profile_write`、`profile_read` |
| 订单类 | 6 | users-vehicles-orders | `object_read`、`object_list` |
| 文件类 | 3 | 真实静态文件（含路径处理缺陷） | `file_read` |
| 管理类 | 4 | users + orders 聚合 | `admin_function`、`normal_function` |
| 代理类 | 2 | 真实 HTTP 客户端 | `url_fetch`（无白名单）/ `url_fetch`（白名单） |
| GraphQL | 1 | vehicles + orders | `graphql_endpoint` |
| 元信息 | 6 | — | （无业务标签） |

**元信息组的特殊处理**：`__admin/reset`、fingerprint 等**不是测试面**，
它们的地址只能从 `config/bindings/sources.yaml` 的符号取，**不进入 `RouteSet`**（不进发现、不进判定）。
这是 v2 的一个隐患：把运维路径和生产路径混在一个命名空间里，很容易被误当测试面。

### 3.3 故意保留的 10 处缺陷（**按语义描述，不按地址**）

| # | 缺陷类别 | 语义位置 | 对应 oracle | 判定要点 |
|---|---|---|---|---|
| V1 | 对象级鉴权缺失 | `object_read`（不含 self 语义的那一组） | idor_cross_account | B 读 A 的对象 200 且 body 相同 |
| V2 | 功能级鉴权缺失 | `admin_function`（报表类） | bola_functional | 低权 200 且有报表数据 |
| V3 | 服务端取用任意 URL | `url_fetch`（无白名单面） | ssrf_oob | OOB 收到 nonce |
| V4 | 令牌无签名可接受 | `token_issue` | jwt_replay | 无签名 token 200 |
| V5 | 路径穿越 | `file_read` | path_traversal | 命中系统文件特征指纹 |
| V6 | 开放跳转 | `redirect_entry` | open_redirect | Location 指向 OOB |
| V7 | CORS 回显 + 凭据 | `api_read` | cors_misconfig | 响应头回显任意 Origin |
| V8 | 无限流 | `rate_sensitive`（登录类） | rate_limit_absent | 10 并发全成功 |
| V9 | GraphQL introspection + 无鉴权 mutation | `graphql_endpoint` | graphql_introspection | 低权 mutation 成功 |
| V10 | 批量赋值 | `profile_write` | mass_assignment | 回读角色字段被采纳 |

### 3.4 安全孪生（负样本来源，10 条）

| # | 语义位置 | 为什么安全 |
|---|---|---|
| S1 | `object_read`（self 语义那一条） | 正确校验归属，读他人 403 |
| S2 | `admin_function`（用户管理类） | 低权 403（**与 V2 不重叠**：V2 在报表类） |
| S3 | `url_fetch`（白名单面） | 只允许同域 |
| S4 | `file_read`（受限面） | 规范化后限制在静态目录 |
| S5 | `redirect_entry`（受限面） | 只允许相对路径白名单 |
| S6 | `api_read`（严格面） | ACAO 精确匹配自身域 |
| S7 | `rate_sensitive`（防护面） | 5 次/分钟限流 |
| S8 | `graphql_endpoint`（关闭面） | introspection 关闭生效 |
| S9 | `profile_write`（严格面） | 忽略只读字段 |
| S10 | `object_read`（另一组，正确校验） | 正确对象级校验（对照 V1） |

### 3.6 `role: hardened` 孪生资产（可选能力，供 `07 §0.2.4` 用）

`three_way_holds` 的第 4 条件需要"同一面在补丁后的实例"上再打一次。这要求靶场提供一个**孪生资产**：

| 项 | 规格 |
|---|---|
| 声明方式 | `profile.scope.assets[]` 里加 `role: hardened` 与 `twins_with: <原资产 id>` |
| 数据 | **同一份快照**（`data/` 同 manifest），只有行为层不同（缺陷已修） |
| 契约 | 同一份契约（面相同），否则 `template_sha256` 会对不上，第 4 条件失效 |
| 必须成对 | `twins_with` 指向的资产必须存在且 `role: target`；否则启动即失败 |
| 不声明时 | 第 4 条件**整体跳过**（`assertion.hardened_absent = null`），行为与未引入时一致 |

**为什么要求"同一份契约"**：第 4 条件比较的是"同一个 `RouteRef` 在两个实例上的行为"。
契约不同 → `ref` 不同 → 比的就不是同一个面，条件失去意义。

**做这个的成本**：`tsp-lab` 需要一份"打了补丁的镜像"（同一代码 + 缺陷开关关闭）。
这是 `25 §3.3` 那 10 处缺陷的**开关化**，不是新写一套。

> **铁律**：同一条绑定不能既是缺陷又是安全样本，否则负样本失效。
> 这条在 v3 更容易保证：因为"同一条"现在有精确定义（`ref` 相同），而不是"看起来路径一样"。

### 3.5 确定性

| 项 | 规格 |
|---|---|
| 数据 | 全部来自快照，运行时**不联网**、不随机 |
| 时间戳 | 统一固定值（来自快照字段，不是 `now()`） |
| ID | 来自快照，稳定 |
| 重置 | `__admin/reset`（符号取自 bindings）重放同一份快照，幂等，2s 内完成 |
| 指纹 | `__admin/fingerprint` 返回数据快照 sha256（供 bench 校验"数据没变"） |
| **路由指纹** | `__admin/fingerprint` 同时返回**契约 sha256**，用于校验"面没变" |

## 4. 数据集（真实与受管拟真）

| 数据集 | 来源类型 | 许可 | 行数目标 | 服务于 |
|---|---|---|---|---|
| `nhtsa-vpic-vin` | B（公开数据快照） | public-domain (US gov) | ≥10,000 | 车辆实体、VIN 校验 |
| `telemetry-sample` | B（公开数据集快照） | 按数据集许可 | ≥50,000 点 | 遥测时序 |
| `users-vehicles-orders` | C（LLM 拟真，固定种子 + 抽检） | 内部 | ≥500 用户 / ≥600 车 / ≥2,000 单 | 用户/订单/归属关系 |

**每份数据集必须有 `manifest.json`**（schema 见 `schemas/dataset-manifest.schema.json`），字段含
`source_ref / license / retrieved_at / sha256 / rows / fields / distribution / pii / reviewed_by`。

**`pii` 必须为 false**：真实数据里的个人信息一律脱敏后快照；不脱敏不进仓库。

## 5. OOB 通道（离线可用）

| 项 | 规格 |
|---|---|
| 服务 | `oob` 容器：HTTP listener + DNS listener |
| 接入点 | **由 `config/bindings/sources.yaml` 的 `oob_ref` 符号提供**，代码与文档里都不出现 |
| 记录 | `{nonce, ts, method, path_sha256, headers, src_ip}` 落内存 + 文件（**路径存哈希**，避免形成"可用地址"清单） |
| 查询 | `__oob/events?nonce=x`（符号取自 bindings） |
| 清理 | `__oob/reset`；每任务开始前清该任务 nonce 前缀 |
| 无外网 | 全在 docker 内网，不依赖任何公网服务 |
| 自测 | worker 容器内 `veripen oob selftest` 必须命中（不写裸地址） |

**`path_sha256` 而不是 `path`**：OOB 记录里如果存明文路径，它就成了系统里唯一一处
"存下来的可用地址"。存哈希足够判定（我们只关心"有没有回调、带没带 nonce"）。

## 6. 靶场自测（`make range-selftest`）

**目的**：证明"靶场是好的"。它失败时 bench 数字一律不可信，`make bench` 内部会先跑它。

| 断言 | 方法 |
|---|---|
| 外部靶场按契约工作 | 每个 profile 用到的标签都能解析出 ≥1 条绑定 |
| 10 处故意缺陷存在 | 用**独立脚本**（不走 oracle 代码）按**标签**取绑定，断言状态码/内容 |
| 10 处安全孪生安全 | 同上，断言 403/白名单生效 |
| 数据快照完整 | `make data-verify`：sha256 + 行数 + 字段 + `pii:false` |
| 数据可追溯 | 任取 3 行响应，能在 `data/` 快照里定位到源行 |
| OOB 可回连 | worker 内 `veripen oob selftest` → 事件表命中 |
| 重置幂等 | 连续 reset 两次，`__admin/fingerprint` 相同 |
| 无随机字段 | 同请求两次，响应体 sha256 相同（nonce 回显除外） |
| 探活稳定 | 连续 30 次契约可达 |
| **适配契约完整（v3）** | 每个标签在适配契约里都有 `review.by`，无 `TODO` |

## 7. 版本与锁定

| 项 | 规格 |
|---|---|
| 镜像 | 全部 digest 锁定（`image@sha256:…`），禁 `latest` |
| `tsp-lab` | 自建镜像，`Dockerfile` + `pyproject` 锁定；digest 进 capsule `env.image_digest` |
| 数据 | 快照 sha256 进 `tests/range/VERSIONS.md` 与 capsule 的 `env.data_fingerprint` |
| **契约** | 契约 sha256 进 `routesets` 的 `query_hash` 关联字段与 `VERSIONS.md` |
| 变更 | 靶场/数据/**契约**变更 = bench 基线失效，必须重跑并更新 `bench.md` |
| 记录 | `tests/range/VERSIONS.md`：镜像 digest + 数据 sha256 + 契约 sha256 |

**v3 新增"契约变更也算基线失效"**：因为契约决定 `RouteSet`，而 `RouteSet` 决定能测什么。
契约改了不重跑，等于拿旧地图找新城市。

## 8. 常见坑（提前写死）

| 坑 | 处理 |
|---|---|
| DVWA 首次访问要初始化 DB，前 20s 500 | 就绪探测改为"契约可达 + 一次成功解析"，重试到超时 |
| juice 首屏慢（SPA） | 探契约而非探页面 |
| crAPI 依赖多个子服务，启动慢 | `depends_on` + 每 5s 重试，最多 3 分钟 |
| vAmPI 需要先注册 | init 脚本注册两个账号并落库 |
| 数据快照体积过大 | 只留"够覆盖分布"的抽样（≥下限行数），完整版放 LFS |
| 固定时间戳被框架改写 | 禁用 `datetime.now()`，全部读快照字段 |
| 容器时区 | 全部 `TZ=UTC` |
| 端口冲突 | 靶场不映射宿主端口，只走 compose 内网 |
| 数据残留 | `down -v` + reset 双保险 |
| 真实数据含个人信息 | 快照前脱敏，manifest `pii:false`；否则不进仓库 |
| **适配契约漂移（v3）** | 靶场升级后标签可能指向不存在的 operation → `range-selftest` 的"适配契约完整"项会失败 |
| **把运维路径当测试面（v3）** | 元信息组不进 `RouteSet`（§3.2），从结构上杜绝 |
