# 11 · 测试策略与靶场用例清单

> 三层测试，各管一段。**判据：能不能在没有模型、没有网络的情况下证明判定是对的。**

## 1. 三层测试

| 层 | 范围 | 依赖 | 数量目标 | 运行时长 |
|---|---|---|---|---|
| L1 单元 | `judge()` 纯函数（14 类）、状态迁移、令牌桶、哈希链、schema 校验、用例生成稳定性 | 无（纯 CPU） | ≥140 例 | <10s |
| L2 oracle 集成 | 真打本地靶场，验证 VERIFIED/REFUTED | 靶场容器 | ≥44 例 | <8min |
| L3 端到端 | compose 全栈，跑 demo / demo-alt / replay / bench 抽样子集 / 控制台只读 | 全部容器 + 模型 | ≥12 例 | <15min |

**门禁**：L1 必须 100% 绿才允许提交；L2 每 PR 跑；L3 每日 + 发布前。

## 2. L1 单元测试清单（最有价值，最先写）

| 目标 | 用例 | 断言 |
|---|---|---|
| `judge` 纯函数性 | 同一 `pairs` 调 100 次 | verdict 集合大小 = 1 |
| `judge` 无时钟依赖 | 冻结/打乱 `ts` 字段 | 结论不变 |
| `sqli_bool_diff` | 4 正 + 2 负 | 正→VERIFIED，负→REFUTED |
| `idor_cross_account` | 4 正 + 2 负（含"公开资源"） | 公开资源必须 REFUTED |
| `ssrf_oob` | 3 正（含 nonce 命中）+ 3 负（回显 / control 有回调 / listener 离线） | 离线→INCONCLUSIVE |
| `jwt_replay` | 3 正 + 3 负（强校验/弱但需特权数据） | 缺 control→INCONCLUSIVE |
| 三条件合取 | 缺 control 的 pairs | **一律不得 VERIFIED** |
| 状态迁移 | QUEUED→LEASED 并发 2 线程 | 只有一个成功 |
| 租约回收 | 假时钟推进 31s | 任务回 QUEUED 且 attempt+1 |
| 死信 | attempt=3 再超时 | state=DEAD_LETTER |
| 幂等 | 同 idem_key 插两次 | 返回同一 id，无异常 |
| 令牌桶 | 20/s 桶 + 100 并发请求 | 通过数 ≈ 20×时长，误差 <10% |
| 每资产并发 | 同资产 10 并发 | 峰值并发 ≤2 |
| capsule 内容寻址 | 同输入 seal 两次 | self_sha256 相同 |
| 哈希链 | 改中间一条 | verify-chain 定位到该条 |
| 脱敏 | 含 Cookie/Authorization/VIN 的 trace | 落盘后无明文 |
| schema | 缺 `secondary` 账号却开 idor | 启动期抛错 |
| 报告同源性 | 渲染后三视图比对 | finding 集合相同 |
| 措辞 lint | 未验证发现含"存在" | lint 失败 |

## 4. 靶场用例集

> 全集 **44 例 = 28 正 + 16 负**，覆盖 14 类 oracle。
> §4.1/§4.2 是 **Tier A 基础集（20 例）**，W2 结束前必须全绿；
> Tier B/C 的扩展 24 例（P-13…P-28 / N-09…N-16）在各自 oracle 落地时按 §7 模板补入，
> 判据与基础集完全一致：正样本 VERIFIED、负样本 REFUTED、FP 硬门槛 0。

### 4.2 基础集负样本（8，`expect_verdict: REFUTED`，**FP 门槛的全部来源**）

| case_id | 资产 | oracle | 为什么看似漏洞其实安全 |
|---|---|---|---|
| N-01 | dvwa | sqli_bool_diff | 所有参数都返回同一页（如静态页）→ 差分=0 |
| N-02 | juice | sqli_bool_diff | 参数非法返回 500，control 也 500 → INCONCLUSIVE 不算 FP，但要验证不出 VERIFIED |
| N-03 | juice | idor_cross_account | 公开资源，任何账号都能读（非越权）→ control 也 200 |
| N-04 | tsp-lab | idor_cross_account | 正确实现对象级校验 → probe 403 |
| N-05 | tsp-lab | ssrf_oob | URL 白名单实现 → 无回调 |
| N-06 | juice | ssrf_oob | 参数被原样回显但不发起请求 → 无回调（易误判为 SSRF） |
| N-07 | tsp-lab | jwt_replay | 强签名校验 → `alg=none` 与 tamper 均 401 |
| N-08 | juice | jwt_replay | 签名校验弱但返回的数据不含特权字段 → 不得判 VERIFIED |

> N-06 与 N-05 是这套系统的"体检指标"：它们一旦变正，说明对照逻辑坏了。

## 5. 测试数据与凭据（禁 mock，见 26）

| 项 | 规格 |
|---|---|
| 账号 | 靶场真实注册的账号（primary/secondary），凭据进 vault，**不进 profile 明文** |
| 数据来源 | 只允许三种：真实开源靶场 / 公开数据快照 / 受管拟真集（`26 §2`）。**禁止手写响应体** |
| L1 夹具 | **录制回放**：`make record ORACLE=x ASSET=y` 从真实靶场录 request/response 到 `tests/fixtures/`，附靶场镜像 digest；靶场升级后夹具标 `stale` 需重录 |
| 数据集 | `data/` 下每份带 `manifest.json`；`make data-verify` 校验 sha256/行数/字段/`pii:false` |
| 时间 | 全部用 UTC；测试冻结时钟（`freezegun` 或注入 clock） |
| 随机 | nonce 用 `secrets`，但**判定不看 nonce 值本身**，只看"是否出现预期 nonce" |
| 机械检查 | `make lint-nodata-stub`：全仓 0 命中 mock/stub/fake/dummy、0 处硬编码 <5 行样本 |
| 唯一豁免 | `unittest.mock.patch` 仅用于**阻断真实网络**（离线跑），不许用来伪造返回值 |

## 7. 一次 `make test` 的编排

```
make test        = lint(ruff+mypy) + unit + oracle(L2, 需 docker) + report-lint
make test-fast   = lint + unit                       # 本地秒级
make test-e2e    = compose up + demo + demo-alt + replay + down
make bench       = 独立，见 10
```

依赖顺序：L1 绿 → L2 绿 → L3 绿。**L2 失败时不允许跑 bench 出数字**（否则拿坏环境的分数当结论）。
