# 11 · 测试策略与靶场用例清单

> 三层测试，各管一段。**判据：能不能在没有模型、没有网络的情况下证明判定是对的。**
>
> **v3 变更**：新增 **L0 路由层测试**（`tests/routes/`，毫秒级、无网络、无模型）。
> 这一层是"不再产生 hardroute"的执行保证——它比任何文档提醒都有效。

## 1. 四层测试

| 层 | 范围 | 依赖 | 数量目标 | 运行时长 |
|---|---|---|---|---|
| **L0 路由** | 类型/构造、合并、置信、裁决、确定性、失效重发现、自举 | 无（纯 CPU + 录制夹具） | **35 条必测（L0-01…L0-35）** | <3s |
| L1 单元 | `judge()` 纯函数（14 类）、状态迁移、令牌桶、哈希链、schema 校验 | 无（纯 CPU） | ≥140 例 | <10s |
| L2 oracle 集成 | 真打本地靶场，验证 VERIFIED/REFUTED | 靶场容器 | ≥44 例 | <8min |
| L3 端到端 | compose 全栈，跑 demo / demo-alt / replay / bench 抽样子集 / 控制台只读 | 全部容器 + 模型 | ≥12 例 | <15min |

**门禁**：L0 + L1 必须 100% 绿才允许提交；L2 每 PR 跑；L3 每日 + 发布前。

**为什么 L0 单独成层**：路由逻辑退化时，L1/L2/L3 都可能全绿——
因为退化后的代码在**当前靶场版本上**恰好还能跑通（它打对了，只是靠猜的）。
只有 L0 能抓住"结果对了但方法是错的"。

## 3. L1 单元测试清单（最有价值，最先写）

| 目标 | 用例 | 断言 |
|---|---|---|
| `judge` 纯函数性 | 同一 `pairs` 调 100 次 | verdict 集合大小 = 1 |
| `judge` 无时钟依赖 | 冻结/打乱 `ts` 字段 | 结论不变 |

### 4.4 第五种结局：`SKIPPED(no_selector_match)`（v3 新增）

用例跑不起来的原因不止"没授权"，还有"这个环境没有那个面"。必须单列，不能混入失败：

| 结局 | 含义 | 计入 FP? | 报告位置 |
|---|---|---|---|
| VERIFIED | 判定成立 | — | 已验证发现 |
| REFUTED | 判定不成立 | 否 | 负样本库 |
| INCONCLUSIVE | 证据不足 | 否 | 未能验证 |
| BLOCKED | 越界/未授权/缺前置 | 否 | 未能验证 |
| **SKIPPED(no_selector_match)** | **该资产没有对应语义标签的面** | 否 | **未覆盖（且写明缺哪个标签）** |
| **SKIPPED(route_unresolved)** | **有标签但解析不到绑定** | 否 | **未覆盖（且写明解析失败原因）** |

**为什么要分开**：`SKIPPED(no_selector_match)` 是"这个系统没这个面"（正常），
`SKIPPED(route_unresolved)` 是"有面但我们找不到"（异常，要修 discovery）。
混在一起就永远发现不了 discovery 退化——而这正是这一版要防的事。

| 账号 | 靶场真实注册的账号（primary/secondary），凭据进 vault，**不进 profile 明文** |
| 数据来源 | 只允许三种：真实开源靶场 / 公开数据快照 / 受管拟真集（`26 §2`）。**禁止手写响应体** |
| L0 夹具 | **录制的 `RouteSet`**：`make record-routes ASSET=y` 把真实解析结果落 `tests/routes/fixtures/<sha>.json`；回放时校验 `routeset_sha256` 一致 |
| L1/L2 夹具 | **录制回放**：`make record ORACLE=x ASSET=y` 从真实靶场录 request/response 到 `tests/fixtures/`，附靶场镜像 digest；靶场升级后夹具标 `stale` 需重录 |
| 数据集 | `data/` 下每份带 `manifest.json`；`make data-verify` 校验 sha256/行数/字段/`pii:false` |
| 时间 | 全部用 UTC；测试冻结时钟（`freezegun` 或注入 clock） |
| 随机 | nonce 用 `secrets`，但**判定不看 nonce 值本身**，只看"是否出现预期 nonce" |
| 机械检查 | `make lint-nodata-stub`：全仓 0 命中 mock/stub/fake/dummy、0 处硬编码 <5 行样本 |
| **机械检查（v3）** | `make lint-noroute`：全仓 0 处路径/URL/host/端口字面量（例外 ≤6 行且带理由） |
| 唯一豁免 | `unittest.mock.patch` 仅用于**阻断真实网络**（离线跑），不许用来伪造返回值；`httpx.MockTransport` 同样只用于阻断，返回值必须来自录制夹具 |

## 7. 一次 `make test` 的编排

```
make test        = lint(ruff+mypy+lint-noroute) + routes(L0) + unit(L1) + oracle(L2, 需 docker) + report-lint
make test-fast   = lint + routes + unit                  # 本地秒级
make test-e2e    = compose up + demo + demo-alt + replay + rediscovery-drill + down
make bench       = 独立，见 10
```

依赖顺序：**L0 绿 → L1 绿 → L2 绿 → L3 绿**。任何一层失败都不允许跑 bench 出数字。

**`make rediscovery-drill` 是 v3 新增的独立目标**（A9.4 的可执行形式）：
删掉一条绑定 → 跑任务 → 断言出现 `rediscovery` 事件、无兜底请求、结论为"找到新绑定"或"BLOCKED"。
它是一个**演练**目标，不是单元测试：因为它要真改环境，所以放在 e2e 层、默认不进 `make test`。
