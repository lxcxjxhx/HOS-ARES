# 05 · 安全边界规格（scope / 限流 / 审批 / 凭据 / 出口）

> 这类系统最大的风险不是打不穿，是**打到不该打的地方**。
> 本文是"敢用"的全部依据，也是面试最能拉开差距的一章。

## 1. scope 三处校验（同一份逻辑，三个时机，缺一即漏）

| 时机 | 校验内容 | 失败行为 | 事件 kind |
|---|---|---|---|
| ① 规划期 `plan` | asset ∈ scope.assets；∉ deny；oracle ∈ enabled；impact ≤ max_impact_class；窗口内 | 该 oracle 标 `BLOCKED`，**不发包** | `scope` |
| ② 执行前 `preflight` | 复核 ① + 预算充足 + 令牌可得 + 审批门已过 | 阻塞/排队/等审批 | `preflight` |
| ③ 连接后 `post_connect` | 实际连接的对端 IP ∈ assets 的解析集合，且 ∉ deny；跳转目标同样校验 | **立即断连**，标 `BLOCKED`，若 `stop_on_scope_violation` 则整任务停 | `scope` |

```python
def check_post_connect(conn, asset, profile) -> None:
    ip = ipaddress.ip_address(conn.peer_ip)
    allowed = asset.resolved_ips | profile.explicit_ips    # 解析集合（预解析并缓存）
    if ip in profile.deny_nets or ip not in allowed:
        conn.abort()
        events.record("scope", ok=False,
                      detail={"VIOLATION": "peer_not_in_scope", "ip": str(ip),
                              "asset": asset.id, "url": conn.url})
        if profile.policy.stop_on_scope_violation:
            raise ScopeViolation(ip, asset.id)
```

**为什么必须有第 ③ 处**：DNS rebinding、302 跳转、URL 解析差异、CDN 回源、IPv6 回退——前两处都看不见真实对端。

### 1.1 已知绕过面与对策（写进代码注释，面试直接讲）

| 绕过面 | 对策 |
|---|---|
| DNS rebinding（解析两次不同） | 预解析一次并**固定 IP 直连**（`httpx` 自定义 transport，SNI 用原域名） |
| 302/307 跳出 scope | `max_redirects: 0`，跟随跳转需显式开启且每跳都过 ③ |
| `@` 与 URL 混淆（`http://allowed@evil/`） | 用 `urllib.parse` 严格解析，拒收含 userinfo 的 URL |
| IPv4-mapped IPv6 / 十进制 IP | `ipaddress` 归一化后再判 |
| 云元数据 / 内网段 | `deny` 默认含 `169.254.169.254/32`、`10/8`、`172.16/12`、`192.168/16`、`::1`、`fd00::/8` |
| 代理变量污染 | 显式 `trust_env=False`，禁止读 `HTTP_PROXY` |

> 这一小节是**唯一值得写长注释的地方**。它证明"你想过失败"。

## 2. 限流（规格见 04 §5，这里只讲实现要点）

```python
# 令牌桶用 Redis Lua 保证原子
LUA = """
local now = redis.call('TIME'); local t = now[1] + now[2]/1e6
local b = redis.call('HMGET', KEYS[1], 'tokens', 'ts')
local tokens = tonumber(b[1]) or tonumber(ARGV[1])
local ts = tonumber(b[2]) or t
tokens = math.min(tonumber(ARGV[1]), tokens + (t - ts) * tonumber(ARGV[2]))
if tokens < 1 then redis.call('HMSET', KEYS[1], 'tokens', tokens, 'ts', t); return 0 end
redis.call('HMSET', KEYS[1], 'tokens', tokens - 1, 'ts', t); return 1
"""
```

- 令牌桶**不可用本地内存实现**：3 个 worker 各自 20 QPS = 实际 60 QPS，直接违反合同。
- 排队而非丢弃：拿不到 -> 短暂 sleep(50ms) 重试，累计超 `max_throttle_wait_s` 才放弃。
- 每资产并发用 `vp:sem:asset:<id>`（Redis 计数 + TTL 兜底，防泄漏）。

## 3. 审批门（人机交接的唯一接口）

```
agent 想执行 action_class=X 的动作
   → guard.approval.require(task, X, impact)
       ├─ profile.policy.approval_gates 里没有 X        → 直接拒绝（不允许就是不允许）
       ├─ 有 X 且 when=first_time 且本 engagement 已批过 → 放行
       └─ 否则 → task 转 AWAITING_APPROVAL，写 approvals(PENDING)，agent 挂起
                        │
        POST /approvals/{id} {decision, reason, by}
                        │
        ├─ APPROVED → 恢复执行，事件记 approval(ok)
        └─ REJECTED → 该动作 BLOCKED，任务继续走其余 oracle
```

| 规则 | 说明 |
|---|---|
| 默认全拒 | profile 不写就是不允许，不存在"默认放行" |
| 审批不可自我批准 | `decided_by` 不得等于 `lease_owner`（写死校验） |
| 挂起有时限 | `approval_ttl=3600s`，过期转 `EXPIRED` → 该动作 BLOCKED |
| 本期只 read_only | 审批门在 demo 里**只演示拒绝路径**（`scope_expand`），不演示写操作 |

**一句话**：agent 只负责发现和验证，是否执行由人决定，责任由人承担。

## 4. 凭据管理（agent 会拿客户账号，这是最大内鬼面）

| 项 | 规格 |
|---|---|
| 存储 | 本地 vault 文件（`~/.veripen/vault.db`，`0600`），字段级 AES-GCM，主密钥来自 `VERIPEN_MASTER_KEY` 环境变量或 OS keyring |
| profile 中只有 | `secret_ref: vault://<profile>/<name>` |
| 生命周期 | 任务结束即从内存清除（`AuthHandle.__del__` + 显式 `clear()`）；可配 TTL 15 分钟强制过期 |
| 日志 | 全局 redaction 过滤器：`authorization`、`cookie`、`set-cookie`、`x-api-key`、`password` 一律 `<redacted>`，**在 logger 层做，不靠调用方自觉** |
| capsule | 只存 header 名与哈希，不存值；`replay` 时从 vault 重新取 → 证据可分享而凭据不外泄 |
| 轮换 | `make vault-rotate` 生成新密钥并重加密，旧 capsule 不受影响（因为不含凭据） |

## 5. 出口与外联（egress）

| 规则 | 实现 |
|---|---|
| 只允许 assets 解析集合 | 应用层白名单 + （可选）容器 `--network` 隔离 + iptables |
| 默认无外网 | compose 里 worker 放在 `internal: true` 网络，只有 API 与靶场互通 |
| 模型调用 | 本地 Ollama（默认）或网关；**离线模式下绝不外联** |
| OOB 回调 | 本地 listener 在 docker 内网，域名用 `oob.internal`；不依赖公网服务（这是离线兼容的关键） |
| 禁止代理变量 | `trust_env=False`，显式代理才生效（且代理出口 IP 记入 capsule） |

## 6. 留痕（出事能复盘）

每次请求必记（`task_events.detail_json` + capsule）：

```
who(worker_id) / when(UTC 秒 + tz) / asset_id / url / method / params_hash
/ peer_ip / status / body_sha256 / oracle_id+version / verdict / capsule_id
```

**审计三问必须能秒答**：谁跑的？打了哪个资产？结果证据在哪？——`doctor --audit --engagement ENG-xxx` 一条命令输出。

## 7. 数据分级与不出域

| 数据 | 级别 | 默认 | 导出 |
|---|---|---|---|
| scope / asset 清单 | confidential | 库内存 | 需审批 + 水印 |
| 请求响应正文摘录 | confidential | capsule 内（本地盘） | 需审批 + 脱敏 |
| 发现与报告 | internal | 可渲染 | 水印 + `distribution` 标记 |
| 运行指标/bench | internal | 可导出 | 直接可出（对外可信度物料） |

**导出闸门**：`data_egress: deny` 时，`report export --external` 必须显式带 `--approved-by`，否则拒绝。

## 8. 边界清单：哪些必须人拍板

判据：**可逆性 × 影响是否可界定**。两个都"是"才交给 agent。

| 动作 | 可逆 | 影响可界定 | 结论 |
|---|---|---|---|
| GET 类差异对比 | ✅ | ✅ | agent 自主 |
| 双账号读取同一资源 | ✅ | ✅ | agent 自主 |
| OOB 外带（读操作） | ✅ | ✅ | agent 自主 |
| 提交含 payload 的 POST | ⚠️ | ⚠️ | 本期不做 |
| 暴力破解 / 撞库 | ❌ | ❌ | 不做 |
| 上传 webshell | ❌ | ❌ | 不做 |
| 扩大 scope / 加资产 | ❌ | ✅ | 审批门 `scope_expand` |
| 内网横向 / 凭据复用 | ❌ | ❌ | 不做 |
