# 15 · 开工提示词（批次版 · 复制即用）

> **用法**：项目目录建好后，按 `21` 的批次顺序，一次只粘**一个批次卡**给 agent。
> 每批结束看 DoD 输出，绿了再进下一批。
>
> 为什么不一次性粘全量：写代码快，**验证和集成慢**。一次跑 17 批 = 产出一个无法定位失败的大文件。
> 所以本文只提供四种模板 + 每批卡的"填空位"，范围由 `16` 定，批次由 `21` 定。

---

## 模板 A · 内核批次（B1–B4、B10、B13）

```
批次 <BX> · <名称>

【只读这些文档】docs/plan/<本批相关的 1–3 篇>，不要通读全册。
【本批目标】<从 21 的批次卡"目标"列复制>
【允许修改的路径】<从批次卡"产出"列复制>；其他路径一律不改。
【必须遵守的硬约束】
  判定是纯函数：oracle.judge(pairs) 无 IO / 无时钟 / 无随机
  三条件合取才出 VERIFIED：probe 符合漏洞 ∧ baseline 正常 ∧ control 符合预期
  finding 只能由 run_oracle 产生；模型无 record_finding 工具
  core 不 import oracles；core 与 oracles 都不出现客户标识
  常量：心跳 5s / TTL 30s / 扫描 5s / max_attempts 3 / 退避 1s,4s,16s(±20%)
        QPS 20 burst 40 / 每资产并发 2 / 排队上限 5s / 工具输出 4KB
【常量与枚举】见 docs/plan/15 §C 的"枚举与常量"段，直接照抄进代码常量模块。
【DoD】<从批次卡"退出条件"列复制，必须是可执行命令>
【交付】改动文件清单 + DoD 命令的**完整输出**（不许写"应该可以"）
【停止】DoD 全绿即停；不顺手做下一批；新想法写进 docs/plan/99-二期池
```

## 模板 B · Oracle 批次（B5–B7、B14）

```
批次 <BX> · 新增 oracle <oracle_id>

【只读这些文档】18-Oracle目录（本类小节）+ 07 §0 通用规格 + 01 §3.1 协议
【本批目标】实现 <oracle_id> 并接入注册表
【允许修改的路径】veripen_oracles/<oracle_id>/ 与 tests/{unit,oracle}/*<oracle_id>*
【必须遵守】
  三条件合取，缺 control 一律不得 VERIFIED
  judge 是纯函数；不发请求（请求由 oracle.plan 描述、由 tools.http 执行）
  每类 ≥4 正样本 + ≥2 负样本进 judge 单测
  负样本必须包含"看似漏洞实则安全"的对照（见 11 §4.2）
  安全属性：impact=read_only（写类 oracle 必须 requires=[approval:reversible_write]）
【DoD】
  pytest tests/unit -k <oracle_id>        →  全绿
  pytest tests/oracle -k <oracle_id>      →  靶场正样本 VERIFIED、负样本 REFUTED
  git diff --stat veripen_core/           →  空
【交付】oracle 目录全文件 + 两类测试输出 + 一条 capsule 样例路径
【停止】core diff 必须为 0；不新增依赖；不加未在 18 登记的变体
```

## §C · 全量总纲提示词（只用于评审，不做开工用）

```
做一个可审计、可复现、可离线部署的渗透验证内核，代号 veripen。

【架构】三包 + profiles + cli + web(只读)
veripen_core      调度/agent/guard/证据/Oracle协议      ← 零客户串
veripen_oracles   14 类验证器（A 6 / B 5 / C 3，见 18）
veripen_contract  OpenAPI/GraphQL → 用例生成（见 19）
veripen_cli       run/replay/bench/doctor/package-offline/report/cases/stats/lint-noleak
profiles/<name>/  demo-a（SaaS）· demo-b（车云）
checks/           认证半自动检查单（OAuth2/mTLS/Session/SAML，见 20）

【核心设计（不许改）】
1 判定纯函数：judge(pairs) 无 IO/时钟/随机
2 三条件合取：probe ∧ baseline ∧ control，无 control 不出洞
3 模型只影响"跑不跑得到"，不影响"判定是什么"；无模型（scripted planner）也能跑完（A8）
4 客户差异只进 profile；core diff = 0 是能卖第二家的机械判据
5 scope 三处校验 + fail-closed；越界一次整轮作废

【枚举与常量（写死）】
Verdict: VERIFIED | REFUTED | INCONCLUSIVE | BLOCKED
Task: QUEUED | LEASED | RUNNING | AWAITING_APPROVAL | DONE | FAILED | DEAD_LETTER | CANCELLED
Finding: CANDIDATE | VERIFIED | REFUTED | UNVERIFIABLE | BLOCKED
Impact: read_only | reversible_write
心跳 5s / TTL 30s / 扫描 5s / max_attempts 3 / 退避 1s,4s,16s(±20%)
QPS 20 burst 40 / 每资产并发 2 / 排队上限 5s / 输出截断 4KB
预算 steps 120 / tokens 400k / wall 1800s / cost 5USD；80% 收敛
idem_key = sha256(engagement|asset|oracle|params_canonical)
capsule_id = 自身 sha256；profile_hash 进每条 capsule

【数据表】tasks / task_events / findings / capsules / approvals / bench_runs（见 03）
【报告】MD/SARIF/JSON 同源；ruleId=veripen/<oracle>/<CWE>；partialFingerprints 稳定
【评测】44 例（28 正 16 负）× 3 轮；FP=0；越界=0；人工基线并列展示
【边界】不做：时间盲注 / 白盒 SARIF in-out / 交互式工具 / 多模态车机 / SAML 全自动 / 多租户 K8s
【执行】按 21 的 17 批，一批一验收，禁止一次跑多批
```


## 给 agent 的三条纪律（每次粘提示词都带上）

1. **只读本批相关文档**，不通读 28 篇；不确定时读 `16 §3` 能力表定位文档。
2. **DoD 输出必须贴原文**，不许"应该可以"；失败就开一条临时支线（一层、绑父批次、关闭后回归）。
3. **越界即停**：改到"允许路径"以外、需要新依赖、需要放宽断言——立刻停下来说明原因。
