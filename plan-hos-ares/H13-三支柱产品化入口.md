# H13 · 三支柱产品化入口（B66–B68）

> **问题陈述**：22 项能力矩阵里 20 项有实现、账本 100 条 done，但**没有一条能让人当产品用的入口**。
>
> - strix 面：`oracles/` 14 类、`cmd_hunt`、浏览器执行体、容器接口都在，但"给个目标 → 自己跑完 → 出报告"没有一条命令；
> - codex 面：`Loop`/`Decider`/fs/shell 工具面都在，TUI 是**只读面板**，没有"下指令、看它干活"的会话；
> - 驭智面：黑板/审批/Playbook/压缩/审计都在，`orchestrate()` 也没有 CLI 调用它。
>
> 一句话：**零件齐，装配零**。本册补的就是装配。

## 0. 为什么不是"再加几个模块"

`H01 §3` 已经把差距分成四类，A 类（结构性缺失）与 B 类（零件齐、装配缺）一期都处理过；
但"装配"这件事有第二层：**装配到能当产品用**。

一期的完成口径是"每批有自己的判据且能红"，这是对的，也是必须的。
它证明不了的是：**这些判据串起来能不能完成一次完整的活**。
本次用户的原话是"怎么都没有"——指的就是这一层。

所以本册三批各对应一条**用户视角的完整链路**，而不是三组新模块：

| 批 | 用户视角 | 一条命令 |
|---|---|---|
| B66 | "我给它一个目标，它自己打一遍并告诉我结论" | `python -m veripen_cli run --target ... --openapi ...` |
| B67 | "我坐下来跟它一起干活，能连续下指令" | `python -m veripen_cli agent --db ...` |
| B68 | "企业里一次要跑多个资产，还要人批、要报告" | `python -m veripen_cli platform --engagement ...` |

---

## B66 · `veripen run`：端到端渗透链路（strix 面）〔P0，1.5 人天〕

| 项 | 内容 |
|---|---|
| 目标 | 一条命令完成：路由解析 → oracle 选择 → 执行 → capsule 封存 → 报告出具；用本地靶场可复现 |
| 判据 | A：对 `secure=False` 靶场跑完退出 0，产出 `findings.json` / `report.md` / capsule 目录；B：对 `secure=True` 靶场同一批 oracle 产出 `REJECTED`（负样本不误报）；C：同输入两次运行 `findings_sha` 逐字相同；D：全程只连 `127.0.0.1`，报告与日志中无外部地址；E：无可执行 oracle 时退出码非 0 且写明原因（不静默成功） |
| 产出 | `veripen_cli/cmd_run.py` + `Makefile` 的 `run-e2e` + `tests/integration/test_run_e2e.py` |
| 依赖 | `cmd_hunt`（已有执行体）、`veripen_core/evidence.py`（capsule）、`veripen/report/`（三视图）、`tests/lab`（靶场 + `LabServer`） |
| PR | `b66/run-e2e` |
| 回滚 | 删除命令；不改任何既有模块 |

**与 `cmd_hunt` 的分工**：`hunt` 是"人盯着跑"，只打印；`run` 是"跑完给你交付物"——
多出 capsule 封存与报告出具两段，并且**失败要显式非 0**。

**为什么要用靶场而不是真站**：A/B 两条判据要求正负样本成对（同一个 app 切 `secure`），
只有靶场能提供；C 条要求同输入同输出，真站每天都在变。

---

## B67 · `veripen agent`：交互式会话（codex 面）〔P0，1.5 人天〕

| 项 | 内容 |
|---|---|
| 目标 | 一个能连续下指令的会话：每条指令走 `Loop`，实时显示工具调用与结果，会话可恢复 |
| 判据 | A：连续 3 条指令在同一会话内累计上下文（第 3 条能看到第 1 条的事实）；B：每步显示 `工具名 → 结果`，且**没有任何改判定/改发现的入口**；C：`Ctrl+C` 中断后已完成步骤仍在 `task_events`，`--resume` 能继续；D：无模型时自动降级 scripted 并显式提示（不假装调了模型） |
| 产出 | `veripen_cli/cmd_agent.py` + `veripen_core/agent/session.py`（会话状态）+ `tests/unit/test_agent_session.py` |
| 依赖 | `veripen_core/agent/loop.py`（`Loop`/`build_decider`）、`veripen_core/tools/registry.py`（B47 工具面）、`blackboard.EventLog` |
| PR | `b67/agent-session` |
| 回滚 | 删除命令；会话状态是新增模块，不触及既有循环 |

**与 TUI 的分工**：TUI（B56）是**只读三面板**，给"看"；`agent` 是**会话**，给"干"。
两者共用 `task_events` 作数据源，不重复实现状态。

**为什么不做 IDE 插件**：`H04 §6` 已写明"不能讲 IDE 插件"。终端会话是零依赖能到达的上限。

---

## B68 · `veripen platform`：企业级编排（驭智面）〔P1，2 人天〕

| 项 | 内容 |
|---|---|
| 目标 | 一次运行完成"多资产 + Playbook 选择 + 审批阻断 + 汇总报告 + 审计节"，并把结果写成企业交付物 |
| 判据 | A：一次跑 2 个资产，产出汇总报告（含逐资产结论与总计）；B：需要审批的动作停在 `PENDING`，`approvals` 表有行且 `task_events` 有痕；C：报告含智能体行为审计节（`B53` 的五表），空表也要显式；D：Playbook 命中率写进报告，未被选中时写明原因；E：全程可 replay——每资产的 capsule 链完整 |
| 产出 | `veripen_cli/cmd_platform.py` + `tests/integration/test_platform_e2e.py` + `docs/delivery/platform-run.md` |
| 依赖 | `veripen_core/agents/orchestrator.py#orchestrate`、`veripen_core/playbooks.py`、`guard/approval.py`（B60 落库）、`veripen/report/` |
| PR | `b68/platform-run` |
| 回滚 | 删除命令；编排逻辑本就是既有函数，本批只加 CLI 与报告拼装 |

**企业级不是"功能更多"，是"能被别人接手"**：报告要能让没参与的人看懂
"打了什么、为什么停、谁批的、证据在哪"。所以 B68 的交付物是**报告 + 审计节**，
不是"跑得更快"。

---

## 依赖与顺序

```
B66（run）──┬─→ B68（platform 复用 run 的单资产链路）
B67（agent）┘   两者可并行；B68 依赖 B66
```

推荐 **B66 → B67 → B68**：B66 先把"能打"这条线打通，B67 给它一个坐着干活的壳，
B68 把单资产放大到企业场景。

## 验收命令

```bash
make run-e2e                 # B66：靶场正负样本 + 报告 + capsule
python -m veripen_cli agent --db out/agent.db     # B67：交互（需 TTY）
python -m veripen_cli platform --engagement profiles/demo-a    # B68
python -m pytest tests/integration/test_run_e2e.py tests/integration/test_platform_e2e.py -q
```

## 与既有红线的关系

| 红线 | 本册怎么守 |
|---|---|
| H1 判定不许模型说了算 | 三批都只调 `oracles/` 的纯函数判定，`agent`/`platform` 不产生 verdict |
| H2 零地址 | 靶场地址由 `LabServer` 运行时给出；命令只接受 `--target` 参数，不写常量 |
| H4 缺件不许标 done | 每条判据都有"注入什么会红"；跑不通的批次标 `blocked` 并写明原因 |
