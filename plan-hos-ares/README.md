# plan-hos-ares · HOS-ARES 总规划（索引）

> `plan-hos-v1.0` · 2026-11-03 · 状态：`ready-for-review`
>
> **本项目要造的不是"一个验证内核"，是"一台能干活的机器"。**
> 判定要硬（VeriPen），执行要能打（strix），工作台要能写能跑（codex），平台要能指挥能复盘（驭智 HARNESS）。
>
> `plan-veripen/`（v3.6）是其中**判定面**的详细规格，**冻结只读**。

---

## 0. 一句话

> 判定内核已经能回答"凭什么相信"；接下来三个月要回答**"能不能打、能不能写、能不能指挥"**。
> 三件事做完，HOS-ARES 才是一门生意；只做第一件，它是一个很强的组件。

**现状（实测）**：22 个能力项里，领先 3、持平 5、半成品 10、结构性缺失 3、策略不做 1（`H01 §2`）。
**排期**：四波 25 批，44.5 人天，单人约 9 周（`H00 §2`）。


## 4. 与其他规划的关系

| 包 | 版本 | 状态 | 本包动作 |
|---|---|---|---|
| `plan-veripen/` | `plan-v3.7` | **冻结只读** | 判定面规格与 B1–B34 账本；B44 已改断言表 12→16，B59 再 16→20 |
| `plan-hos-ares/`（本包） | `plan-hos-v1.0` | 新增 | 总规划：四波、25 批、20 断言、红线与决策 |
| `.veripen/batches.jsonl` | append-only | 80 条 | 编号 B35 续 |

**为什么必须分成两个包**：判定面的规格已经冻结并被 80 条账本引用，改它会把"可回滚"变成"全仓动"；
总规划反过来引它才不会互相拖累。**一个包一个权威，冲突有裁决表（`H00 §4`）。**

## 5. 本包不含

| 不含 | 原因 |
|---|---|
| 代码改动 | 本包只定方案；代码按 `H07` 逐批落，一批一 PR |
| 判定语义规格 | 在 `plan-veripen/`（冻结） |
| 竞品推断当事实 | 竞品信息按 A/B/C 分级，C 级只留痕不作判据（`H01 §1`） |
| 截图 | 视觉回归用文本快照（可 diff） |
| 多租户 / K8s / 智能体安全产品线 | 明确不做（`H00 §5`） |

## 6. 自检（这个包需要机械门的原因）

| 检查 | 挡什么 |
|---|---|
| 每篇有 H1、围栏成对 | 手滑致整篇塌掉 |
| `H0X-xxx` 引用能对上真实文件 | 改名断链 |
| `H00` 登记全部 `H0X` | 新增一篇没人知道 |
| **`H01` 恰好 22 项，且每项都有批次或"保持"** | 矩阵慢慢退化成散文 |
| **批次卡与排期表逐条一致（编号/数量/人天/合计）** | 两处各写一份，逐渐对不上 |
| **代码锚点 `path:line` 真实存在且行号在文件内** | 本包所有判断都靠"看这一行"，锚点一漂就成意见 |
| `MANIFEST.md` 哈希一致 | 改了没重生成 |
