### 为什么不动 `Loop`

`Loop` 是判定骨架：`tool_calls_per_step=1` 是 `08 §2` 写死的纪律，
**允许多个调用 = 允许它在一个 step 里越权串动作**。

多步计划不属于那件事：它是**用户显式要求的一串动作**，
由 `Plan.steps` 承载，逐步执行、逐步确认——每一"步"仍是一次单一工具调用。

所以改的是意图层与会话层，`Loop` 一行不动。

### 失败即停，不许静默继续

多步计划最危险的失败模式是"第 1 步改了文件、第 2 步读失败，界面继续往下走"。

纪律：

```
⏺ edit(a.txt)  ✓ 替换 1 处
⏺ read(a.txt)  ✗ FsError: ...
  已停止：第 2 步失败，后续 1 步未执行
```

**停止要明说停在第几步、还剩几步**——用户才知道世界处于什么状态。

### 分段规则

拆句用「然后 / 再 / 接着 / 之后」，且：

- 只有**全部**分段都解析成功才返回多步计划；
- 任一分段解析不出 → 整句按单步处理（走原路径），并回显"没听懂"——
  不做"一半执行一半猜"。

## 执行记录（2026-11-05）

实测：

```
> 把 a.txt 里的 x 改成 y 然后读一下
⏺ 计划  把 a.txt 里的「x」换成「y」 → 读 a.txt
  1. edit(path=a.txt, old=x, new=y)
  2. read(path=a.txt)          ← 第二段沿用第一段的路径
```

三处必须做对的：
1. **第二段要能沿用第一段的路径**："读一下"没带路径，靠分段历史里的 `a.txt`；
2. **最后一步失败也要说**：`已停止：第 2 步失败（最后一步）`，
   不能因为"没有后续"就不吭声；
3. **任一段解析不出就退回单步**，不做"一半执行一半猜"。

判据 A–E 全绿：`test_chat_multistep.py` 7 passed；全量 unit + 既有 chat 12 项绿。
