# H00 · HOS-ARES 总纲与四波排期（plan-hos-v1.0）

> **本项目要造的不是"一个验证内核"，是"一台能干活的机器"**：
> 判定要硬（现有 VeriPen），执行要能打（strix），工作台要能写能跑（codex），平台要能指挥能复盘（绿盟驭智 HARNESS）。
> 四件事缺一件，产品形态就不成立。
>
> 本包是**总规划**；`plan-veripen/`（v3.6，判定内核规格）**冻结只读**，作为其中一块的详细规格。

---

## 0. 一句话定性

| 说法 | 成立吗 | 依据 |
|---|---|---|
| "VeriPen 是全部" | ❌ | 它只有判定面，执行面/工作台/平台面是空的（`H01 §2`） |
| "VeriPen 是 HOS-ARES 的判定内核" | ✅ | 纯函数判定 + 三条件 + 六态 replay + 零地址，四条都是别人没有的（`H05`） |
| "HOS-ARES = strix + codex + 驭智" | ✅ 作为**目标口径** | 三家分别代表：能打 / 能写能跑能长会话 / 能指挥能复盘（`H01 §1`） |
| "三家功能已经齐了" | ❌ | 25 批里只有 8 批是"补强"，其余是"从零建"（`H07`） |

## 1. 三根支柱 + 一块底盘（先看清结构，再谈排期）

```
                   ┌──────────────────────────────────────────┐
  驭智 HARNESS ───▶│ 平台面 P 控制平面 / 黑板 / 多执行体 / Playbook / 审批 / 审计 │
                   ├──────────────────────────────────────────┤
  codex ─────────▶│ 工作台面 W  fs / shell / plan / todo / 长会话 / TUI        │
                   ├──────────────────────────────────────────┤
  strix ─────────▶│ 执行面 E  容器隔离 / 浏览器渲染 / 工具面 / 资产发现          │
                   ├──────────────────────────────────────────┤
  VeriPen ───────▶│ 判定面 V  纯函数 / 三条件 / 六态 replay / 零地址 / 四态 outcome │
                   └──────────────────────────────────────────┘
                   ┌──────────────────────────────────────────┐
  产品面 G ───────▶│ 控制台 / 报告 / 离线包 / 断言与验收（对外就讲这一层）        │
                   └──────────────────────────────────────────┘
```

**关键结构判断**：现在 V 面（判定）是**超配**，E/W/P 三面是**欠配**，G 面是**半成品**。
过去的批次（B1–B34）几乎全花在 V 面和它自己的验收上——这就是"内核很强、产品不像产品"的根因。

## 3. 现状与目标的差距（不修饰）

| 面 | 现有 | 目标（三家合起来的要求） | 差距性质 |
|---|---|---|---|
| **V 判定** | 14 类 oracle、六态 replay、零地址、四态 outcome、44 例 × 3 轮 FP=0 | 保持，并把"真实资产召回"从 0.33 往上顶 | **领先，但要防退化** |
| **E 执行** | HTTP/DNS-OOB 两种执行体；subprocess 无隔离；无浏览器；无资产发现 | 容器隔离、浏览器渲染、工具面统一、可选的资产发现 | **结构性缺失** |

| **G 产品** | 9 页只读控制台（6 页裸 JSON）、报告三视图、离线包 | 说真话 + 能用 + 可交付 | **半成品** |

## 5. 范围（明确写下来，防止半路扩张）

**做**：四波 25 批，见 `H07`。

**明确不做**（延续旧包 `16 §7`，本包只补三条新的）：

| 不做 | 理由 | 谁来改判 |
|---|---|---|
| 自动写 exploit 代码（模型生成可执行载荷） | 会破坏"可 replay、可审计"；`30 §1.6` 已定 | 不做（无改判入口） |
| 二次编程载体（msf/sliver/解释器） | 它们自己加载代码，`05` 边界表失效 | `99 P-08` 三期 |
| 多租户 / RBAC / K8s | 第二个付费客户之后 | `16 §7` |
| 智能体安全产品线（清风卫类） | 是另一门生意 | 只做报告里的"智能体行为审计"一节（B53） |
| 网段扫描 / 资产发现 | **`16 §7` 维持不做**；strix 有，但我们做它会打穿 scope 模型 | **B48 决策门**；默认不做 |

## 7. 四条红线（H1–H4，与 `plan-veripen/40 §4` D1–D4 同级）

| # | 红线 | 具体禁止 | 谁最容易被违反 |
|---|---|---|---|
| **H1** | **判定不被任何东西污染** | 模型、界面、执行体、报告都不得改 verdict；`act.*` 类型上拿不到 verdict | 执行面（B45/B47）与界面（B35） |
| **H2** | **地址不入库** | 执行面/浏览器/发现/前端同样适用；不许"为了跑通先写死一个 host" | 执行面（B46/B48）最危险 |
| **H3** | **缺输入 ≠ 没漏洞** | `BLOCKED`/`INCONCLUSIVE` 不得呈现为"没有"或"高危" | 界面（B35）、报告（B53） |
| **H4** | **不做的能力要写清理由并对内对外一致** | 不做要写在 `§5`，不许在答辩时临时答应 | 销售/答辩场景 |
