# H21 · 对话面板接三支柱（B79）

> B77 的 `chat` 能读写文件、跑命令——那是**工作台**。
> 但用户要的是把三件事收进同一个面板：
> **strix 的自动化渗透**（"把这个目标跑一遍"）与
> **驭智的企业编排**（"按 demo-a 跑"）。

## B79 · chat 接 `run` / `platform`〔P0，1 人天〕

| 项 | 内容 |
|---|---|
| 目标 | chat 里说「跑一下 `<target>`」→ 走 `cmd_run` 全链路（契约→oracle→capsule→报告）；说「按 demo-a 跑」→ 走 `cmd_platform --profile`；两者结果摘要进会话 |

| 产出 | `veripen_core/agent/intent.py`（`run` / `platform` 意图）+ `veripen_cli/cmd_chat.py`（两个执行器）+ `tests/integration/test_chat_hunt.py` |
| 依赖 | `cmd_run`（B66）、`cmd_platform`（B68/B72）、`agent/session.py`（B67） |
| PR | `b79/chat-hunt` |
| 回滚 | 删掉两条意图与执行分支；chat 其余能力不变 |

### 为什么不是"再写一个新命令"

`run` 与 `platform` 已经是经过判据验证的链路（正负样本、审批阻断、审计节）。
chat 只是**换个入口**，不能重写一遍——重写会得到第二套没有判据保护的行为。

所以执行器直接调 `cmd_run.main()` / `cmd_platform.main()`，
把它们的 stdout 折成尾段摘要。**同一份逻辑，两个入口。**

### 输出折叠的纪律

`run` 对 5 个 oracle 输出十几行，全量塞进对话会把上下文冲掉。
所以：

- 捕获完整 stdout，**只显示最后 12 行 + 退出码**；
- 完整输出写进 `out/chat/<turn>/stdout.log`，会话里给路径；
- 摘要（不是全文）进 `task_events`——事件表不是日志转储。

### 缺参数就追问，不猜

"跑一下"没给目标 → 问"哪个目标？"
"按档跑"没给档 → 列出 `profiles/` 下可用的档名，让用户选。

**不猜地址、不挑一个"看起来对"的档**——这是 H2（零地址）与 B72（fail-closed）
同一条纪律在对话层的延续。

### 与既有 intent 的关系

| 意图 | 动词 | 落到 |
|---|---|---|
| 读/写/改/跑命令/状态 | 已有（B77） | 工作台工具 |
| **跑渗透** | 跑一遍 / 扫一下 / hunt | `cmd_run` |
| **按档跑** | 按 X 跑 / 用 X 这个档 | `cmd_platform` |

三条线共用一个 `Plan` 结构：先显示计划、再执行、再给摘要。
用户看到的是同一套交互，底下的工具不同。
