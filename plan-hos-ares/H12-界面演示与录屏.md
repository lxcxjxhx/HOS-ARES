# H12 · 界面演示与录屏（B65）

> **定位**：让"能力"从命令输出变成**肉眼可见的画面**。
> 一期交付的 10 个只读页、审批唯一写入点、audit 事件流，全部只被单测覆盖过；
> 没有人用眼睛看过它们连起来是什么样。
>
> 本册只有一批：一条命令产出控制台全页巡检视频 + 逐页截图 + 清单。

## 0. 为什么单独成册

这不是"做个 demo 视频"的 PPT 活。三个真实诉求各自对应一条判据：

1. **眼睛能验**：`check-plan` 绿不等于页面读得懂。`G1 控制台可读` 那条 parity
   是脚本判的，画面是否成立只有人看；
2. **数据要真**：截图里必须是真 Chromium 渲染的真数据，不是 PS 的；
3. **可复现**：同一 commit 重跑，页序列与关键数值必须一致——否则这段视频
   只是一次性宣传素材，不能当回归证据。

所以产出三件套而不是一段 mp4：**视频（感受）+ 截图（引用）+ manifest（断言）**。

## B65 · 控制台巡检录屏〔P1，0.5 人天〕

| 项 | 内容 |
|---|---|
| 目标 | `python scripts/demo/record_console.py` 一条命令：起服务 → 真 Chromium 走完 10 页 → 出 MP4 + 每页 PNG + manifest |
| 判据 | A：视频 ≥25s、1280×720、H.264，ffprobe 可读；B：10 个 UI 页按 `OPS` 顺序各出现一次，manifest 有对应时间戳；C：数据非空——overview 的 findings 数与 audit 的事件数、approvals 的行数都 > 0（空页不算演示）；D：可复现——两次运行 manifest 的页序列与三个关键数值逐字相同（**不要求视频字节相同**，编码器非确定）；E：全程只连 `127.0.0.1`，不解析外部域名 |
| 产出 | `scripts/demo/record_console.py` + `docs/delivery/console-tour.md` + `out/demo/`（mp4 / pages/*.png / manifest.json） |
| 依赖 | `veripen_cli.cmd_console`（含 B64 的 `--db`）、`web/static/router.js` 的 hash 路由、ffmpeg、playwright |
| PR | `b65/console-tour` |
| 回滚 | 删除脚本与产物；不触及产品代码 |

**演示数据从哪来**：脚本自建临时库（`out/demo/tour.db`），写入 3 条 oracle 事件
与一组完整审批四态（PENDING → APPROVED / REJECTED / EXPIRED），再喂给
`cmd_console --db`。用真库而不是内存态——否则 audit 页永远是 `unavailable`。

**为什么用"截图连拍 + ffmpeg"而不是 Playwright 的 `record_video`**：

- 录屏 API 产出 webm，且起停时机与页面稳定性耦合，容易录进白屏；
- 逐页截图能保证**每页至少一帧是干净的**，同时天然产出可引用的 PNG；
- 帧率/时长完全可控，判据 A 才写得出来。

代价：动画与过渡录不进去（页面本来也没有）。这个取舍是有意的。

## 依赖与顺序

```
B64（audit 数据源）──→ B65（演示里要让 audit 页有内容）
```

推荐在 B64 之后做；若 audit 未接，视频里会出现一个 `unavailable` 页，
判据 C 直接红——这正是我们要的联动。

## 验收命令

```bash
python scripts/demo/record_console.py               # 产出三件套
ffprobe -v error -show_entries format=duration -of csv=p=0 out/demo/console-tour.mp4
python -m pytest tests/unit/test_demo_manifest.py -q   # manifest 判据 A–D
```
