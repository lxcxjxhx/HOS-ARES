# H05 · 判定内核边界（VeriPen 在 HOS-ARES 里的位置）

> VeriPen 不是产品，是**判定内核**：它回答"凭什么相信这条结论"。
> 这一卷只做三件事：**划线（谁能碰判定）、交底（现在到底多准）、防退化（新增三面会不会把它弄坏）**。
> 详细规格在 `plan-veripen/`（v3.6，冻结），本卷不重述。

---

## 1. 四条不变量（任何一面都不得绕过）

| # | 不变量 | 落地 | 谁最容易违反 |
|---|---|---|---|
| **I1/I2** | 判定是纯函数 + 三条件合取（probe ∧ baseline ∧ control） | `veripen_oracles/`（14 类） | 浏览器执行体（"看起来渲染出了 alert"就想判） |
| **I4/I12** | 模型与自由动作不产 verdict；`act.*` 类型上拿不到 verdict | `veripen_core/agents/orchestrator.py:62`（`assert_no_verdict`） | 工具面统一（B47 把 fs/shell 接进来时） |
| **N1–N6** | 地址只能由 `route_discovery` 产出，类型上写不出 URL | `veripen_core/routes/types.py` | 容器与浏览器（最容易"先写死一个 host 跑通"） |
| **D1** | 缺输入只能是 `BLOCKED`/`INCONCLUSIVE` | `veripen_core/outcome.py` | 界面（B35）与报告（B53） |

**判定域的修改权**：只有 `plan-veripen/` 的规格能改判定语义；本包只能改"呈现"和"供给"。
一句话：**本包可以把判定喂得更好（更多绑定、更多执行体），不许把判定改得更松。**

## 2. 交底：现在到底多准（只写实测）

| 指标 | 值 | 来源 | 说明 |
|---|---|---|---|
| 自建靶场用例 | 44 例 × 3 轮，TP26 / FP0 / FN2 | `make bench`（`plan-veripen/16 §4.1`） | 三轮判定完全一致 |
| 真实资产（Firing Range） | 召回 **0.33**、误报 **0**、两次结果一致 | B30 账本 | **未达标**（门槛 0.6），原因在目标侧与契约侧 |
| 真实资产请求量 | 8 条绑定 / 10 个 oracle / 84 次真请求 | `cmd_hunt` | 只读、限速 1 req/s |
| 模型可发现性 | **0.0**（3 步只读探索后收敛） | B29 账本 | 负结论：模型不会自己进入验证 |
| 零地址 | 0 命中 / 156 文件 | `make lint-noroute` | A9 |

**必须照实说**：
- "召回 0.33"不是判定错，是**目标上没有可判的面**（OOB 缺域名、端点与 oracle 不匹配、契约标签没被采纳）；
- "模型不主动验证"是负结论，`plan-veripen/40 §9` 已写死对外表述：**能打靠 scripted + oracle 库，不靠模型自主**。

## 3. 召回 0.33 的三条真实原因（B59 要逐条复测）

| 原因 | 现象 | 新执行面能不能解决 | 归属 |
|---|---|---|---|
| OOB 缺域名 | `ssrf_oob` 拿不到回调 → `BLOCKED` | 能（容器内起 listener + 公网可达域名） | B45 + B59 复测 |
| 端点与 oracle 不匹配 | 契约给的端点不是漏洞所在 | 部分（浏览器渲染能看到前端实际调用的接口） | B46 + B59 复测 |
| 标签没被采纳 | 契约标签与 oracle 的 `selector_tags` 对不上 | 否（属契约解析，需单独修） | 需新批次（本包不排，记 `H09 §3`） |

**这一节的意义**：B59 不许只写"召回提升了"，必须写"哪条原因被消掉、哪条还在"。

## 4. 防退化：三面落地时对内核对表

每批合并前，逐条核对（发现违反即打回）：

| 新增能力 | 必查 | 会怎么坏 |
|---|---|---|
| 容器执行（B45） | 镜像/compose/脚本里无地址；绑定运行时注入 | 地址进镜像 → `lint-noroute` 应红但可能扫不到 |
| 浏览器（B46） | 渲染结果不得直接产 verdict；DOM 只作证据 | `page.evaluate` 里写个断言就"判了" |
| 工具面统一（B47） | `workbench.*`/`act.*` 不 import 判定类型 | 类型穿透 → `assert_no_verdict` 失效 |
| 并行（B49） | 黑板/leads 按 `task_id` 过滤 | 跨任务污染 → 结论不可复现 |
| 压缩（B52） | 压缩前后 findings 逐条相同 | 判定输入被压掉关键事实 |
| 记忆（B57） | 结论不跨任务 | 旧结论冒充新验证 |
| 界面（B35） | 未验证不标 severity | 读者把"没测成"读成"高危" |

**这张表就是 H1/H2/H3 三条红线的执行形态**，不是新规则。

## 5. 内核侧明确"不做"的改判（本包不支持）

| 想改的 | 为什么不做 |
|---|---|
| "让模型在拿不准时给个 VERIFIED" | 直接摧毁 FP=0 与 replay |
| "把 `INCONCLUSIVE` 合并进 `REFUTED`（少几行报告）" | 等于把"没测"写成"没洞"，D1 |
| "为了演示，允许 profile 里写一个 host" | 零地址破一次就会破无数次（`27 §0` 的根因） |
| "把 control 省掉换取速度" | 三条件是 FP=0 的唯一实现 |

这四条如果有人提，回答统一：**改判据之前先写"原判据为何不合理"，再改，改完重跑全部历史**（`40 §4` D2）。

---

## 6. 一句话

> 判定内核这三个月**只许变强不许变松**：喂给它更多绑定、更多执行体、更多真实目标；
> 但不许动"纯函数、三条件、零地址、四态"这四根柱子。
