# H14 · 体验录屏（B69）

> **目标**：把 B66/B67/B68 三条入口"真跑一遍"的过程录成视频，
> 让没装环境的人也能看到"它到底怎么工作、输出了什么"。

## 0. 为什么不是"截图拼一拼"

截图只能证明"某个瞬间长这样"，证明不了**命令与输出的因果关系**。
所以本批要求：

1. 画面里的输出必须是**真命令真跑出来的**（不是手写的美化文本）；
2. 每一行出现的位置要对应原始 stdout 的行号（可回溯）；
3. 同一 commit 重跑，场景序列与关键行逐字相同（可复现）。

### 取数方式（为什么不录屏幕）

真实终端录屏要么引入 asciinema（新依赖），要么录桌面（不可复现）。
本批改用**捕获 stdout → 渲染终端 HTML → 逐帧截图**：

- stdout 来自真跑，行号可回溯到原始输出；
- 渲染是确定性的（同一份行 → 同一张图）；
- 逐帧截图天然产出可引用的 PNG。

代价：看不到"打字过程"与光标闪烁。这个取舍是有意的——**内容是证据，动画不是**。

### 三幕结构

| 幕 | 命令 | 该看到什么 |
|---|---|---|
| 1 | `python -m veripen_cli.cmd_run --target … --openapi …` | 路由数、逐 oracle 判定、`VERIFIED 2`、capsule 数 |
| 2 | `python -m veripen_cli.cmd_agent --db …` | 两条指令的 `ok write` / `ok read`，末行"最近一步" |
| 3 | `python -m veripen_cli.cmd_platform --targets … --require-approval --approve` | 逐资产进度、审批已签、汇总数与报告路径 |

### 与 B65 的关系

`B65` 录的是**控制台 10 页**（产品面，给人看界面）；
`B69` 录的是**三条命令的执行过程**（三支柱，给人看能力）。
两者产物独立，不合并——合并会让"哪一段是哪批的证据"变模糊。

