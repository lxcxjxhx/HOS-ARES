#### B12-cors 的修改计划（下一批做）

现状只覆盖"简单请求"：带 `Origin` 发 GET，看 `Access-Control-Allow-Origin` 有没有反射。

缺的是**预检**：`OPTIONS` + `Access-Control-Request-Method`。
预检配错的典型形态是"允许任意方法/任意头 + 允许携带凭证"，比简单请求反射更危险。

落点：
1. `plan()` 加一个 `preflight` 变体（method=OPTIONS，带 `Origin` 与 `Access-Control-Request-Method`）；
2. `judge()` 用它对 `access-control-allow-methods` / `-headers` / `-credentials` 判；
3. bench 的 cors 案（P-23/P-24/N-xx）要重跑，确认判定变化是"更准"而不是"更松"。

**先记着不做**：OPTIONS 属于"非 GET 方法"，闸门会按方法放行——改之前先确认
`GuardContext` 对 OPTIONS 的策略，否则会在真实目标上被拦成 BLOCKED。

## 3. 环境真欠账：E1 真隔离

> 其余真欠账（设计决定／能力／待修）见 §2.3；本节只讲卡在环境上的那条。

**E1 真隔离。** 不是设计取舍，是环境缺口：

- 本机无 docker/podman；Job Object 只提供资源隔离（进程树 + 内存/时间上限）；
- B127 已把**能验的**验掉：超时真杀、退出码保留、输出捕获；
- `attest()` 给出的是**否证**：当前不是容器隔离。

要关闭它需要一台有容器运行时的机器，然后跑
`veripen parity`（E1 项会从 UNVERIFIED 变 GREEN）与
`tests/range/`（A17 五项）。
