## 1. 一句话现状

**能对任意目标（有契约或无契约）跑出一条可复核的链路，并在报告里说清"哪块没测"。**
本地 44 案实测：precision **1.00**、recall **0.93**、越界 **0**、闭环 **1.00**，

## 3. 已经定死、不要再改的裁决

这些是踩过坑之后的结论，改动前先读对应文档：

| # | 裁决 | 依据 |
|---|---|---|
| 1 | **缺输入是 BLOCKED，不是"没跑"** | D1；B130 实测差距 |

| 8 | **一条规则只有一个来源**（强度/短标识/severity/发现参数/逐面记录/档名） | B100/B101/B104/B113/B122/B123 |

## 4. 接手先跑这几条

```bash
# 1. 结构自检（文档、能力矩阵、代码锚点）
node plan-hos-ares/check-plan.cjs

# 2. 环境自检（19 项；skip ≠ pass）
python -m veripen_cli doctor

# 3. 能力矩阵（22 项；E1 会显示"未验"）
python -m veripen_cli parity

# 4. 判定能力（44 案，有门槛）
python scripts/b12/run_bench.py --rounds 3 --out out/bench

# 5. 全量测试（约 9 分钟）
python -m pytest tests -q
```

四项口的含义：`check-plan`=文档没散、`doctor`=环境没缺、`parity`=能力没假报、
`bench`=判定没退化。

## 6. 别做的事

- **别为了让指标好看去打开 `rate_limit_absent`**：它默认关闭是因为慢，不是因为它不重要。
- **别把 `skip` 当成通过**：doctor 的 skip 意味着那项**没验**。
- **别在报告里把 `not_run` / `error` 写进"未发现"**：报告层有断言挡着，改之前先看 `assert_renderable`。
- **别在 `run` / `hunt` 里各自拼覆盖面**：`observations_from(face_runs)` 是唯一入口。
