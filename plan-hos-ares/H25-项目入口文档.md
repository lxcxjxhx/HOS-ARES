### 为什么文档要机器校验

文档最常见的腐烂方式不是"写错"，是**写得当时对、之后没人改**：
子命令改名了、参数变了，README 还写着老命令，而没人会去试。

所以本批的判据 E 是可执行的：从 README 里抽出所有 `veripen <名字>`，
逐个比 `COMMANDS` 表；对不上就红。**文档里的命令必须真能跑**。

### 诚实清单

README 里必须有一节写"不能做什么"，且要具体到卡点：

- 容器隔离：接口/策略/BLOCKED 已验，**真隔离未验**（本机无 docker/podman）
- 真模型：链路已验（本地假服务），**模型服从性未验**（本机无后端）
- 真实目标召回：靶场已验，**外部目标 0.33 未复测**

不写"敬请期待"，写清卡在哪、需要什么条件才能翻绿。
