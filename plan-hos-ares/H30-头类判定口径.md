# H30 · 头类判定口径

> 这类 oracle 只回答一个问题：**「这条响应有没有配某个安全头」**。
> 它**不回答**「配得好不好」。本文把这条边界写死，免得下次有人顺手扩成评分。

---

## 1. 现有四条

| oracle | 判据（算"有保护"的条件） | CWE | 不适用时 |
|---|---|---|---|
| `csp_absent` | `Content-Security-Policy` 存在且**非空** | 693 | — |
| `frame_opt_absent` | `X-Frame-Options` 存在 **或** CSP 里含 `frame-ancestors` | 1021 | — |
| `nosniff_absent` | `X-Content-Type-Options` 的值**精确等于** `nosniff` | 693 | — |
| `hsts_absent` | `Strict-Transport-Security` 含 `max-age>0` | 319 | **非 https → `not_https`** |

四条的 `expected` 都写成 `dict[str, list[int]]`（1 = 有保护 / 0 = 没有），
因为 capsule 的 `AssertionBlock` 只接受整数列表。

---

## 2. 共同判据（骨架 `_HeaderAbsent`）

```
probe   —— 「我断言它缺这个头」的那次请求（原样发）
control —— 同一条面再发一次（带无害参数 vp_hdr=1）
```

判定成立要同时满足：

1. probe 与 control **都是 2xx**；
2. probe 与 control **都"没有"保护**——两次独立请求都缺，才算稳定缺失；
3. 任一次"有" → 判否（有就是有）。

任一次请求出错 → `INCONCLUSIVE(fetch_failed)`；缺 probe 或 control →
`INCONCLUSIVE(missing_variant)`。

**为什么必须有 probe**：框架的 `three_way_holds()` 要求 probe 存在，只有 control 会被
打回 `three_way_failed`（B123 踩过——判定跑完但结论是"未定"）。

---

## 3. 为什么"有"的判据各不相同

同一个头，判"有保护"的口径必须单独想，否则两侧都会错：

| oracle | 只看"头存在"会怎样 | 只看"某个头"会怎样 |
|---|---|---|
| CSP | 空值被当成有保护（假阴性） | — |
| 点击劫持 | — | 只看 XFO → 现代站点用 CSP `frame-ancestors`，全被判缺失（**假阳性**） |
| nosniff | `none` 被当成有保护（假阴性） | — |
| HSTS | `max-age=0` 被当成有保护（假阴性） | — |

所以每条都单独覆盖 `_present()`，骨架只负责流程。

---

## 4. 刻意不做的三件事

### 4.1 不做强弱评分

`default-src *` 也算"有 CSP"；`max-age=60` 也算"有 HSTS"。
强弱是**主观判断**，一旦写进判定，同一条响应在不同人眼里会有不同结论——
那与"可复核"直接冲突。要评分就单开一类分析，别混进 oracle。

### 4.2 不判"头配错了"

例：`X-Content-Type-Options: inline`。现状按"没有保护"处理（值不等于 `nosniff`），
但**不额外报一条"配置错误"**——那需要一份"合法取值表"，而各浏览器厂商的口径并不一致。

### 4.3 不管 JSON 接口

四条都只选 `html_document`（HTML 页面）。JSON 接口上的头缺失属于另一类问题
（多数是网关统一配置），混进来会把接口面全标成缺失。

---

## 5. 加一条新头时的检查清单

1. **判据**：什么算"有保护"？（非空 / 精确值 / 含某指令 / 阈值）
2. **适用性**：有没有前提条件（如 HSTS 只在 https）？不适用时返回
   `INCONCLUSIVE` 并写清原因，**不许判否也不许跳过**。
3. **两侧风险**：只看"头存在"会不会假阴性？只看某一个头会不会假阳性？
4. **强弱边界**：这条判定会不会滑进"配得好不好"？会就停下。

---

## 6. 已知局限

- `scheme` 只认 `https`；空串（老调用方未传）按非 https 处理。
- 只读**响应头**，不读页面里的 `<meta http-equiv>`（那是另一条判定路径）。
- 判定粒度是"面"：同一站点不同路径可能配得不一样，不做站点级汇总。
