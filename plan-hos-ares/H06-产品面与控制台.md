# H06 · 产品面与控制台

> 控制台是唯一"甲方会亲手点"的东西，所以它有两个责任：
> **说真话**（不说谎）与**好看懂**（不让人读 JSON）。
> 现状是**一半没做、一半做错了**——做错的那半更贵，因为它让读者把"没测成"读成"高危"。

---

## 1. 实测审计（2026-11-03，`main@2df3e60`，数据来自 B30 真实目标）

### 1.1 九页现状

| 页 | 渲染方式 | 问题 |
|---|---|---|
| `overview` | **裸 `<pre>` JSON** | 最该先看的页反而最难看 |
| `engagement` | 裸 `<pre>` | 同上 |
| `findings` | 表格 | 两列恒空（见 §1.3） |
| `finding` | 裸 `<pre>` | 且**无视 id**，永远第一条 |
| `unverified` | 裸 `<pre>` | 可信度的一半，却最不可读 |
| `coverage` | 裸 `<pre>` | **契约漂移**：实际返回 `{"confirmed":1,"unconfirmed":2}`，不是矩阵 |
| `routes` | 表格（摘要） | 正常（只给 8 位、无模板） |
| `audit` | 裸 `<pre>` | 恒空，且无导出入口 |
| `bounds` | 告警条 | 正常（非空即红） |

### 1.2 最严重的一条：未验证冒充高危

```json
// /ui/findings
{"id":"F-003","title":"ssrf_oob 未确认","severity":"high","confidence":0.0,
 "priority":11.0,"queue":"now","hits":0}
// /ui/unverified —— 真相在这一页
{"groups":{"undetermined":[
   {"id":"F-003","oracle":"ssrf_oob","reason":"BLOCKED: baseline_abnormal"}]}}
```

一条 `BLOCKED` 的条目以 `high` 进了「立即看」，排在唯一一条真结论（`medium`/priority 8.0）前面。
**这不是排序不好看，是判定域 D1 在展示层被违反**：读者只有一种理解方式——"这条更严重"。

根因：`web/console.py:87` 的 `queue` 只看 `severity`，而 `severity` 在装载器里由 oracle 名硬映射
（`scripts/serve_console.py:26`），**与 verdict 无关**。

### 1.3 「面」「命中」两列为什么是空的（纠正一个误判）

不是"数据没填进去"。数据在：`route: ""`、`hits: 1 / 0`。
空的是**表达**：`web/static/index.html:76` 直出空串，`:79` 只在 `hits > 1` 时才出文案。
于是**三种语义被渲染成同一种空白**：无绑定 / 单命中 / 零命中。

修法不是"补字段"，是**定三义 + 给不同文案 + 加断言**（§2.2）。成本 **0.5–1 人天**，不是 20 分钟。

## 2. 展示语义（先定语义，再谈样式）

### 2.1 三轴正交

| 轴 | 取值 | 现状 |
|---|---|---|
| **verdict** | `verified / inconclusive / blocked / not_run / error` | 被压进 `outcome`，界面不读 |
| **severity** | `critical/high/medium/low/info` | 未验证行也被填值 |
| **queue** | `now/week/low/silenced` | 只看 severity |

**规则（B35 实现）**：

```
severity 只在 verdict == verified 时合法，否则为 null
queue 只对 verified 行计算；未验证行只进 ui.unverified
概览的"高危数"只算 verified
```

### 2.2 空值四态

| 状态 | 文案 | 样式 |
|---|---|---|
| 无绑定（`route_ref=None`） | `未绑定` | 灰 |
| 单命中（`hits==1`） | `1` | 正常 |
| 多命中（`hits>1`） | `N 处（已合并）` | 正常 + 汇总标记 |
| 零命中（`hits==0`） | `0` | 弱化 |
| 未执行（`hits==None`） | `未执行` | 虚线 |

### 2.3 文案纪律

| 禁止 | 改用 |
|---|---|
| `存在 SQL 注入` | `已确认：布尔差分成立（replay OK）` |
| `无漏洞` | `未发现（覆盖率 3/14 类）` |
| `未确认` 单独出现 | `未确认 · BLOCKED · baseline_abnormal` |
| 无分母的百分比 | `1/3 已确认（33%）` |

## 3. 九页规格（按"读者要决定什么"排）

| 页 | 读者 | 首屏 | 关键交互 | 库 |
|---|---|---|---|---|
| `overview` | 管理层/甲方 | 3 卡：资产与范围 / 结论计数 / 覆盖缺口 + 低覆盖黄条 | 每个数字可下钻 | B38 |
| `engagement` | 研发/交付 | 输入身份 + 执行统计 + 证据链根哈希 | 复制 | B38 |
| `findings` | 工程师 | 表格（verdict 徽标 / severity / oracle / 资产 / 置信 / 强度 / 面 / replay / 优先级 / 命中 / capsule） | 筛选、排序、搜索、`j k` | B35+B39 |
| `finding` | 研发/合规 | 五段：断言 / 复现 / 三 trace / 路由来源(8 位) / capsule | `?id=` | B36+B40 |
| `unverified` | 研发/合规 | 四组：`inconclusive/blocked/not_run/error` + 原因码 + "补什么能测" | 跳转 | B35+B39 |
| `coverage` | 评审 | 资产×oracle 矩阵 + 标签×oracle 矩阵 + 概览条 | 单元格下钻 | B36 |
| `routes` | 评审 | 摘要表 + 固定声明条 | 无导出 | 保持 |
| `audit` | 合规 | 事件表（时间/主体/动作/资产/参数哈希/结果） | 接不进源就下架 | B36 |
| `bounds` | 值班 | 非空即红 + 应当拦截的闸门 | 保持 | 保持 |
| **`approvals`** | 甲方 | **新增第 10 页**：待批动作卡片 | 批准/拒绝（唯一写入） | **B54** |

**全局**：hash 路由（`#/findings?verdict=verified&sev=high&q=xss`）、每页 loading/empty/error 三态、
键盘 `g` 前缀跳页、`/` 搜索、`Esc` 返回。

## 4. 契约 v2（只增不改）

```json
{"op":"ui.findings","data":{...},"payload_version":2}
```

| 新字段 | 类型 | 含义 |
|---|---|---|
| `verdict` | 枚举 | 结论强度 |
| `severity` | `string|null` | 仅 verified 有值 |
| `bound` | bool | 是否绑定（区分"未绑定"与"绑定了但空"） |
| `hits_state` | `zero/single/multi/not_run` | 空值四态的机械形态（`None`=未执行） |
| `requested` / `selected_by` | string | 详情页取数三态：命中 / 回落 / 默认（回落必须可见） |
| `scope` | string | `coverage` 的自我声明：`observed_only`（分母只含跑过的面） |
| `source` | string | `audit` 的事件源：`state` / `unavailable`（恒空页签不许留） |
| `by_verdict` | object | `unverified` 按 verdict 分组的兼容视图（三组旧契约不动） |

| 规则 | 内容 |
|---|---|
| R1 只增 | 不改名、不改类型 |
| R2 不改义 | `route` 仍 8 位；`hits` 仍数字（文案在前端） |
| R3 可降级 | 缺 `payload_version` 视为 1 |
| R4 未知字段 | 前端忽略，不校验白名单 |

**outcome → verdict 映射（唯一权威）**：`reported→verified`；`undetermined→inconclusive`；
`blocked→blocked`（**新增**，现在混进 `inconclusive`）；`not_run→not_run`；`error→error`。

## 5. 边界（含一条必须写清的破例）

| 边界 | 内容 |
|---|---|
| 只读 | `ui.*` 写方法一律 405（现有 36 条路由，测试锁着） |
| 不判定 | 不改 verdict / 不重算置信度 / 不越权分档 |
| 不查库不发包 | 全部由 `ConsoleState` 注入 |
| 无地址 | 不出现完整 `route_ref`、不出现模板正文、不拼目标 URL |
| **唯一破例** | `ui.approvals` 的 POST 只写"审批决定"（批准/拒绝 + 理由），其余写路径仍 405；破例需在 `H10` 与 `plan-veripen/22 §1` 留修订记录 |

## 7. 可访问性与打印（B42）

键盘全可达 + `:focus-visible` + `aria-live` 状态区 + 对比度 ≥ 4.5 + `prefers-reduced-motion` +
打印样式（去导航、展开折叠、保留徽标）。

**诚实的局限**：无浏览器 CI，屏幕阅读器行为**不做自动判据**，只做静态断言 + 人工清单，PR 里写明"验了什么/没验什么"。
